# Промпт агенту: вкладка «Контроли» — раунд 7 (фильтры, инициаторы, удаление всего, Excel-экспорт 1:1, resize колонок, hover)

**Репозиторий:** `https://github.com/sledovatel61/porayonka.git` (ветка `main`).
**Приложение:** `porayonka-app/main.py`.
**Запуск:** `python porayonka-app/main.py` (Windows, Flet **0.23.2**, Python 3.10+).
**База:** текущий `main` (после `4a4bdfd` — fuzzy surname matching).

## Контекст и текущее состояние

Вкладка «Контроли» реализована, сетевая синхронизация работает, фильтры по исполнителям/контролёрам сделаны каноническими. **Однако после внедрения fuzzy-матчинга появился регресс:** в фильтре «Прочие» стало ещё больше контролей (24–25 из 135), хотя должно быть наоборот меньше.

Диагноз оркестратора: `executor_canonical = get_criminalists_only()` включает только 16 криминалистов, **но в реальных данных в колонке «Исполнители» встречаются и контролёры** (`Потемкин С.А.`, `Чашин Э.А.`, `Ченакал Ю.А.` и др.). Они не входят в `executor_canonical`, поэтому такие контроли попадают в «Прочие». Fuzzy-матчинг тут не помогает, потому что это не опечатки, а совершенно другие ФИО.

## Задачи

### Задача 1. Исправить регресс фильтра «Прочие»

**Цель:** «Прочие» должно показывать только контроли, где исполнители/ответственные действительно не из справочника (не криминалисты и не контролёры).

**Что сделать:**
1. Пересмотреть состав `executor_canonical`. Вероятно, фильтр «Исполнители» должен использовать **объединённый канонический список**: криминалисты + контролёры + возможно другие часто встречающиеся ФИО из данных.
2. Либо ввести отдельную логику: «Прочие» = нет совпадения ни с одним именем из **полного канонического справочника** (criminalists + controllers + дефолтные).
3. Проверить на реальных данных пользователя (`%APPDATA%\porayonka\controls.json`): контроли с исполнителями `Чашин Э.А.`, `Потемкин С.А.`, `Семисенко И.Ю.` не должны попадать в «Прочие». В «Прочие» должны остаться только записи с посторонними ФИО (например, `Эксузян А.М.`, `Кудрявцев В.А.` — если они не входят в справочник, и т.п.).
4. Не сломать существующие проверки в `tests/test_controls_smoke.py`; при необходимости обновить ожидания.

### Задача 2. Канонический фильтр «Инициаторы»

**Проблема:** в фильтре «Инициаторы» огромный список из-за того, что одни и те же инициаторы записаны по-разному (`ГУК`, `ГУК С.`, `ГУК СК`, `ГУК С.Т.С.А.С.И.Ю.`, `СУ`, `СУ/СК`, `СК РФ` и т.д.).

**Цель:** список фильтра должен содержать только канонические варианты, а фильтрация должна находить все варианты написания.

**Что сделать:**
1. Составить канонический список инициаторов. Источники:
   - встроенные дефолтные (`get_initiators()`),
   - distinct значения из данных,
   - возможно, кластеризация по схожести (fuzzy/нормализация).
2. Реализовать нормализацию/маппинг вариантов к каноническому значению. Например: `ГУК С.`, `ГУК СК`, `ГУК С.Т.С.А.С.И.Ю.` → `ГУК`; `СУ/СК`, `СУ СК` → `СУ` и т.п.
3. В UI фильтра «Инициаторы» показывать только канонические значения + «Прочие» (если нужно).
4. Фильтрация должна проходить по всем сырым вариантам, относящимся к выбранному каноническому.
5. Сохранить возможность добавлять кастомных инициаторов через карточку (`custom_initiators` в настройках), но в фильтре они должны нормализоваться к каноническому виду, если совпадают с существующим каноническим.

### Задача 3. Кнопка «Удалить все контроли»

**Цель:** дать администратору возможность полностью очистить таблицу.

**Что сделать:**
1. Добавить в тулбар вкладки «Контроли» кнопку (например, рядом с «Экспорт Excel» или в меню настроек) **«Удалить все»**.
2. По нажатию показывать **обязательный диалог подтверждения**:
   - Текст: «Уверены, что хотите удалить ВСЕ контроли? Это действие нельзя отменить».
   - Кнопки: «Удалить всё» (красная) и «Отмена».
   - Дополнительно можно требовать ввести слово-подтверждение (например, «УДАЛИТЬ»), чтобы исключить случайное нажатие.
3. После подтверждения:
   - Очистить `state["controls"]`, локальный `controls.json` и shared-файл (если сеть включена).
   - Очистить `notify_log`, снимки `known_ids`, `my_status_map`, `known_attachments`.
   - Обновить таблицу, счётчики, фильтры.
   - Показать toast «Все контроли удалены».
4. Действие должно быть доступно только в роли `admin` (в роли `user` кнопка скрыта или неактивна).

### Задача 4. Экспорт Excel — точно как в оригинальном файле

**Эталон:** файл `Контроли ОКРИМ.xlsx` в корне репозитория. Экспорт должен выглядеть **точно так же**: структура колонок, порядок, заголовки, объединённые ячейки, цвета, ширины, автофильтр.

**Что сделать:**
1. Открыть `Контроли ОКРИМ.xlsx` и проанализировать его структуру:
   - какие колонки и в каком порядке,
   - какие заголовки,
   - есть ли объединённые ячейки (например, общий заголовок «КОНТРОЛИ ОТДЕЛА КРИМИНАЛИСТИКИ»),
   - цвета заливки/шрифта (жёлтая колонка «Следующая дата», зелёная «Исполнено» и т.д.),
   - ширины колонок,
   - наличие автофильтра и закреплённых строк.
2. Переписать `core/controls_exporter.py` (режим «как в таблице») так, чтобы результат совпадал с эталоном **визуально и структурно**.
   - Скрытый лист `_controls_full` для round-trip сохранить (это важно для импорта).
   - Основной лист должен быть копией эталона по форматированию.
3. Даты — в формате `dd.mm.yyyy`.
4. Жёлтая подсветка «Следующая дата исполнения» при OVERDUE/TODAY/SOON — сохранить, как в эталоне.
5. Зелёная подсветка «Исполнено» — как в эталоне.
6. Проверить: экспорт → открыть в Excel → сравнить с `Контроли ОКРИМ.xlsx`.

### Задача 5. Ресайз колонок перетаскиванием (как в Excel)

**Требование:** пользователь может потянуть границу заголовка колонки и изменить её ширину. Изменения сохраняются.

**Текущее состояние:** в коде есть `_header_cell` с `GestureDetector` и логикой `_save_col_widths` в `controls_settings.json.col_widths`, но, по словам пользователя, **не работает или работает не так**.

**Что сделать:**
1. Проверить текущую реализацию в `ui/controls/controls_tab.py`.
2. Сделать так, чтобы при перетаскивании правой границы заголовка колонка меняла ширину **в реальном времени** (или по окончании drag), ширина сохранялась в `controls_settings.json`.
3. Должны быть ограничения: минимальная ширина колонки (например, 60 px), нельзя уменьшить «Содержание» ниже разумного.
4. После resize таблица не должна ломаться (ширины пересчитываются, контент не выезжает).
5. Не использовать `expand=True`/`wrap=True`/`animate` внутри `Column(scroll=AUTO)` — следовать правилам AGENTS.md §15.11/§22.

### Задача 6. Убрать задержку hover-подсветки строк

**Проблема:** подсветка строк срабатывает с задержкой/«через одну» при быстром движении курсора.

**Что сделать:**
1. Найти причину задержки. Возможные направления:
   - `_safe_update()` делает лишние проверки;
   - `update()` контрола строки дорогой из-за большого количества детей;
   - обработчик hover делает лишние вычисления.
2. Оптимизировать:
   - в горячем обработчике оставить только присвоение `bgcolor`/`border` и `_safe_update()`;
   - возможно, обновлять только фон контейнера строки, а не весь контрол;
   - проверить, не вызывается ли `_rebuild_table()` или другой тяжёлый код в hover.
3. Цель: при проведении курсором по строкам подсветка должна следовать мгновенно, без видимой задержки.
4. Не возвращать `traceback.print_exc()` в hover-обработчик (AGENTS.md §36.2).

## Технические ограничения (обязательно)

- Flet **строго 0.23.2**, новых зависимостей не добавлять.
- `ft.icons.*` вместо emoji; `print()` в консоль — только ASCII; UI-текст — русский.
- Hex с прозрачностью — только `#AARRGGBB`, не CSS `#RRGGBBAA`.
- Внутри `Column(scroll=AUTO)` запрещены: `expand=True` (кроме горизонтальных спейсеров в Row), `wrap=True`, `animate*`, `shadow`, `gradient` на мелких контейнерах.
- Все `.update()` контролов — через `_safe_update()`.
- Вложенные `AlertDialog` запрещены; подтверждения — через `page.open()/page.close()`.
- Рамки с `border_radius` — равномерная толщина всех сторон.
- Не ломать вкладки «Следственные отделы» и «Зональные».
- Не ломать сетевую синхронизацию, уведомления, архив, импорт Excel, вложения.
