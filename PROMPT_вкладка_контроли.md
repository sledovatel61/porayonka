# Мегапромпт: вкладка «Контроли» для приложения «Порайонка»

> **ВАЖНО:** Это промпт для AI-агента на арене. Агент должен сначала изучить
> `AGENTS.md` и код проекта, затем **спланировать и предложить 2–3 варианта
> архитектуры** (особенно сетевого интерфейса), выбрать лучший, обосновать и
> реализовать. Коммитить результат только в отдельную ветку от `main`.

---

## 1. Контекст проекта

- **Репозиторий:** `https://github.com/sledovatel61/porayonka.git` (ветка `main`).
- **Приложение:** `porayonka-app/main.py`.
- **Запуск:** `python porayonka-app/main.py`.
- **Стек:** Python 3.10+, Flet **строго 0.23.2**, openpyxl 3.1.5.
- **Окружение:** Windows, тёмная тема (DARK final), цвета из `porayonka-app/core/constants.py`.
- **Текущее состояние:**
  - Вкладка «Следственные отделы» — kanban-доска, статистика, экспорт.
  - Вкладка «Зональные» — плашки 300×380, drag-and-drop, сводка, шаблоны, очистка данных, экспорт Excel.
  - Данные хранятся в `%APPDATA%\porayonka\` (departments.json, zonal_*.json).
  - Layout вкладок стабилизирован (см. `AGENTS.md` разделы 15–27); **не ломать его**.
- **Перед началом обязательно прочитать:** `AGENTS.md` (особенно разделы 15.11, 22.3, 24.3).

---

## 2. Задача

Добавить **третью вкладку «Контроли»** в приложение. Вкладка должна заменить
ведение контролей в Excel-таблице и быть **удобнее, функциональнее и красивее**.

Пример текущей Excel-таблицы (скрин от пользователя):
- Колонки: `№`, `вх. № ВХСОП`, `Дата поступления`, `Инициатор`,
  `Содержание`, `Исполнитель (ФИО)`, `За кем контроль`, `Разовый/постоянный`,
  `Следующая дата исполнения`, `Исполнено + дата`.
- Жёлтым подсвечиваются ближайшие сроки.
- В «Содержании» встречаются распоряжения с несколькими пунктами, у каждого
  свой исполнитель и свой срок.

---

## 3. Функциональные требования

### 3.1 Список контролей (основной экран)

- Таблица/список всех контролей с колонками:
  - № (порядковый)
  - Входящий номер (вх. № ВХСОП / Вхсоп / Иссоп и т.д.)
  - Дата поступления
  - Инициатор (СУ, ГУК СК, ГУК ЮФО, СК РФ, ПСК, ГСУ, ОКРИМ и др.)
  - Содержание (краткое, до 2–3 строк, полное — в карточке)
  - Исполнитель(и) — ФИО, можно несколько
  - За кем контроль (Потемкин С.А. / Чашин Э.А. / другие из списка)
  - Тип: разовый / постоянный (периодический)
  - Следующая дата исполнения
  - Статус срока (цветная индикация):
    - 🔴 Просрочено (дата < сегодня)
    - 🟡 Сегодня
    - 🟠 Скоро (например, ≤ 3 дней, настраивается)
    - 🟢 В работе (норма)
    - ⚪ Исполнено
  - Исполнено + дата (если исполнено)
- **Сортировка** по любой колонке (клик по заголовку).
- **Поиск** по всем текстовым полям (номер, содержание, инициатор, исполнитель).
- **Фильтрация**:
  - по статусу срока (просрочено / сегодня / скоро / в работе / исполнено / все);
  - по инициатору;
  - по исполнителю;
  - по контролеру;
  - по типу (разовый / постоянный);
  - по диапазону дат (следующая дата).
- **Быстрые действия** в строке:
  - открыть карточку (клик);
  - отметить исполненным;
  - продлить срок;
  - удалить (с подтверждением).
- Счётчики по фильтрам (как в зональной вкладке: «Все / Просрочено / Скоро / Исполнено»).

### 3.2 Карточка контроля (добавление / редактирование)

- Открывается по клику на контроль и по кнопке «Добавить контроль».
- Поля:
  - Входящий номер (текст, обязательное).
  - Дата поступления (выбор даты).
  - Инициатор (выпадающий список + возможность добавить свой).
  - Содержание (многострочный текст).
  - Исполнитель(и) — выбор из списка криминалистов (подтягивается из вкладки
    «Зональные», см. 3.5), можно несколько + ручной ввод.
  - За кем контроль (выпадающий список: Потемкин С.А., Чашин Э.А., другие).
  - Тип: разовый / постоянный. Для постоянного — периодичность
    (ежедневно / еженедельно / ежемесячно / ежеквартально / свой интервал в днях).
  - Следующая дата исполнения (выбор даты).
  - Комментарий.
- **Пункты задания** (ключевая фича):
  - Если содержание включает несколько пунктов (например, распоряжение с п. 1,
    п. 2, п. 3), их можно добавить отдельными строками внутри контроля.
  - У каждого пункта: название/описание, ответственный(ие), срок исполнения,
    статус исполнения (в работе / исполнено), дата исполнения, комментарий.
  - Следующая дата контроля по умолчанию = минимальная дата неисполненных пунктов
    (можно переопределить вручную).
  - Пункты можно добавлять/удалять/редактировать, менять порядок.
- Кнопки: «Сохранить», «Отмена», «Удалить» (с подтверждением).
- Валидация: входящий номер и дата поступления обязательны.

### 3.3 Уведомления о сроках

- При запуске приложения и **периодически** (например, каждые 5 минут или при
  фокусе окна) проверять сроки контролей.
- Показывать уведомления в приложении (Snackbar / баннер / всплывающее окно):
  - «Просрочено: N контролей»;
  - «Сегодня истекает: N контролей»;
  - «Скоро истекает: N контролей (≤ X дней)».
- Уведомления не должны дублироваться бесконечно: либо показывать сводку,
  либо запоминать уже уведомлённые контроли (в настройках/файле).
- Настройка: за сколько дней считать срок «скорым» (по умолчанию 3).
- При сетевом режиме уведомления должны приходить и другим пользователям сети
  (см. 3.4).

### 3.4 Сетевой интерфейс (локальная сеть)

**Цель:** несколько компьютеров в локальной сети работают с одной базой
контролей. Администратор (Потемкин С.А.) ведёт контроли, остальные видят
свои задания и получают уведомления.

**Требования:**
- Настройка «сетевого режима» в приложении:
  - включение/выключение;
  - роль: администратор / пользователь;
  - имя пользователя/компьютера (по-фамильно), связанное с криминалистом из
    «Зональных»;
  - путь к общей папке (сетевой диск/ресурс) или адрес сервера.
- Общая база хранится в сетевой папке в JSON (например,
  `\\SERVER\share\porayonka\controls.json`).
- Автосинхронизация:
  - периодический polling файла (например, каждые 15–30 секунд) с перезагрузкой
    при изменении;
  - сохранение локальных изменений сразу в общий файл;
  - индикатор состояния синхронизации в UI (последнее время, статус).
- Конфликты: простая стратегия last-write-wins по записи/объекту + резервные
  копии перед перезаписью. Предложить вариант получше, если есть.
- **Альтернативные варианты, которые агент должен рассмотреть:**
  1. Shared JSON + file polling (просто, надёжно, без сервера).
  2. Встроенный HTTP-сервер на машине администратора (Flask/FastAPI/aiohttp)
     + клиенты по сети.
  3. Гибрид: shared JSON для данных + UDP broadcast для мгновенных уведомлений.
- Агент должен сравнить варианты по сложности, надёжности и UX, выбрать один
  и обосновать выбор в комментарии к PR/сообщении.

### 3.5 Связь с криминалистами из «Зональных»

- Список исполнителей и контролеров подтягивается из
  `%APPDATA%\porayonka\zonal_criminalists.json` (16 криминалистов).
- В настройках сети компьютер связывается с конкретным криминалистом (по ФИО).
- В фильтрах и поиске исполнители — из того же списка.
- Дополнительно добавить в список контролеров: Потемкин С.А., Чашин Э.А.
  (можно через константы или первый запуск).

## 4. UI/UX

- Современный тёмный интерфейс в стиле приложения (цвета `core/constants.py`).
- Соблюдать **все layout-правила** из `AGENTS.md`:
  - внутри `Column(scroll=ft.ScrollMode.AUTO)` не использовать `expand=True`,
    `wrap=True`, `animate`, `gradient`, `shadow` на мелких контейнерах;
  - фиксированные размеры для карточек/панелей;
  - `ft.icons.*` вместо emoji;
  - `print()` только ASCII (без русских букв и спецсимволов);
  - UI-текст на русском.
- Компактные строки контролей с цветной полосой срока слева.
- Удобные фильтры-чипы с счётчиками.
- Карточка контроля — модальное окно или боковая панель, адаптивная ширина.
- Выбор даты — удобный (ft.DatePicker или masked text field).
- Empty state при пустом списке.
- Индикатор синхронизации и статуса сети в шапке вкладки.
