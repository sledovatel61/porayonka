## 1. Живые баги после раунда 34 (обязательно устранить)

### 1.1 User-дистрибутив открывается как admin
**Симптом:** установлен `Порайонка_Пользователь_Setup.exe` на ПК пользователя (Авакян, Win10/11). При запуске открывается **админский UI**: видны кнопки «Импорт Excel», «Удалить все», «Справочники», секция пароля в настройках, фильтр по всем контролям. При этом сетевой режим был **выключен** по умолчанию.

**Гипотезы, которые надо проверить и починить:**
- В `User.iss` страница ФИО записывает `edition.json` в `{app}` с `"role": "user"`, но возможна проблема с `_app_dir()` в `core/edition.py`: в frozen onefile PyInstaller `sys.executable` указывает на exe в папке установки, но `edition.json` рядом с exe может не читаться (кодировка BOM, права, путь с пробелами/русскими буквами, или файл перезаписывается установщиком/скриптом).
- Возможно, `build_all_distributives.bat`/`build_user.bat` генерируют `dist_user/edition.json` правильно, но при сборке **Installer** используется `dist_all/Порайонка_Пользователь/edition.json`, который мог быть перезаписан/испорчен.
- Возможно, `%APPDATA%/porayonka/edition.json` от предыдущих тестов admin имеет приоритет выше, чем ожидалось (см. `edition.py`).
- Возможно, `apply_edition_to_settings` не сбрасывает `network_role`/`network_user` при explicit user-редакции, или настройки из `%APPDATA%` перетирают edition.json.

**Что сделать:**
1. Добавить **ASCII-диагностику** при старте в `main.py`/`create_controls_tab`: печатать `sys.executable`, папку exe, наличие/содержимое `edition.json` рядом с exe, `%APPDATA%/porayonka/edition.json`, итоговую роль из `load_edition()`.
2. Проверить `_app_dir()` на frozen onefile: она должна возвращать папку **реального exe** (не `_MEIPASS`), и `edition.json` должен читаться именно оттуда.
3. Защитить user-редакцию от appdata-наследия: если `edition.json` рядом с exe explicit `role=user`, то `%APPDATA%/porayonka/edition.json` НЕ должен переводить в admin (сбрасывать `network_role`/`network_user` и сохранять настройки).
4. Проверить, что установщик `User.iss` пишет `edition.json` без BOM, UTF-8, валидный JSON, и что файл копируется в `{app}`.
5. При необходимости переделать механизм определения редакции: например, жёстко кодировать `role` в имя exe/argv, или проверять сначала имя исполняемого (`Порайонка_Пользователь.exe` → user), как запасной/основной вариант.
6. В user-редакции кнопки admin-функционала должны быть **физически удалены** из дерева тулбара (не `visible=False`), а не только скрыты. Сейчас в `controls_tab.py` они должны уже удаляться, но проверить и усилить.

### 1.2 Сетевой режим по умолчанию включён, для user — read-only
**Симптом:** при первом запуске user-версии сетевой режим был **отключен**, пришлось включать вручную.

**Что сделать:**
- В `core/controls_data.py` `DEFAULT_SETTINGS["network_enabled"] = True`.
- При миграции/загрузке старых настроек (`load_settings`): если ключ `network_enabled` отсутствует или явно `False` из старой установки, принудительно ставить `True` и сохранять.
- В user-редакции переключатель «Сетевой режим» в настройках должен быть **disabled/read-only** (иконка замка + текст «включён»), чтобы пользователь не мог отключить синхронизацию. Admin может переключать.

### 1.3 Убрать секцию «Пароль администратора» из настроек
**Симптом:** в user-версии (и, возможно, admin) в настройках (шестерёнка) видна секция «Пароль администратора».

**Что сделать:**

### 1.4 User-версия не спрашивает «Кто вы?» при первом запуске
**Симптом:** на ПК Авакяна пользовательская версия загрузилась сразу с ФИО «Миронович Д.В.» (наследие appdata/admin-тестов), диалог «Кто вы?» не появился.

- При explicit `role=user` без `user_name` принудительно сбрасывать `network_user = ""` в настройках и сохранять, чтобы диалог сработал.
- Если `edition.user_name` задан — использовать его, не спрашивать.

## 2. Аудит экспорта Excel 1:1 с эталоном

**Файлы:**
- Эталон (исходный импорт): `porayonka-app v2 DARK final\LLM\14.08.2026\Контроли ОКРИМ.xlsx`
- Результат экспорта: `porayonka-app v2 DARK final\LLM\14.08.2026\controls_20260814_135024.xlsx`

**Задача:**
1. Написать скрипт `tools/audit_excel.py` (или встроить в тесты), который сравнивает оба файла по:
   - Заголовкам (строка 2, A2:J2).
   - Общему заголовку (A1:J1, текст + заливка + шрифт).
   - Ширинам колонок (A…J).
   - Количеству строк данных.
   - Содержимому каждой ячейки (№, вх.№, дата поступления, инициатор, содержание, исполнители, «за кем контроль», тип/периодичность, следующая дата, исполнено+дата).
   - Форматам ячеек (даты, выравнивание, перенос, шрифт).
   - Цветовой подсветке (жёлтая — только OVERDUE/TODAY, зелёная — только исполнено).
   - Наличию автофильтра.
   - Высоте строк.
2. Вывести список расхождений в файл `porayonka-app v2 DARK final\LLM\14.08.2026\excel_audit_report.txt`.
3. **Устранить все расхождения** в `core/controls_exporter.py`:
   - Если исходная таблица имеет другие ширины/высоты — привести к ней.
   - Если в исходнике «Разовый / постоянный» содержит конечную дату + периодичность — экспорт должен повторять точь-в-точь.
   - Если даты в исходнике — настоящие Excel-даты (serial) с форматом `DD.MM.YYYY` — сделать так же.
   - Если «Содержание»/«Исполнители» в исходнике переносятся по строкам — включить `wrap_text=True` и автовысоту (уже частично сделано; довести).
   - Если исходник не подсвечивает SOON жёлтым — оставить только OVERDUE/TODAY (уже сделано; проверить).
   - Проверить, что персонализация user-экспорта (колонка 9 = user-дата) не ломает формат для admin.
4. После правок экспортировать заново и проверить, что `excel_audit_report.txt` показывает **ноль значимых расхождений**.

## 3. Технические ограничения

- Flet строго 0.23.2. Не повышать.
- Никаких новых зависимостей (кроме уже используемых openpyxl).
- `print()` — только ASCII (без кириллицы/emoji/«—»/«→»/«×»), чтобы не было `UnicodeEncodeError` на Windows cp1251.
- UI-текст (`text=...`) — на русском.
- Цвета 8-digit — только `#AARRGGBB`, не `#RRGGBBAA`.
- Внутри `Column(scroll=AUTO)` — без `expand=True` (кроме горизонтальных спейсеров Row), без `wrap=True`, без `animate`, без `gradient`/`shadow` на мелких контейнерах.
- Вложенные `AlertDialog` внутри карточки запрещены.
- Не ломать раунды 20–34: read-only user-режим, трей/автозапуск, алармы, web-режим, lock-файлы, офлайн-вложения.
