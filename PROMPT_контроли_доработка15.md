## 2. Задачи раунда 15

### 2.1 Hover — сделать мгновенным или убрать

**Симптом:** при движении курсора по строкам таблицы подсветка отстаёт от курсора,
иногда остаются «хвосты» (несколько строк подсвечены одновременно).

**Что уже пробовали (не работает в живом GUI):**
- `Container.on_hover` с изменением только `bgcolor`/`border`;
- единый `_hover_active` — гасить предыдущую строку при enter на новой;
- `_quiet_update` без `print`/`traceback`;
- без `animate`, `shadow`, `gradient`, throttle.

**Что нужно сделать:**
1. Поискать в интернете и issues Flet, почему `on_hover` в Flet 0.23.2 лагает
   на длинных списках (ключевые фразы: "flet on_hover lag", "flet hover slow",
   "flutter mouse region hover performance list", "flet container on_hover delay").
2. Изучить `AGENTS мангуст.md` в корне репозитория — там в проекте на tkinter
   решалась похожая проблема (hover только рамкой/полоской, без заливки строки,
   без print/traceback в горячем обработчике, debounce только для тяжёлых операций).
3. Предложить и реализовать **радикально работающее** решение. Допустимые варианты:
   - полный отказ от hover-эффекта на строках (оставить только `mouse_cursor=CLICK`);
   - hover только левой полоской 3–4 px (меньше перерисовки);
   - hover только рамкой, без заливки фона;
   - throttle на уровне событий, но без визуальной задержки;
   - виртуализация / постраничный вывод / ограничение числа видимых строк;
   - любой другой подход, если докажешь, что он работает в Flet 0.23.2.
4. Если hover оставляешь — в живом GUI он должен реаговать мгновенно, без «хвостов».

**Не делать:**
- не добавлять `animate`, `shadow`, `gradient`;
- не вызывать `print`/`traceback` в горячем обработчике;
- не вешать `on_hover` на вложенные контролы (иконки, кнопки, тексты) — только на
  саму строку-контейнер;
- не использовать throttle, если он даёт визуальную задержку.

### 2.2 Таблица — убрать пустое место справа

**Симптом:** при широком окне справа от таблицы остаётся пустой промежуток.
Колонки не заполняют всё доступное пространство. См. скрин
`Основной экран после раунда 14.png`.

**Требования:**
- При ширине окна **1280 px** таблица должна помещаться целиком (без горизонтального
  скролла), а колонка «Действия» не должна уезжать за экран.
- При ширине окна **>1280 px** таблица должна равномерно заполнять доступную ширину
  (гибкие колонки «Содержание» и «Исполнители» растягиваются, фиксированные колонки
  остаются компактными, действия прижаты к правому краю без зазора).
- Не должно быть «кучи» колонок посередине экрана с пустым местом по бокам.
- Сохранить кламп сохранённых `col_widths` из `controls_settings.json`: если
  пользователь раньше растянул колонки, при следующем запуске они не должны
  превышать бюджет окна.

**Что нужно сделать:**
1. Исследовать в интернете, как в Flet/Flutter делать таблицу с фиксированными и
   гибкими колонками, заполняющую всю ширину (`ft.Row`/`ft.Column`, `expand`,
   `DataTable`, `ResponsiveRow`, `LayoutBuilder` — что доступно в Flet 0.23.2).
2. Проанализировать текущий `_build_row`, `_header_row`, `_layout_widths`,
   `_rebuild_header`, `_clamp_col_widths`.
3. Реализовать растягивание гибких колонок + прижатие действий к правому краю
   без пустого места.

### 2.3 Карточка контроля — resize handle и адаптивное содержимое

**Симптом 1:** при растягивании карточки вниз угол resize-handle остаётся на старом
месте. Чтобы снова растянуть, нужно навести на исходное положение угла, а не на
новый угол. См. `Карточка resize handle баг.png`.

**Симптом 2:** растягивается только рамка карточки, содержимое (блоки «Реквизиты»,
«Исполнение», «Сроки», «Пункты задания» и т.д.) не адаптируется — остаётся на
прежней высоте/ширине.

**Что нужно сделать:**
1. Исследовать в интернете, как в Flet/Flutter правильно делать абсолютно
   позиционированный resize-handle в `ft.Stack` (`Stack` + `left`/`top` vs
   `alignment` vs `Positioned`), чтобы хит-зона следовала за углом контейнера.
2. Исправить, чтобы при изменении `detail_card.width`/`height` handle тоже
   перемещался в новый правый нижний угол.
3. Сделать так, чтобы внутреннее содержимое карточки (`detail_content` / `middle` /
   левая и правая колонки) растягивалось вместе с карточкой. Использовать
   `expand=True` в правильных местах (соблюдая ограничение: нельзя `expand=True`
   внутри `Column(scroll=AUTO)` — см. AGENTS §15.11/22). Возможно, потребуется
   вынести скролл внутрь карточки иначе или перестроить layout.
4. Сохранить возможность resize и сохранение размеров в `controls_settings.json`.

## 3. Технические ограничения

- **Flet строго 0.23.2.** Не повышать.
- **Внутри `Column(scroll=ft.ScrollMode.AUTO)`** запрещено:
  - `expand=True` (кроме горизонтальных спейсеров внутри `Row`);
  - `wrap=True`;
  - `animate*`, `gradient`, `shadow` / `BoxShadow` на мелких контейнерах.
- **Цвета 8-digit — только `#AARRGGBB`** (альфа первая). Не `#RRGGBBAA`.
  Динамические полупрозрачные: `f"#22{color[1:]}"`.
- **`print()` в консоль — только ASCII** (без русских букв, emoji, спецсимволов),
  чтобы избежать `UnicodeEncodeError` на Windows cp1251.
- **UI-текст (`text=...`) — на русском.**
- **Иконки — `ft.icons.*`**, не emoji.
- **Все `.update()` контролов** — через `_safe_update()` (хелпер уже есть в
  `controls_tab.py`). Исключение: горячие hover-обработчики — там `_safe_update`
  без печати ошибок (или вообще без hover).
- **Не ломать весь текущий функционал:** сохранение справочников, прикрепление,
  таблица ≤1240 px при 1280, фильтры, экспорт Excel, сеть, архив, smoke ALL OK.
- **Не добавлять новых зависимостей.**
