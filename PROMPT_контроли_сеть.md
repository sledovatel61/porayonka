## 0. Контекст

Сценарий: локальная сеть, несколько ПК. Администратор (Потемкин С.А.) ведёт контроли.
У остальных ПК (роль `user`, `network_user` выбирается из криминалистов в настройках)
таблица должна обновляться сама, а при приближении сроков ИХ контролей — приходить
уведомления.

**Что уже есть в коде (НЕ писать с нуля, довести):**

- `core/controls_data.py`:
  - `read_shared_controls(settings)` (~стр. 398), `write_shared_controls(controls, settings)` (~412) — атомарная запись через `.tmp` + `os.replace`, `.bak`-копия; `get_shared_mtime(settings)` (~437).
  - `sync_attachments_from_shared`, `copy_attachment_to_local`, `copy_attachment_to_shared` — синхронизация вложений (`controls_attachments/` в shared-папке).
- `controls_settings.json`: `network_enabled`, `network_role` (admin/user), `network_user`, `shared_path`, `soon_days`.
- `ui/controls/controls_tab.py`:
  - `_background_loop` (~стр. 2244): polling сети раз в ~20 с (`_poll_network`, ~2257), уведомления раз в ~60 с (`_poll_notifications`, ~2281). Остановка — флаг `page._controls_poll_stop`.
  - `_poll_network`: сравнивает mtime, при изменении — молча подменяет `state["controls"]` и перестраивает таблицу (но НЕ при `state["editing"]` — тогда UI не трогает, но state уже подменён!).
  - `_poll_notifications`: сводный toast при росте числа просроченных (для всех ролей).
  - Индикатор в шапке: точка + «Локально» / «Сеть: админ|пользователь» (`_update_sync_ui`, ~265).
  - Роль user: список фильтруется по `executors`/`assignees == network_user` (`_visible_base`, ~283).
  - `_persist()` (~228): сохраняет локально + в shared, при ошибке записи ставит `network_ok=False`.
- Модель `Control` имеет `updated_at` (ISO-строка) — основа для merge.

**Известные дыры (их и чиним):**

1. Уведомления — только общая сводка; исполнитель НЕ получает персональных «это твой контроль».
2. При открытой карточке сетевые изменения молча подменяют `state["controls"]` — пользователь не знает, а при сохранении карточки перезапишет их (last-write-wins вслепую).
3. Офлайн-правки: сеть пропала → пользователь редактирует локально → сеть появилась → `_poll_network` тупо подменяет state сетевой версией, локальные правки ТЕРЯЮТСЯ.
4. Нет синхронизации вложений в polling-цикле (только при первичной загрузке).
5. Индикатор не различает «сеть выключена» и «сеть включена, но недоступна».

## Задача 1. Merge вместо тупой подмены (фундамент задач 2–5)

В `core/controls_data.py` добавить чистую функцию (легко тестируется headless):

```python
def merge_controls(local: List[Control], shared: List[Control]) -> List[Control]:
    """Union по id. При конфликте версий одного контроля побеждает более новый updated_at.
    Контроль, есть только на одной стороне, — сохраняется."""
```

- Сравнение `updated_at`: ISO-строки сравнимы лексикографически; пустое/битое значение считать старее.
- Известная оговорка (задокументировать в docstring): контроль, удалённый «навсегда» локально, но живой в shared, воскреснет при merge. Приемлемо — физическое удаление редкая ручная операция админа. НЕ городить tombstones.
- Порядок результата: порядок local, новые из shared — в конец (порядок стабилен для UI).

**Применить merge в `controls_tab.py`:**
- `_persist()` (перед записью в shared): если `network_enabled` и `get_shared_mtime() != state["shared_mtime"]` — кто-то писал, пока мы работали → перечитать shared, `state["controls"] = merge_controls(state["controls"], shared)`, залогировать в консоль ASCII (`[CONTROLS_TAB] merge: N controls from shared`), затем записать результат и обновить `state["shared_mtime"]`.
- `_poll_network()` при появлении сети после офлайна (см. задачу 4): тоже merge, НЕ подмена.

## Задача 2. Персональные уведомления исполнителю

Новая функция `_check_my_notifications()` в polling-цикле (тот же ~60-секундный шаг, что `_poll_notifications`; существующую сводку для admin НЕ трогать).

Логика (только если `network_enabled` и роль `user` и задан `network_user`):

- **(a) Новый контроль для меня:** контроль появился в данных (id не было в `state["known_ids"]` предыдущего снимка) и `network_user` ∈ executors или ∈ assignees любой задачи → toast «Новый контроль для вас: вх.№ {incoming_number}» + звук.
- **(b) Срок по моему контролю:** для моих неисполненных контролей `deadline_status` стал `OVERDUE`/`TODAY`/`SOON` → toast «Срок по контролю вх.№ {n}: просрочен / сегодня / скоро» + звук. Статусы считать один раз за цикл, сравнивать с `state["my_status_map"]` (id → status).
- **Антиспам — журнал в настройках:** `notify_log` в `controls_settings.json`, формат `{"<control_id>:<status>": "YYYY-MM-DD"}`. Уведомление (b) — не чаще одного раза в день на контроль на статус; (a) — один раз вообще (ключ `<control_id>:new`). После записи в журнал — `save_settings()`. При сохранении настроек подрезать записи старше 30 дней.
- **Звук:** `winsound.MessageBeep(winsound.MB_ICONEXCLAMATION)` в `try/except` (не Windows / нет звуковой схемы — молча пропускаем). Переключатель «Звук уведомлений» (`notify_sound`, default True) — добавить в `ui/controls/controls_settings_modal.py` (Checkbox, стиль как у существующих контролов модалки).
- Toast — через существующий `ui.toast.show_toast`, иконка `ft.icons.NOTIFICATIONS_ACTIVE`, вызовы из потока — в `try/except` (документированный риск, AGENTS §29.6). UI-текст русский, `print()` — ASCII.

## Задача 3. Конфликт при открытой карточке (last-write-wins вслепую)

Сейчас при `state["editing"]` polling подменяет `state["controls"]` молча. Переделать:

- `_poll_network()` при `state["editing"] == True`: НЕ подменять state. Сохранить пришедшее в `state["pending_shared"]` (список + mtime) и показать ОДИН диалог через `page.open()` / `page.close()` (AlertDialog — карточка у нас Container-overlay, системный диалог поверх — допустимо; вложенные AlertDialog поверх AlertDialog по-прежнему запрещены, AGENTS §31.5):
  - Текст: «Данные на сервере изменились. Обновить сейчас? Открытая карточка будет закрыта без сохранения».
  - Кнопки: «Обновить» → закрыть карточку (без сохранения), применить `pending_shared` (merge с текущим state на всякий случай), rebuild таблицы, toast «Данные обновлены из сети». «Позже» → диалог закрыть, `pending_shared` остаётся.
- При закрытии карточки (сохранение ИЛИ отмена): если `state["pending_shared"]` есть → применить merge (при сохранении это естественно сделает `_persist` из задачи 1; при отмене — явный merge + rebuild), очистить `pending_shared`.
- Диалог показывать ОДИН раз на одно открытие карточки (флаг, сбрасываемый при закрытии карточки), чтобы polling не спамил диалогами каждые 20 секунд.
- Без открытой карточки — текущее поведение (подхват + rebuild), плюс ненавязчивый toast «Данные обновлены из сети» (один на цикл изменений, не на каждый poll).

## Задача 4. Офлайн-устойчивость + индикатор

- Индикатор — три состояния (`_update_sync_ui`):
  - сеть выключена: точка серая, «Локально» (как сейчас);
  - сеть включена, shared доступен: точка зелёная (`GLASS["in_progress"]`), «Сеть: админ|пользователь»;
  - сеть включена, shared НЕ доступен: точка красная (`GLASS["overdue"]`), «Сеть: нет связи».
- `_poll_network()`: `get_shared_mtime` вернул None/упал → `network_ok=False`, обновить индикатор, выйти. Ранее был `network_ok=False`, а теперь mtime появился → «сеть вернулась»: перечитать shared, `merge_controls` (НЕ подмена — локальные офлайн-правки дороже), затем `write_shared_controls` результата merge (отдать свои офлайн-правки), rebuild, toast «Сеть восстановлена, данные синхронизированы».
- `_load_initial()`: при `network_enabled`, но недоступном shared — грузить локальный `controls.json` (убедиться, что fallback есть; если нет — добавить), `network_ok=False`.

## Задача 5. Вложения в polling-цикле

- После подхвата shared в `_poll_network` (и после merge в задаче 4): для контролей с непустым `attachments` вызвать `sync_attachments_from_shared(c.id, c.attachments, settings)` — сейчас это делается только в `_load_initial` (~стр. 256). Ограничить: только для контролей, которых не было в прошлом снимке или у которых изменился список вложений (иначе каждые 20 секунд лишний файловый обход). Ошибки копирования — `try/except` + ASCII `print`, цикл не ронять.

1. `merge_controls`: union по id; конфликт — побеждает новый `updated_at`; локальный новый контроль не теряется; порядок стабилен.
2. Симуляция двух инстансов через ОДНУ temp-папку как shared: «админ» пишет (`write_shared_controls`) → «пользователь» читает (`read_shared_controls` + `get_shared_mtime` изменилось) → получил данные.
3. Журнал уведомлений: два вызова логики уведомления в один день по одному контролю/статусу → toast только один раз (мокнуть `show_toast` или вынести решение «надо ли уведомлять» в чистую функцию `_should_notify(log, control_id, status, today)` и тестировать её).
4. Офлайн→онлайн: запись при недоступном shared (папка удалена/пустой путь) → `network_ok=False`, локальный файл сохранён; shared появился → merge не теряет локальную правку.
5. Подрезка журнала: записи старше 30 дней удаляются.

**В финальном сообщении:** имя ветки + чек-лист ручной приёмки на двух ПК (двух инстансах с общей папкой):
включить сеть (admin → общая папка; user → та же папка, `network_user` = один из криминалистов) →
админ создаёт контроль с этим исполнителем и близким сроком → у user за ~20–60 с: контроль в списке,
персональный toast + звук, повторного спама нет → user отмечает исполнение офлайн (папку переименовать) →
вернуть папку → правка не потерялась, появилась у админа → карточка открыта у user, админ правит →
диалог «Данные на сервере изменились».

## Ограничения (нарушение = баги в GUI, проверено болью)

- Цвета с прозрачностью — только `#AARRGGBB` (§32). Динамика — `with_alpha()`.
- Внутри `Column(scroll=AUTO)`: никаких `expand=True` (кроме горизонтальных спейсеров в Row), `wrap=True`, `animate*`, `shadow`, `gradient` на мелких контейнерах (§15.11, §22).
- Все `.update()` контролов — `_safe_update()`. В горячих обработчиках — никаких `traceback.print_exc()` (§36.2); в остальных обработчиках исключения — `traceback.print_exc()`, не глушить.
- Вложенные `AlertDialog` запрещены (§31.5). FilePicker — `overlay.append` + `page.update()` (§31.5).
- `ft.icons.*` (не emoji), `print()` — только ASCII, UI-текст — русский.
- Flet строго 0.23.2, без новых pip-зависимостей.
- Не ломать: вкладки «Следственные отделы» и «Зональные», Excel-импорт/экспорт, архив, роли, существующие контракты функций. Не вводить read-only для роли user — исполнитель должен отмечать исполнение своих пунктов.
- Поток polling — daemon, останавливается по `page._controls_poll_stop`; UI-вызовы из потока только в `try/except`.
