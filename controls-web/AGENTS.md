# AGENTS.md — правила работы с новой системой `controls-web`

Этот каталог — **новая система** (этап W01: технический стенд). Правила дополняют корневой `AGENTS.md`
репозитория и `../migration-web/AGENTS.md`. При расхождении приоритет у задания текущего этапа и у
решений владельца, зафиксированных в `../migration-web/decisions.md`.

## 1. Границы системы

- `controls-web` полностью независим от Flet-приложения `porayonka-app` и от прототипа `src/`.
- Запрещено: импортировать из legacy код, запускать legacy-процессы из нового сервера, читать рабочие
  JSON, каталог вложений `%APPDATA%`, UNC-ресурсы, `Контроли ОКРИМ.xlsx`.
- Запрещено менять `porayonka-app`, `src`, legacy-тесты, `Porayonka_Win7.spec`, `requirements-win7-web.txt`,
  данные и документы статуса (`../migration-web/05-status.md`).
- Все данные стенда — синтетические. Настоящие ФИО, входящие номера, сканы и адреса не появляются
  ни в коде, ни в тестах, ни в отчётах.

## 2. Стек и версии

- Backend: Python 3.11, FastAPI, psycopg 3, PostgreSQL **≥ 14** (проверено на 16.14).
- Frontend: React + TypeScript + Vite, обычный CSS без UI-библиотек.
- Версии фиксируются в `backend/requirements.txt` + `backend/requirements.lock.txt` и
  `frontend/package.json` + `frontend/package-lock.json`. Любое изменение версии — с обоснованием
  совместимости в README и с обновлением lock.
- Замена PostgreSQL на SQLite, файлы JSON или иную БД **запрещена**, в том числе «временно для тестов»:
  тесты поднимают отдельную базу `controls_web_w01_test` на том же сервере PostgreSQL.

## 3. Браузерный минимум

- Целевой браузер: **Яндекс Браузер 24.10.3.843 corp** на Windows 7 (подтверждено владельцем 17.09.2026),
  самый слабый ПК 1366×768 / 4 ГБ RAM.
- `build.target` и `cssTarget` в `frontend/vite.config.ts` заданы явно: `['chrome109','edge109','firefox115']`.
  Порог консервативный, потому что точная версия движка Chromium в сборке 24.10 публично не раскрыта.
- Запрещены в коде и проверяются тестом `backend/tests/test_frontend_build.py`:
  `toSorted/toReversed/toSpliced`, `Object.groupBy`, `Promise.withResolvers`, `structuredClone`,
  `Object.hasOwn`, `URL.canParse`, `navigator.share`, `showOpenFilePicker`, `Intl.Segmenter`,
  `findLast/findLastIndex`, `Array.prototype.at`; CSS: `color-mix()`, `@scope`, `@container`, `subgrid`,
  `text-wrap`, `:has()`.
- Запрещены CDN, внешние шрифты, телеметрия, внешняя аналитика, Electron, Flutter Web, Canvas-приложение.
- Frontend обращается к API только по относительным путям `/api/...` (тот же origin).
- Поднять порог можно только после фиксации `browser://version` с реальной машины (блокер B-03).

## 4. Правила API

- Все пользовательские тексты и сообщения об ошибках — на русском.
- Форма ошибки: `{"error": {"code": "...", "message": "..."}}`. Стеки и внутренние детали клиенту не отдаются.
- Список всегда постраничный: `page_size` по умолчанию 50, максимум 200. Отдавать все записи одним
  ответом запрещено.
- Сортировка списка обязана совпадать с индексом `controls_list_order_idx`
  (`receive_date DESC NULLS LAST, incoming_number DESC NULLS LAST, id DESC`) — иначе пагинация нестабильна.
- Поиск — параметризованные запросы; служебные символы LIKE экранируются (`app/repo.py: escape_like`).
- Конфликт версий, идемпотентность записи, авторизация, роли, аудит — этапы W02+; в W01 не добавлять.

## 5. Правила работы с файлами

- Идентичность вложения: пара `(control_id, rel_path)`, где `rel_path = <control_id>/<имя файла>`.
- Тот же путь и другое содержимое → `409` с русским сообщением (правило унаследовано от legacy).
- Повторная загрузка идентичного файла идемпотентна (`created: false`, дубль строки не создаётся).
- Тип файла определяется по содержимому (сигнатура `%PDF`), а не по `Content-Type` клиента.
- Не-ASCII значения в HTTP-заголовках — только percent-encoded (RFC 5987). Прямая кириллица в заголовке
  ломает starlette (latin-1) и даёт 500: это найдено на стенде и закрыто тестом.
- Каталог загрузок не раздаётся статикой и не попадает в git; файлы доступны только через endpoint
  по идентификатору вложения.

## 6. Временные endpoints W01

- `/api/w01-test/*` (загрузка, скачивание, генератор PDF, справка) — временные.
- До передачи W02 их нужно удалить или закрыть (`CONTROLS_WEB_ENABLE_TEST_ENDPOINTS=0`, что отключает
  также `/api/docs` и `/api/openapi.json`).
- Новая функциональность не должна зависеть от этих endpoints.

## 7. База данных

- Схема стенда — `backend/app/schema.sql` (идемпотентная, применяется при старте при `AUTO_SCHEMA=1`).
- Инструмент миграций выбирается в W02; до этого изменения схемы делать только в `schema.sql` и только
  добавляя `IF NOT EXISTS`-совместимые конструкции.
- `controls.legacy_raw` (jsonb) хранит исходный словарь записи: неизвестные поля legacy не теряются.
- Детерминированное наполнение — `backend/app/seed.py`; uuid генерируются `uuid5` от seed, digest пишется
  в `seed_meta`. Любое изменение генератора меняет digest — это ожидаемо и фиксируется в отчёте.

## 8. Тесты и проверки

- Тесты backend: `cd backend && .venv/bin/python -m pytest` (64 теста, отдельная тестовая БД).
- Smoke по HTTP: `bash scripts/smoke_http.sh` (49 проверок, требует запущенный стенд).
- Измерения: `backend/.venv/bin/python scripts/measure.py --repeats 30` (p50/p95, фиксирует среду).
- Новое поведение добавляется вместе с тестом. Проверка, которая не выполнялась, не объявляется пройденной.
- Проверки сборки фронтенда: `npm run typecheck`, `npm run build` (сборка падает при ошибке типов).

## 9. Безопасность и гигиена

- Секреты (пароли БД, ключи сессий) — только из окружения, никогда в git и не в отчётах.
- `CONTROLS_WEB_DEBUG=0` при показе владельцу и в любом production-контуре.
- Локальные артефакты (`.venv`, `node_modules`, `dist`, `.pgdata`, `uploads`, `measurements`, `.env`)
  в git не попадают — см. `.gitignore`.
- Отчёты и уточнения по этапам пишутся в `../migration-web/reports/`, а не в этот каталог.

## 10. Границы этапа

- В W01 не реализуются и не «начинаются»: авторизация и роли, редактирование, бизнес-операции, импорт
  Excel, архив, уведомления, polling, перенос рабочих данных, production deployment, HTTPS, резервные копии.
- W02 не начинать без отдельного задания владельца.
- Совместимость с Win7 не объявлять до протокола ручной проверки на настоящей машине
  (`docs/win7-checklist.md`). Статус до тех пор — «ожидает проверки».
