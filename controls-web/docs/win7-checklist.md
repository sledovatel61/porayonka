# Инструкция владельцу: ручная проверка стенда с настоящего Windows 7

Проверка занимает 10–15 минут. Нужны: машина с Windows 7 и Яндекс Браузером 24.10.3.843 corp,
сетевой доступ к стенду, секундомер (телефон подходит). Рабочие данные и сканы загружать **не нужно** —
в стенде только синтетические записи.

## 0. Подготовка (один раз)

1. Развернуть стенд по `README.md` на согласованном хосте и убедиться, что он отвечает:
   `curl http://<адрес стенда>:8080/api/health` → `"status":"ok"`, `"database":"ok"`.
2. Наполнить стенд: 10 000 синтетических записей (`scripts/provision_stand.sh` делает это автоматически).
3. Убедиться, что с Win7-машины адрес стенда открывается (при необходимости — правило в firewall).
4. Записать параметры машины: версия Windows 7 и разрядность, RAM, разрешение и масштаб экрана,
   версия браузера (`browser://version`), включён ли режим Турбо (должен быть выключен).

## 1. Что сделать на машине с Windows 7

| Шаг | Действие | Что записать |
|---|---|---|
| 1 | Открыть `http://<адрес стенда>:8080/` | Время до появления первой таблицы (секундомер), есть ли ошибки в интерфейсе |
| 2 | Посмотреть на шапку | Видны ли счётчики (всего / в работе / исполнено / просрочено / в архиве) |
| 3 | Посмотреть на строку состояния внизу | Написано ли «Показано 50 строк из …», есть ли время ответа сервера |
| 4 | Прокрутить список из 50 строк вниз и вверх | Плавность: есть ли рывки, «подвисания», мигания |
| 5 | Ввести в поиск `СТЕНД-000042` и нажать «Найти» | Время до результата; найдена ли ровно одна запись |
| 6 | Ввести в поиск `сводку` и нажать «Найти» | Время до результата; видны ли строки |
| 7 | Нажать «Сбросить», затем «Вперёд» 5 раз подряд | Время каждого перехода (примерно), нет ли ошибок |
| 8 | Перейти в конец списка кнопкой «В конец» | Время перехода, видно ли 50 строк |
| 9 | Кликнуть по любой строке | Время открытия карточки справа; читаются ли русские тексты, даты, ФИО |
| 10 | В карточке посмотреть раздел «Пункты» | Видны ли пункты, даты, отметки «исполнено» |
| 11 | Нажать «Скачать синтетический PDF» | Скачался ли файл; читается ли русское имя файла; открывается ли PDF; видна ли кириллица внутри |
| 12 | Нажать «Выбрать PDF и загрузить», выбрать скачанный PDF | Появилось ли сообщение об успехе; появился ли файл в разделе «Вложения» |
| 13 | Скачать загруженный файл по ссылке в карточке | Совпал ли файл с исходным (открывается, тот же размер) |
| 14 | Попробовать загрузить тот же файл под тем же именем ещё раз | Повтор accepted без дубля (сообщение «уже был загружен ранее») |
| 15 | Отключить сеть (вынуть кабель / выключить Wi-Fi) и нажать «Обновить» | Появилось ли понятное русское сообщение о потере связи и кнопка «Повторить» |
| 16 | Вернуть сеть и нажать «Повторить» | Восстановился ли список |
| 17 | Оставить страницу открытой на 5–10 минут и поработать дальше | Не «поехала» ли вёрстка, не выросла ли заметно память вкладки (в браузере: `browser://process-internals` или диспетчер задач) |

## 2. Что обязательно приложить к протоколу

- Параметры машины и браузера (п. 0.4), адрес стенда, дата и время проверки, ФИО проводившего (роль, не обязательно полное имя).
- По каждому шагу: получилось / не получилось; сообщения об ошибках **дословно**.
- Скриншоты: список, карточка, строка состояния, сообщение о потере связи, окно загрузки файла.
- Время (секундомер) для шагов 1, 5, 6, 8, 9.
- SHA сборки стенда: `git rev-parse HEAD` в каталоге репозитория и имена файлов из `frontend/dist/assets`.

## 3. Критерии, по которым проверка считается пройденной

- Список открывается не дольше согласованного порога (порог фиксируется после первого прогона; ориентир — до 3 с).
- Поиск и переход по страницам выполняются без ошибок и без «белого экрана».
- Кириллица читается везде: список, карточка, даты, имена файлов, текст внутри PDF.
- Файл скачивается и загружается повторно, дубли не создаются.
- Потеря связи показывает понятное русское сообщение и не теряет данные (в стенде редактирования нет).
- Память вкладки не растёт заметно за 10 минут простоя.

## 4. Если что-то не работает

1. Не перезагружать стенд и не «починять» на месте: зафиксировать сообщение об ошибке и шаг.
2. Проверить, что адрес и порт введены верно и стенд запущен (`/api/health` отвечает).
3. Проверить, что режим Турбо в Яндекс Браузере выключен (он проксирует трафик и может блокировать локальные адреса).
4. Уточнить у администратора, не блокируют ли корпоративные политики браузера загрузку файлов.
5. Передать протокол: по нему будут заведены риски и исправления, а статус совместимости сменится
   с «ожидает проверки» на подтверждённый или на список дефектов.
