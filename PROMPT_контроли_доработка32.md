## 1. Пароль администратора в dev-режиме

**Симптом:**
```cmd
set PORAYONKA_EDITION=admin
python main.py
```
— открывается диалог ввода пароля (верно, пароль установлен через настройки приложения и сохранён в `%APPDATA%\porayonka\edition.json`). Ввод пароля `1` → UI таблицы строится, но модальный диалог пароля **не закрывается** (или мгновенно появляется повторно), войти в приложение нельзя.  
Если удалить `%APPDATA%\porayonka\edition.json` — пароль не запрашивается (как и раньше, но это не решение).

**Причины (гипотезы):**
1. Раунд 31 в `core/edition.py::load_edition` сделал так, что в dev-режиме (`not frozen`) env-переменная `PORAYONKA_EDITION=admin` берёт редакцию **только** из env, а пароли из файлов (`%APPDATA%\porayonka\edition.json`) не читаются. Из-за этого пользователь не может протестировать в dev-режиме пароль, установленный через UI настроек.
2. `ui/admin_gate.py::show_admin_password_gate` использует `page.close(dlg)` + `page.update()` + `on_ok()`, но в Flet 0.23.2 диалог остаётся видимым / клиент дублирует событие submit/клик.

**Требуемое поведение:**
- В dev-режиме (`python main.py`, не frozen): `PORAYONKA_EDITION=admin` задаёт **роль**, но если env не задаёт пароль (`PORAYONKA_ADMIN_PASSWORD` / `PORAYONKA_ADMIN_PASSWORD_HASH`), пароль должен читаться из `%APPDATA%\porayonka\edition.json` (как в обычной работе приложения).  
  Если env-пароль задан — он имеет приоритет (для теста).  
  Если пароля нет ни в env, ни в файле — вход без пароля (как сейчас).
- В frozen-сборке: приоритет у `edition.json` рядом с exe (как сейчас), env-пароль тоже имеет приоритет, если задан.
- После верного пароля диалог должен **гарантированно закрыться** перед построением UI. Попробовать, если `page.close(dlg)` не срабатывает:
  - `page.overlay.remove(dlg)` + `page.update()`;
  - `dlg.open = False` + `page.update()`;
  - комбинацию.
- Флаг `_submitted` уже есть — он должен предотвращать повторный вызов `on_ok()` и `_close_app` при дублировании событий клиента.
- После успешного входа приложение работает, таблица отрисовывается один раз (не «тускло/дважды»).

## 2. Трей: «Открыть» не восстанавливает окно

**Симптом:**
- Запускаем `python main.py` (Windows, установлены `pystray`/`pillow`).
- Закрываем окно крестиком — значок остаётся в трее (правильно).
- Клик по значку → «Открыть» — окно приложения **не появляется**, приходится перезапускать программу.
- В web-режиме трей не падал, но для нативного режима это критично.

**Причины:**
- В `main.py` обработчик `on_window_event` при `e.data == "close"` вызывает `page.window.close()` — приложение уничтожается, а не сворачивается.
- `ui/tray_icon.py::_show` делает `page.window.visible = True; page.window.to_front(); page.update()`, но окна уже нет.\n**Требуемое поведение:**
- При закрытии окна крестиком (и только при закрытии окна, не при «Выход» из трея) нативное приложение должно **сворачиваться/скрываться**, а не завершаться:
  - `page.window.prevent_close = True` (уже стоит);
  - в `_on_window_event` при `close` вместо `page.window.close()` делать `page.window.visible = False` (или `page.window.minimized = True` — проверить, что работает в Flet 0.23.2) + `page.update()`.
  - Остановить фоновый polling (`page._controls_poll_stop["flag"] = True`) и сохранить данные (как сейчас), но процесс продолжает работать.
- Кнопка «Открыть» в трее восстанавливает окно:
  - `page.window.visible = True`;
  - `page.window.minimized = False` (если используется minimize);
  - `page.window.to_front()`;
  - `page.update()`.
  - При этом фоновый polling должен возобновиться, если был остановлен, или продолжать работать, если не останавливался. polling-цикл в `controls_tab.py` должен быть устойчив к visibility окна.
- «Выход» в трее — полный выход: остановить polling, сохранить данные, `icon.stop()`, `page.window.destroy()`/`close()`, `os._exit(0)` как fallback.
- В dev-режиме, если `pystray`/`pillow` нет — приложение просто работает без трея (как сейчас).
- Web-режим: трей работает как сейчас («Открыть в браузере» открывает вкладку, сервер продолжает работать после закрытия браузера).

## 3. Excel-экспорт: «Следующая дата исполнения» должна быть персонализирована для пользователя

**Симптом:**
- В user-редакции (и при экспорте админом с фильтром по конкретному исполнителю) в колонке «Следующая дата исполнения» экспортируются **общие** даты контролей, а не даты, актуальные для этого пользователя по его пунктам.
- Пример: `Миронович Д.В.` имеет в контроле пункт `п.2` с датой `01.05.2026`, а в экспорте для этого контроля стоит `16.02.2026` / `01.09.2026` — даты, относящиеся к чужим пунктам или общему сроку.
- Скрины: `design/screenshots/13.08.2026/Экспорт контролей у пользователя1.png` и `...2.png`.

**Требуемое поведение:**
- В `core/controls_exporter.py::ControlsExcelExporter.export` добавить параметр `user_name: str = ""`.
- Если `user_name` не пуст:
  - Колонка «Следующая дата исполнения» (9) = `user_effective_due_date(control, user_name)` (уже есть в `core/controls_models.py`).
  - Статус для жёлтой подсветки = `user_deadline_status(control, user_name, soon_days)` (уже есть).
- Если `user_name` пуст (admin без персонального фильтра):
  - Как сейчас: `effective_due_date` + `deadline_status`.
- Жёлтая заливка по-прежнему **только** для `OVERDUE`/`TODAY`; `SOON` не подсвечивается.
- В `ui/controls/controls_tab.py::_on_export_picked` передавать `user_name`:
  - Для `network_role == "user"` — `settings.get("network_user")`.
  - Для `network_role == "admin"` и выбранного фильтра «Все исполнители» конкретного ФИО (не «Все» и не «Прочие») — это ФИО.
  - В остальных случаях — пусто (общий вид admin).
- Колонки «Содержание» и «Исполнители» по-прежнему `wrap_text=True`, высота строки по контенту (не ломать).
- Проверить, что при экспорте в user-редакции даты в Excel совпадают с датами, которые видит пользователь в таблице приложения (колонка «Срок исполн.»).

## 4. Общие ограничения (как всегда)

- Flet строго **0.23.2**. Не повышать.
- Не добавлять новых зависимостей.
- `print()` в консоль — только ASCII (без русских букв, emoji, спецсимволов), чтобы избежать `UnicodeEncodeError` на Windows cp1251.
- UI-текст (`text=...`) — на русском.
