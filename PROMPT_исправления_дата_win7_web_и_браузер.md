## Критическое требование по Win7 Admin

**Win7 Admin Web нельзя урезать.** Административная Win7-сборка должна остаться полной версией приложения со всем функционалом:

- «Контроли»;
- «Зональные криминалисты»;
- «Следственные отделы»;
- Excel-импорт/экспорт;
- архив и вложения;
- сеть и уведомления;
- справочники;
- редактирование, добавление, удаление и прочие admin-возможности.

Не создавать Admin Win7-сборку только со вкладкой «Контроли» и не удалять функции ради производительности. Оптимизировать нужно реализацию: ленивое создание вкладок, кеширование уже созданных вкладок, устранение лишних пересборок и `page.update()`. После первого открытия «Зональные» и «Следственные отделы» должны работать со всем прежним функционалом.

User и Admin, Desktop и Web редакции также не ломать. Flet строго `0.23.2`.

## 1. Очистка конечной даты периодического контроля

Проверить:

- `ui\controls\control_card_modal.py`;
- `ui\controls\russian_calendar.py`;
- `core\controls_models.py`;
- `core\controls_exporter.py`;
- `tests\test_controls_smoke.py`;
- `tests\test_round38.py`.

Сейчас карточка использует `ft.DatePicker`, а конечная дата хранится в `end_ref["value"]` и сохраняется так:

```python
c.end_date = end_ref["value"] if c.control_type == PERIODIC else None
```

В `russian_calendar.py` уже есть очистка через `on_change(None)`, но она не подключена к полю конечной даты.

Требования:

1. Добавить в карточку явную понятную команду очистки конечной даты.
2. После очистки поле отображает пустое или «не указана» состояние.
3. Нажатие «Сохранить» записывает `end_date=None`.
4. После повторного открытия карточки дата не восстанавливается.
5. Очистка не меняет `due_date`, `period_days`, `tasks` и `milestones`.
6. Переключение периодического контроля в разовый по-прежнему обнуляет `end_date`.
7. После очистки выбор новой даты снова корректно устанавливает дату.
8. Не создавать два независимых календаря. Если подключается русский календарь, сохранить единый контракт `on_change(Optional[str])`.

Добавить регрессионную проверку полного round-trip: заданная дата → очистка → сохранение `None` → повторное открытие без даты → выбор новой даты. Проверить также Excel round-trip: пустая дата не восстанавливает старое значение, заданная дата продолжает экспортироваться и импортироваться.

## 3. Устранить двойное открытие браузера

Проверить:

- `main.py`;
- `main_web.py`;
- `start_web_win7.bat`;
- `Porayonka_User_Web.spec`;
- `Porayonka_Admin_Web.spec`.

Факты:

- `main.py` использует `ft.AppView.WEB_BROWSER`;
- Flet runtime сам открывает браузер в этом режиме;
- `main_web.py` дополнительно вызывает `webbrowser.open()`;
- batch-файл также может выполнять `start http://127.0.0.1:8555`.

Оставить ровно одного владельца открытия браузера. Предпочтительная схема:

- оставить `ft.AppView.WEB_BROWSER`;
- убрать ручной `webbrowser.open()` из обычного запуска `main_web.py`;
- `start_web_win7.bat` только запускает сервер и ждёт доступности HTTP, но не открывает URL второй раз;
- повторный запуск уже работающего сервера не должен создавать две новые вкладки;
- поиск свободного порта и web Admin/User режимы сохранить.

Добавить статические или mock-тесты, подтверждающие отсутствие одновременного ручного открытия в `main_web.py` и batch-файле при сохранении единственного согласованного механизма.

## 4. Два значка приложения в трее в обычной Admin Desktop

Фактический дефект: в обычной админской Desktop-версии Windows одновременно
появляются два одинаковых значка «Порайонка» в системном трее. Исправить
первопричину, а не просто скрывать один из значков.

Проверить:

- `ui\tray_icon.py`, прежде всего `start_tray()`, `_ACTIVE_ICON`,
  `run_detached()`, обработчики «Открыть» и «Выход»;
- `main.py`, все места вызова `start_tray()` и жизненный цикл `main(page)`;
- `core\autostart.py`, значение реестра `PorayonkaControls` и фактическую
  команду автозапуска;
- batch/shortcut/installer-файлы Admin Desktop, если они могут запускать exe
  более одного раза.

Требования:

1. В одном запущенном Admin Desktop-процессе создаётся ровно один объект
   `pystray.Icon` и регистрируется ровно один значок.
2. Повторный вызов `start_tray()` безопасен и возвращает уже существующий
   значок; инициализация должна быть защищена от гонки между потоками (проверка
   `_ACTIVE_ICON` после захвата lock, а не только до него).
3. Если два экземпляра exe действительно запускаются параллельно, добавить
   Windows-compatible single-instance guard (например, named mutex) либо иной
   надёжный механизм. Второй запуск не должен создавать второй tray icon;
   он должен корректно завершиться или передать команду первому экземпляру
   согласно существующей архитектуре.
4. Не запускать трей одновременно из нескольких входов (`main()`, `_entry()`,
   `main_web.py`, callback Flet или автозапуск). Desktop и Web-сценарии должны
   иметь явно определённого владельца tray lifecycle.
5. При «Выходе» корректно остановить icon, освободить singleton/mutex и не
   оставлять «призрачный» значок после завершения процесса. При закрытии окна
   крестиком текущую семантику сворачивания в трей сохранить.
6. Не урезать функционал Admin и не отключать трей как обходной путь.

Добавить тесты/диагностику, подтверждающие количество вызовов регистрации,
повторный вызов `start_tray()`, конкурентный вызов и корректное освобождение.
На реальной Windows-проверке запустить свежую Admin Desktop-сборку, убедиться,
что после одного запуска виден ровно один значок, после закрытия/повторного
запуска не остаётся старых значков и автозапуск не порождает второй процесс.

## 5. Импорт Excel не срабатывает в Admin Win7 Web

Фактический сценарий воспроизведения на Win7 Admin Web:

1. Удалить все существующие контроли, чтобы таблица была пустой.
2. Нажать административный импорт Excel.
3. Диалог выбора файла открывается, файл выбирается, диалог закрывается.
4. Импорт не выполняется, preview/ошибка не показываются, таблица остаётся
   пустой.

Проверить полный путь события, а не только `core.controls_exporter.py`:

- `ui\controls\controls_tab.py`: `_ensure_file_picker()`,
  `_on_import_picked()`, `_preview_import()`, `_confirm()`, создание
  `_controls_import_picker`;
- `core\controls_exporter.py`: `import_plan()` и разбор полного/табличного
  Excel-формата;
- Flet `0.23.2` FilePicker в Desktop и Web, включая отличие результата
  выбора/загрузки файла в Web;
- `main_web.py`, `Porayonka_Admin_Web.spec` и web static/upload assets.

Требования:

1. После выбора `.xlsx` в Admin Win7 Web должен гарантированно запускаться
   импорт: получить фактически доступный локальный путь/загруженный файл,
   дождаться завершения upload при необходимости и передать его в
   `import_plan()`.
2. Обработать все поддерживаемые формы результата Flet 0.23.2 (`path`,
   `files[*].path`, имя/загруженный путь и соответствующие web-атрибуты), не
   подставлять фиктивный путь и не считать импорт успешным до фактического
   чтения `.xlsx`.
3. Если файл отменён, upload не завершён или путь недоступен, показать
   понятную русскую ошибку/toast и записать ASCII-safe причину в startup/error
   log. Исключение не должно молча теряться в `console=False`.
4. При пустой таблице импорт должен добавить все валидные записи, присвоить им
   уникальные `id`, сохранить rich-поля/вложения по существующим правилам и
   обновить модель, counters и таблицу после подтверждения preview.
5. Не обходить preview/upsert: сохранить новые/обновляемые/без изменений/
   конфликты/ошибки и backup перед применением. User-режим по-прежнему не
   должен получать импорт.
6. FilePicker должен быть добавлен в `page.overlay` до `page.update()`, а
   обработчик должен быть подписан ровно один раз и не накапливаться при
   повторном создании вкладки/переходе между вкладками.
7. Desktop-импорт не сломать. Не решать проблему удалением Excel-импорта или
   превращением Admin Win7 в урезанную сборку.

Добавить регрессионный smoke/mock-тест именно сценария Admin Web: пустой список
контролей → событие выбора/загрузки `.xlsx` → preview с найденными записями →
подтверждение → записи появились в таблице/модели. Отдельно проверить отмену,
ошибочный файл и повторный импорт; по возможности выполнить ручную проверку
на Win7 в собранном `Порайонка_Админ_Web.exe`.
