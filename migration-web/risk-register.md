# risk-register.md — риски переезда «Контролей» в браузер

База: SHA `b5f24ab58c642fafb5cca616aa8b4e16d3a3de3f`. Формат записи:
**Причина → Последствия → Как проверить → Как снизить → Где закрывается → Блокирует ли ввод.**
«Блокирует ввод» = W09 (пилот/переключение) нельзя начинать, пока риск не снижен до
принятого владельцем уровня. Ссылки R##/F-##/D-##/S-## — на
`requirements-matrix.md`, `field-mapping.md`, `decisions.md`.
Приоритеты: **P0** — потеря/утечка рабочих данных или невозможность работы; **P1** —
существенное ухудшение; **P2** — тактическое.

---

## P0

### RISK-01. Win7/старый браузер не потянет выбранную сборку

- **Причина:** браузер и его версия на Win7 не определены (N-02 в `decisions.md`).
  Legacy-профиль `porayonka-app/requirements-win7-web.txt` закрепляет стек эпохи Flet
  0.23.2 именно потому, что транзитивный Rust-код (pydantic-core 2.x, watchfiles) на Win7
  не импортируется **[Код]**; набор требований React/TS-сборки другой и не замерен.
- **Последствия:** приложение не открывается или открывается пустой страницей;
  обещание «работает на Win7» оказывается невыполненным; возврат к переделке стека.
- **Как проверить:** W01 — сборка под точную версию браузера + ручная проверка на РЕАЛЬНОЙ
  машине Win7 (открыть, искать, карточка, загрузить/скачать PDF с кириллицей, прокрутка);
  замеры холодного открытия, поиска, памяти. Эмуляция DevTools доказательством не является
  (`01-architecture.md`).
- **Как снизить:** никаких обязательных новейших API и CDN; целевой ES-пакет по
  результатам замера; список полифилов = только использованные; если браузер слишком
  стар — возврат к решению W00 о стеке, а не «дотягивание» сборки; установка более
  нового браузера — только с разрешения владельца.
- **Где закрывается:** W01. До его закрытия полный перенос функций не разрешён.
- **Блокирует ввод:** да.

### RISK-02. Сервер не подтверждён: негде разместить БД и сервис

- **Причина:** N-01 — нет ответа, есть ли постоянно включённая машина с поддерживаемой ОС,
  кто её обслуживает, можно ли установить PostgreSQL и сертификат.
- **Последствия:** соблазн «временно» держать базу на сетевой папке или на ПК
  администратора — то есть воспроизвести схему, от которой уходят; незаметная подмена
  PostgreSQL на SQLite прямо нарушает `01-architecture.md`.
- **Как проверить:** письменное подтверждение владельца: хост, ОС, ответственное лицо,
  право на установку, адрес/порт в ЛВС, сертификат, режим резервного копирования.
- **Как снизить:** W00 не начинает код без ответа; стенд W01 — в тестовой сети на
  временном хосте, без рабочих данных; перенос стенда на боевой хост — отдельная
  процедура W08.
- **Где закрывается:** W00 (решение) → подтверждение в W01/W02.
- **Блокирует ввод:** да.

### RISK-03. Утечка чужих данных по прямой ссылке

- **Причина:** доступ в legacy — UI-фильтр: пользователь читает весь `controls.json` и всю
  общую папку вложений (R12); в web-режиме скачанные копии кладутся в каталог,
  отдаваемый как `/assets/downloads/<имя>` без авторизации
  (`ui/controls/controls_tab.py:3295–3320`)**[Код]**. Непредсказуемый URL защитой не
  является (`01-architecture.md`).
- **Последствия:** чужие служебные документы и ФИО доступны любому, кто видит каталог или
  угадает имя; файлы оседают в кэше браузера и в общем профиле ПК.
- **Как проверить:** на W02/W04 тестами: `GET /files/{id}`, `GET /controls/{id}`,
  `GET /exports/{token}`, `GET /imports/{token}` чужого пользователя → 403/404;
  проверка `Cache-Control`; отсутствие раздачи каталога загрузок; повторение проверки
  внешним аудитом на W08.
- **Как снизить:** файлы вне публичной статики, доступ только через авторизованный
  endpoint с политикой «участник контроля»; `Content-Disposition: attachment`,
  `no-store`, inline — только PDF/изображения; временные подписанные URL короткого TTL,
  привязанные к пользователю; токены предпросмотра импорта/экспорта — тоже привязаны.
- **Где закрывается:** W02 (политика), W04 (файлы), W08 (проверка).
- **Блокирует ввод:** да.

### RISK-04. Потеря или искажение данных при миграции

- **Причина:** (1) строковые ФИО вместо идентификаторов (F-06); (2) отсутствующие `id`,
  которые legacy «лечил» uuid (F-01/F-02); (3) `Control.from_dict` молча теряет
  неизвестные ключи JSON (R02); (4) парсер содержания вырезает нераспознанный текст внутри
  диапазона пунктов (R18 — подтверждено реальным прогоном); (5) скрытый лист Excel не
  содержит `created_at/updated_at/archived_at` (R15); (6) «самолечение» значений
  (`period_days` 0→7, невалидная дата→None) маскирует дефекты.
- **Последствия:** потерянные пункты/сроки/комментарии, обрезанное содержание, неверные
  владельцы пунктов, невозможная сверка «до/после».
- **Как проверить:** dry-run миграции на копии + полный сверочный отчёт по
  `field-mapping.md` §7 (все 8 сверок); отдельная проверка «ни одно непустое значение не
  стало пустым»; идемпотентность повторного запуска; обратный полный Excel-экспорт и
  сравнение с экспортом legacy.
- **Как снизить:** только воспроизводимые правила; `legacy_raw` для спорного; неразрешённые
  ФИО и коллизии — блок до переключения; миграцию выполняют локально уполномоченные лица,
  реальные данные в Arena/GitHub не попадают; односторонний перенос legacy → новая, без
  двусторонней синхронизации (AGENTS §6).
- **Где закрывается:** W07 (миграция), W08 (репетиция на копии).
- **Блокирует ввод:** да.

### RISK-05. Конфликты одновременного редактирования

- **Причина:** legacy решает их LWW по `updated_at` без слияния полей (R22); часовой
  сдвиг или часы «из будущего» меняют победителя (`core/controls_data.py:1149–1199`,
  `docs/network_audit_report.md` §4.3)**[Код]**; файловый lock — advisory, только для
  открытой карточки и только у admin-редакции, протухает через 10 мин
  (`core/control_locks.py:22`, `:112–140`).
- **Последствия:** правка исчезает молча; в браузере «окно редактируется» не защитит
  закрытую вкладку, уснувший ПК или второй браузер того же пользователя.
- **Как проверить:** W02/W03: два браузера, параллельные сохранения одной карточки →
  409 у второго и сохранение его черновика; повтор запроса с тем же `Idempotency-Key` →
  не дубль; отсутствие «вечной» блокировки.
- **Как снизить:** `revision` + условная запись (`If-Match`) + 409 (D-02); серверное
  время вместо клиентского; окно сравнения версий с сохранением ввода (ui-outline §5);
  массовые операции — со списком `revision[]`.
- **Где закрывается:** W02 (контракт), W03/W04 (UX), W06 (обновления).
- **Блокирует ввод:** да.

### RISK-06. Потеря вложений и неатомарность «БД + файлы»

- **Причина:** публикация файла и запись ссылки — разные шаги: при отказе остаётся ссылка
  на неопубликованный файл или осиротевший `.tmp` (round 38 stress 5c); удаление файла из
  карточки не сохраняет отвязку, поэтому «Отмена» оставляет битую ссылку (R14,
  `ui/controls/controls_tab.py:3487–3506`)**[Код]**; чтение предпочитает shared-копию
  (`core/controls_data.py:1066–1082`), и два хранилища могут расходиться.
- **Последствия:** «файл не найден», обрезанный скан, сироты в хранилище, расхождение
  ссылок после слияния дублей.
- **Как проверить:** W04: загрузка с разрывом соединения → нет ссылки на неопубликованный
  файл, сирота удалён; «удалить файл + Отмена» → ссылки тоже нет; sha256 после
  скачивания совпадает; W07: 100 % `attachments` существуют и побайтово равны источнику.
- **Как снизить:** staging → проверка → публикация → привязка; физическая чистка —
  отложенной задачей со sweeper'ом; единое серверное хранилище (без локальных копий);
  `sha256 + size` в записи; при миграции — манифест файлов; резервное копирование
  хранилища вместе с дампом БД (R21).
- **Где закрывается:** W04, W07, W08.
- **Блокирует ввод:** да.

## P1

### RISK-07. Однофамильцы и нечёткое сопоставление ФИО

- **Причина:** `name_matches` матчит по подстроке фамилии и по «похожести ≥ 0.80»
  (`core/controls_models.py:89–116`); справочник людей дедуплицируется ПО ФАМИЛИИ
  (`core/controls_data.py:410–417`)**[Код]**.
- **Последствия:** чужие просрочки у однофамильца; при миграции — привязка не того
  человека; если опираться на ФИО в правах — утечка и путаница владельцев.
- **Как проверить:** синтетический набор с двумя «Кузнецов» (S-03): список, счётчики,
  экспорт, алармы; отчёт миграции «коллизии имён» непустой и разобран вручную.
- **Как снизить:** `person_id` как носитель участия (D-07); при коллизии — обязательное
  ручное подтверждение админа и уточняющее отображение; нечёткое сопоставление — только
  подсказка в отчёте; никогда — в решениях о доступе.
- **Где закрывается:** W02 (схема), W07 (отчёт коллизий), W08 (приёмка).
- **Блокирует ввод:** да, если остались неразрешённые коллизии.

### RISK-08. Обратный переход на legacy после появления новых записей

- **Причина:** после W09 источником правды становится новая система; в `controls.json`
  новые контроли не появляются, а в legacy живут «Удалить все» и merge, способные
  перезаписать общий файл (R23)**[Код]**.
- **Последствия:** откат = потеря новых записей; соблазн «дотянуть» двусторонней
  синхронизацией, которая запрещена AGENTS §6.
- **Как проверить:** репетиция отката в W08: дамп новой БД → тестовая копия legacy →
  полный Excel-экспорт/импорт → фиксация того, что теряется (пункты, вложения, архивные
  причины, времена).
- **Как снизить:** план отката = «вернуться на замороженную legacy в том же состоянии»,
  а не «перенести назад»; в пилотный период legacy не редактируется; ежедневный дамп;
  решение владельца о допустимом окне отката (`04-acceptance-and-cutover.md`);
  автоматического обратного импорта нет.
- **Где закрывается:** W08 (репетиция), W09 (условие старта).
- **Блокирует ввод:** да (нужен письменный план отката).

### RISK-09. Локальные кэши браузера и «удалённые» записи

- **Причина:** в legacy локальный `controls.json` — кэш офлайн-чтения, а удалённый навсегда
  контроль воскресает merge'ом (R09)**[Код]**; в браузере добавляются HTTP-кэш,
  черновик во вкладке и состояние списка.
- **Последствия:** пользователь видит удалённое или чужое; служебный текст остаётся в
  черновике на общем ПК.
- **Как проверить:** заголовки `no-store`/ETag на `GET /controls*`, `/files*`,
  `/exports*`; «удалить → другой пользователь заходит → записи нет»; выход из аккаунта
  очищает черновики; сценарий «два пользователя на одном ПК подряд».
- **Как снизить:** серверные заголовки + ревалидация; обновления через версионированные
  события и polling; черновики — `sessionStorage` с очисткой при выходе (и, по решению,
  с таймом жизни); никакого IndexedDB-«зеркала» базы — это вторая копия правды (D-01).
- **Где закрывается:** W02 (заголовки), W04 (черновики), W06 (обновления).
- **Блокирует ввод:** нет при пройденных проверках.

### RISK-10. Уведомления: реальные ограничения браузера

- **Причина:** legacy даёт «злой» модал-аларм каждые 2 ч (user) / 24 ч (admin), повтор
  звука и balloon из трея (`ui/controls/controls_tab.py:5690–5731`, `ui/sound_alert.py`,
  `ui/tray_icon.py`)**[Код]**; в браузере нет постоянного фонового процесса: скрытая вкладка троттлится,
  звук требует взаимодействия, Notification требует разрешения, закрытый браузер ничего
  не показывает.
- **Последствия:** сотрудники перестают узнавать о сроках «сами»; привычное
  «пришёл, увидел, услышал» исчезает; попытка «догнать» через push/LLM-обход уводит к
  внешней инфраструктуре.
- **Как проверить:** W06 на реальном Win7 и на современном браузере: скрытая вкладка
  15 мин, закрытая вкладка, второй ПК; зафиксировать фактическое число доставленных
  событий и поведение после повторного открытия.
- **Как снизить:** серверные события + состояние прочтения (D-18); при входе —
  «у вас N просроченных» на первом экране; звук только при активной вкладке; если
  напоминание при закрытом браузере обязательно — отдельный канал (почта и т. п.) по
  решению владельца (N-06), вне первой версии.
- **Где закрывается:** W06.
- **Блокирует ввод:** нет, если владелец принял формулировку «при закрытом браузере не
  гарантируется» (это уже заявленное отличие в `02-requirements.md`).

### RISK-11. Объём и производительность

- **Причина:** legacy строит в DOM все отфильтрованные строки (R10), экспорт —
  одномоментный проход по базе **[Код]**; реальных замеров нет; объёмы владельца
  неизвестны (N-03).
- **Последствия:** планового объёма «10 000 записей» может не хватить для вывода;
  узкие места — экспорт, импорт, счётчики, polling; на слабом ПК — медленная прокрутка.
- **Как проверить:** наполнение 10 000 (и 50 000, если N-03 покажет такой объём),
  профилирование списка/поиска/карточки/экспорта на сервере и отзывчивости на клиенте;
  проверка лимита `page_size` и индексов.
- **Как снизить:** серверная пагинация; счётчики одним запросом; экспорт/импорт как job;
  ограничение одновременных тяжёлых задач на пользователя; polling только версии;
  частичные индексы по архиву/срокам.
- **Где закрывается:** W01 (ориентиры), W04/W05 (реальные запросы), W08 (приёмка).
- **Блокирует ввод:** нет при выполнении ориентиров `04-acceptance-and-cutover.md` на
  фактическом объёме.

### RISK-12. Часовые пояса, «сегодня» и переход дат

- **Причина:** статусы считаются по `date.today()` процесса
  (`core/controls_models.py:502–530`), `created_at/updated_at` — naive локальное время,
  merge трактовал его как UTC **[Код]**.
- **Последствия:** «просрочено/сегодня» расходятся у пользователей с разной датой;
  сдвиг календарного срока на день при конвертации дата↔момент.
- **Как проверить:** unit-тесты расчёта статуса с фиксированной «датой организации»;
  сценарий «сервер 23:59 / клиент 00:01»; проверка типов (`date` против `timestamptz`);
  тест на 29.02.
- **Как снизить:** серверное «сегодня» (предложение `Europe/Moscow`, **[Владелец]**),
  моменты в UTC, календарные сроки — тип `date`; в UI — явная дата в заголовке списка;
  предупреждение о расхождении часов клиента (аналог `check_time_skew`) — informational.
- **Где закрывается:** W02 (типы), W03 (расчёт), W06 (отображение).
- **Блокирует ввод:** нет при прохождении тестов.

### RISK-13. Excel-совместимость с эталоном

- **Причина:** экспорт — визуальный двойник «Контроли ОКРИМ.xlsx» (объединённая строка 1,
  шапка во 2-й, автофильтр, стили, скрытый лист, `DD.MM.YYYY`, эвристика высоты строк);
  импорт ищет шапку среди 10 строк и при неполном распознавании читает колонки «по
  порядку» (`core/controls_exporter.py:138–238`, `:455–497`)**[Код]**; экспорт в режиме
  «Архив» даёт пустой файл (R15).
- **Последствия:** «модернизация» формата ломает привычные выгрузки; позиционный fallback
  тихо читает неверные колонки; архив не выгружается вовсе.
- **Как проверить:** W05 — структурная сверка с эталоном; импорт эталона → экспорт →
  импорт (идемпотентность); файл с шапкой в 5-й строке и с переставленными колонками;
  строки без вх. №; экспорт в режиме «Архив».
- **Как снизить:** формат = зафиксированный договор; при неполном распознавании — явная
  ошибка вместо позиционного чтения **[Пред]**; версия формата в служебном листе;
  D-13/D-14 — про архивный экспорт и поля скрытого листа.
- **Где закрывается:** W05.
- **Блокирует ввод:** нет, но пилот не начинают без подтверждения владельца «выгрузки как
  раньше».

### RISK-14. Скан-гард: формальное выполнение вместо реального

- **Причина:** гард проверяет только «расширение + файл физически существует» и только при
  создании (`ui/controls/controls_tab.py:3722–3749`)**[Код]**; лимита размера нет, MIME не
  проверяется, импортные записи создаются без скана (R13).
- **Последствия:** «скан» = переименованный HTML или 0-байтовый PDF; переполнение диска;
  при переносе строгий серверный гард может заблокировать легальные действия админа.
- **Как проверить:** W03/W04: `POST` с `evil.html`, с 0-байтовым PDF, с 500 МБ; PUT без
  вложений; импорт без файлов; сверка «кого блокируем против legacy».
- **Как снизить:** правила на сервере, единые для всех клиентов; белый список MIME по
  содержимому; лимиты размера (значение — **[Владелец]**); политика антивируса — отдельно;
  обязательность скана — только при создании (как legacy); исторические помечаются
  `missing_scan` и попадают в отчёт/фильтр.
- **Где закрывается:** W03/W04.
- **Блокирует ввод:** нет.

### RISK-15. Массовые операции: «Удалить все» и молчаливое слияние дублей

- **Причина:** «Удалить все» чистит записи и `notify_log`, но не трогает папки вложений и
  не делает копию перед операцией; дедуп-слияние происходит молча при старте и перед
  записью в shared (R23, R19)**[Код]**.
- **Последствия:** необратимая потеря + сироты в хранилище; «воскресшие» записи при откате
  (RISK-08); неожиданное изменение id/путей вложений.
- **Как проверить:** W03/W07: user-запрос → 403; admin без точной фразы → 422; запись в
  аудите; дамп перед операцией существует; файлы не удалены до подтверждения; повторный
  запуск миграции даёт `merged == 0`.
- **Как снизить:** pre-backup как часть операции; подтверждение с числом записей; аудит;
  soft-delete/tombstone вместо физического; «архивировать выбранное» как основной вариант
  (D-19); дедуп — только явная админ-функция с предпросмотром.
- **Где закрывается:** W03, W07.
- **Блокирует ввод:** нет при реализованных user-запрете и pre-backup.

### RISK-16. Совместная работа legacy и новой системы в период пилота

- **Причина:** до W09 правки идут в legacy; после — в новой; параллельные правки
  недопустимы, двусторонняя синхронизация запрещена (AGENTS §6).
- **Последствия:** два источника правды, потерянные правки, конфликты Excel-обменов.
- **Как проверить:** в W08 проиграть сутки пилота с частичным охватом и убедиться, что
  правила переключения соблюдены (legacy — read-only для «Контролей»).
- **Как снизить:** пилот по группам, а не по людям; «день переключения» с финальным
  переносом дельты; в legacy остаются только зональные и отделы; Excel-канал — как
  импорт пополнения, не как синхронизация.
- **Где закрывается:** W08 (репетиция), W09 (условие старта).
- **Блокирует ввод:** да.

### RISK-17. Сессии, CSRF и секретные данные

- **Причина:** аутентификации в legacy нет: парольные ворота admin отключены
  (`main.py:49–73`), роль берётся из `edition.json`, где допускаются plain-`password` или
  `base64(sha256(salt|password))` с фиксированной солью
  (`core/edition.py:251–444`, `:541–571`)**[Код]**.
- **Последствия:** подмена роли на клиенте; CSRF; перенос слабых хешей/паролей в новую
  систему; утечка секретов в репозиторий или логи.
- **Как проверить:** W02: 403 без CSRF-токена, лимит неудачных входов, инвалидация сессий
  при блокировке аккаунта, grep-скан на секреты, проверка логов (нет паролей, токенов,
  содержимого файлов); внешняя проверка на W08.
- **Как снизить:** cookie-сессия (HttpOnly/Secure/SameSite), CSRF, штатный хеш паролей
  (алгоритм фиксируется в W01), выдача/сброс админом, перенос паролей из
  `edition.json` ЗАПРЕЩЁН (F-17), debug off, secrets вне Git.
- **Где закрывается:** W02, W08.
- **Блокирует ввод:** да.

### RISK-18. Повтор запроса и идемпотентность

- **Причина:** в legacy повтор события выбора файла давал 13 копий, а
  `_attach_event_is_duplicate` и проверка имени закрывают только этот канал
  (`ui/controls/controls_tab.py:285–322`, `:371–389`)**[Код]**; в браузере двойной клик и
  ретрай после таймаута — норма.
- **Последствия:** дубли контролей, вложений, уведомлений; раздувание дедупа (R19).
- **Как проверить:** один `Idempotency-Key` дважды → одна запись; двойные клики
  «Сохранить», «Импортировать», «Отметить пункты»; `POST /files` повторно.
- **Как снизить:** идемпотентные ключи на всех повторяемых операциях (D-03), уникальный
  индекс `(user_id, idempotency_key)`, блокировка кнопки до ответа, ретрай с тем же
  ключом; при конфликте бизнес-ключа — предупреждение, а не молчаливое дублирование.
- **Где закрывается:** W02 (механизм), W03/W04/W05 (применение).
- **Блокирует ввод:** нет.

### RISK-19. Расхождение плана и кода (правила «улучшатся» незаметно)

- **Причина:** уже найдено: R05 («переключение в разовый очищает `end_date`») против кода,
  сохраняющего `end_date` у разового (D-12); требование «счётчики учитывают те же
  фильтры» против расчёта счётчиков по базе (P-02); «логи не дублируются между
  вкладками» при журналах, локальных на машину (R20)**[Код]**.
- **Последствия:** реализация «по плану» ломает колонку H Excel и историю выгрузок;
  реализация «по коду» выглядит как самовольное отклонение.
- **Как проверить:** каждой спорной формулировке — явная строка решения владельца и
  приёмочный тест.
- **Как снизить:** список `P-01…P-07` (`decisions.md` §7); правки в `02-requirements.md`
  вносит оркестратор после ответов; агент не «исправляет» план молча (AGENTS §6).
- **Где закрывается:** W00 (ответы) → W03 (реализация).
- **Блокирует ввод:** нет; блокирует принятие W00.

### RISK-20. Двойная поддержка и «догоняющая» миграция

- **Причина:** W01–W08 менять legacy нельзя (AGENTS §1), а рабочие правки идут в legacy до
  W09 → объём переноса растёт до последнего дня.
- **Последствия:** миграция, которая всегда отстаёт; искушение «заморозить» работу отдела.
- **Как проверить:** зафиксировать условие заморозки изменений ПРАВИЛ в legacy
  (данные правятся до дня переключения); сравнение контрольных сумм
  `porayonka-app/core/controls_*.py` до и после W01–W08 (diff = 0).
- **Как снизить:** перенос данных в W07 и повтор дельты в W09; Excel-канал как
  экстренное пополнение; план «дня переключения» с окончательным дампом.
- **Где закрывается:** W07, W09.
- **Блокирует ввод:** нет.

### RISK-21. Обновления в процессе работы: устаревший экран и потеря формы

- **Причина:** legacy при открытой карточке показывает ОДИН диалог «Данные изменились», а
  «Обновить» закрывает карточку без сохранения; «Позже» не предлагает повторно
  (`ui/controls/controls_tab.py:5341–5376`, `:5533–5551`)**[Код]**; в браузере вкладка
  может «спать» часами.
- **Последствия:** пользователь сохраняет поверх чужого (или теряет ввод при F5);
  несогласованность счётчиков и списка.
- **Как проверить:** W06: правка в другом окне ≤ 30 с отражается; при открытой форме —
  не затирает; после возврата фокуса — проверка свежести; обрыв сети — индикатор, запрет
  сохранения, форма цела; F5 не требуется.
- **Как снизить:** polling версии + точечное обновление строк; при 409/обновлении —
  сохранение черновика и явное сравнение; статус «данные могут быть неактуальны».
- **Где закрывается:** W04 (черновики), W06 (обновления).
- **Блокирует ввод:** нет.

### RISK-22. Резервное копирование и восстановление: непроверенный откат

- **Причина:** в legacy есть ежедневные снапшоты с манифестом и SHA256
  (`core/backup.py:219–373`), но восстановление — ручная операция
  `restore_local_snapshot` в отдельный каталог; проверка манифеста при восстановлении не
  выполняется; в новой системе добавляется файловое хранилище, которое должно
  соответствовать дампу **[Код/Не проверено]**.
- **Последствия:** дамп без согласованных файлов = битые ссылки; «рабочее» восстановление
  обнаруживается только в аварии.
- **Как проверить:** W07/W08: восстановление на отдельной БД, сверка числа записей,
  файлов и SHA256 манифеста; проверка частичного сбоя копирования (прежний снапшот цел,
  день не помечен успешным); проверка retention.
- **Как снизить:** единый снимок «дамп + хранилище» с манифестом и чек-суммами;
  регламент восстановления с датой последней проверки; ограничение прав на бэкапы.
- **Где закрывается:** W07 (механика), W08 (репетиция).
- **Блокирует ввод:** да — без подтверждённой проверки восстановления.

### RISK-23. Разрешения и каталог на сервере: кириллица, коллизии имён, антивирус

- **Причина:** legacy опирается на `имя_1.ext` при коллизии
  (`core/controls_data.py:1043–1053`) и на повторные ретраи публикации из-за блокировки
  файла антивирусом (`_win_sharing_error`, `:863–905`)**[Код]**.
- **Последствия:** на Linux-сервере иные правила имён/нормализации (NFC/NFD), возможны
  коллизии «разных» кириллических имён; блокировка файла антивирусом даёт таймауты.
- **Как проверить:** W04: загрузка файлов с кириллицей, пробелами, точками в имени,
  длинным именем, одинаковым именем и разным содержимым; проверка нормализации;
  загрузка под блокировкой файла.
- **Как снизить:** имя объекта в хранилище генерируется сервером (`storage_key`),
  оригинальное имя хранится отдельно; unicode-нормализация (NFC) единая; `sha256` как
  признак дубля; ограничение длины/символов; таймауты и ретраи публикации.
- **Где закрывается:** W04.
- **Блокирует ввод:** нет.

### RISK-24. Привычки пользователей: «как в Flet, только в браузере»

- **Причина:** 40 раундов доработок сформировали специфичные ожидания (полоса статуса,
  «Без скана», сокращённые ФИО, желтая подсветка только «просрочено/сегодня», жёлтая пилюля
  вложения, сохранённые ширины колонок) **[Код]**; часть из них — обходные решения
  файловой синхронизации, часть — реальные требования.
- **Последствия:** «стало хуже» без объективных причин; волна правок после W09; риск, что
  полезное отличие (пагинация, отсутствие «всего списка») будет отвергнуто.
- **Как проверить:** в W04/W08 — чек-лист соответствия привычным элементам (список в
  `ui-outline.md` §7) и ручная проверка владельцем на реальных данных в тестовой базе.
- **Как снизить:** переносить поведение 1-в-1 по умолчанию; отклонения — только списком
  «намеренные отличия» с решением владельца; не делать «несколько редизайнов
  параллельно» (06-промпт, D-раздел).
- **Где закрывается:** W04 (макет), W08 (приёмка владельцем).
- **Блокирует ввод:** нет.

## Риски процесса и передачи

### RISK-25. Потеря coding-сессии Arena между этапами

- **Причина:** правила требуют не закрывать сессию после этапа (`migration-web/AGENTS.md` §3),
  но автоматический таймаут платформы агент предотвратить не может; `07-agent-selection.md`
  прямо отделяет качество работы от доступности сессии.
- **Последствия:** потеря контекста продолжения, риск «начать заново с худшим результатом».
- **Как проверить:** наличие `reports/SESSION-HANDOFF.md` (он и есть переносимый контекст);
  статус сессии в интерфейсе Arena проверяет оркестратор/владелец, не агент.
- **Как снизить:** handoff-файл обновляется каждый этап; решения и блокеры — только в
  репозитории; при закрытии сессии платформой — продолжение в новой сессии с чтением
  пакета, а не повторный конкурс.
- **Где закрывается:** сопровождение всех этапов.
- **Блокирует ввод:** нет (эксплуатационный риск продолжения).

### RISK-26. Утечка реальных данных в документы/репозиторий

- **Причина:** в коде и в рабочих файлах есть реальные ФИО, сетевой UNC с именем
  сотрудника, номера входящих документов; W00 требует синтетические примеры и не
  размножать реальные имена **[Код/правила]**.
- **Последствия:** публикация служебной информации в GitHub/Arena.
- **Как проверить:** перед коммитом — `git diff`, поиск по характерным признакам (ФИО из
  `DEFAULT_CONTROLLERS`, `DEFAULT_NETWORK_PATH`), `git diff --check`;
  просмотр имён файлов и метаданных.
- **Как снизить:** в документации — синтетические ФИО; конкретные значения UNC/IP не
  воспроизводить; реальные JSON/сканы не загружать и не запрашивать; обезличивание
  распространять на имена файлов.
- **Где закрывается:** каждый этап; проверка — перед внедрением.
- **Блокирует ввод:** да, если найдена утечка — до удаления из истории.

### RISK-27. Незакреплённые версии и «установим на всякий случай»

- **Причина:** стек предложен, но версии/инструменты не закреплены
  (`01-architecture.md`: W01 закрепляет версии с доказательством совместимости);
  в legacy закрепление версий было следствием аварий на Win7 **[Код]**.
- **Последствия:** «работает у разработчика, не работает на Win7»; разрастание
  зависимостей; невозможность воспроизвести сборку.
- **Как проверить:** W01 — чистая установка из lock-файлов, production build, запуск
  собранного интерфейса (не dev-сервера), сборка под целевой браузер.
- **Как снизить:** фиксировать минимум зависимостей; никакого CDN и внешних шрифтов;
  список версий и обоснование — в `controls-web/README`; запрет на «на всякий случай».
- **Где закрывается:** W01.
- **Блокирует ввод:** нет, но блокирует принятие W01.
