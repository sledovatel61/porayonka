# Реестр рисков переноса вкладки «Контроли» (W00)

Формат: **причина → чем опасен → чем подтверждён → как снизить → чем закрывается → блокирует →
статус**. Закрыть риск может только рецензент после проверки этапа (в W00 все — `открыт`, если не
указано иное). Ссылки — на код базового SHA `b5f24ab58c642fafb5cca616aa8b4e16d3a3de3f`.

Пометки: `[код]` — чтение кода; `[выполнено]` — локальный прогон чистой функции на синтетике;
`[документировано]` — `docs/network_audit_report.md`; `[не проверено]` — проверить нечем
(нет доступа к среде/данным).

---

## R-01. Потеря правок при слиянии и сохранении (LWW вместо версионирования)

- **Причина:** `merge_controls` = union по `id` + LWW по `updated_at` на всём объекте; сохранение —
  перезапись всего JSON (`porayonka-app/core/controls_data.py:1149–1199, 1250–1302`) `[код]`.
- **Опасность:** параллельная правка другого админа исчезает целиком (поля не сливаются); потеря
  видна не сразу, а через цикл поллинга.
- **Подтверждение:** `[документировано]` «Подтверждено корректным» п. 1 (это заявленное поведение),
  `[код]` — `expected_revision`/версий нет нигде.
- **Снизить:** `expected_revision`/`If-Match` на всех изменяющих эндпоинтах + `409`; запись —
  транзакция «всё или ничего»; черновик формы не теряется; запрет на «сохранить весь список».
- **Закрывается:** W02 (контракт) + W03 (операции и тесты «два админа, один контроль»).
- **Блокирует:** перенос любых записей. **Статус:** `открыт`.

## R-02. «Воскрешение» удалённых записей; необратимость «Удалить все»

- **Причина:** tombstone нет; `delete_all_attachments` удаляет файлы сразу
  (`core/controls_data.py:1106–1125, 1170–1180`; `ui/controls/controls_tab.py:4431–4460,
  5067–5141`) `[код]`.
- **Опасность:** (а) «удалено навсегда» возвращается у офлайн-клиента; (б) «Удалить все» + чужой
  офлайн-кэш = восстановление всех записей поверх пустого файла; (в) файлы уже удалены, запись
  вернулась → «Файл вложения не найден»; (г) «Удалить все» не чистит каталоги вложений → сироты.
- **Подтверждение:** `[документировано]` «Известные ограничения» п. 1, 5.
- **Снизить:** одна БД (второго хранилища нет → воскрешение невозможно); жёсткое удаление —
  admin, с причиной, подтверждением номером и аудитом; отложенная чистка файлов + реестр
  «файл-принадлежит»; массовое удаление записей по фильтру заменяется массовым архивированием
  `[предложение]`.
- **Закрывается:** W02 + W03 (политика) + W07 (сверка количеств «до/после»).
- **Блокирует:** перенос массовых операций. **Статус:** `открыт`.

## R-03. Расхождение «общий срок / персональный срок»

- **Причина:** два параллельных расчёта: общий (`effective_due_date`/`deadline_status`) и
  персональный (`user_effective_due_date`/`user_deadline_status`), выбор — по роли в UI
  (`core/controls_models.py:441–590`; `ui/controls/controls_tab.py:953–964, 1483–1490`) `[код]`;
  персональный расчёт игнорирует `milestones`, общий — учитывает `[выполнено]`.
- **Опасность:** «Просрочено» у одного и «В работе» у другого в том же контроле; расхождение
  списка, счётчиков, алармов и экспорта; в web это воспроизведут в четырёх местах кода.
- **Подтверждение:** `[выполнено]` (матрица в `requirements-matrix.md` §3 S01–S06).
- **Снизить:** один серверный модуль расчёта + golden-тесты; статус и срок приходят в ответе API;
  UI ничего не пересчитывает; отдельные решения владельца — про milestones и роль «контролёр».
- **Закрывается:** W03 + W04 (отображение) + W05 (экспорт) + W06 (уведомления) + W07 (сверка).
- **Блокирует:** W03–W06. **Статус:** `открыт`.

## R-04. Ложные слияния дубликатов и потеря «богатых» полей

- **Причина:** `business_key` = (нормализованный вх. №, дата поступления, канон инициатора,
  SHA1(содержание)); при совпадении `merge_duplicate_group` объединяет и **удаляет** неканонические
  записи; на read-пути — «сухая» дедупликация (`core/controls_dedup.py:48–101, 170–263, 349–458`;
  `ui/controls/controls_tab.py:742–751, 781–793, 834–866`) `[код]`.
- **Опасность:** два разных контроля с одинаковым номером и содержанием (например, «повторное
  поручение по тому же распоряжению») сливаются безвозвратно; при `move_files` переезжают файлы.
- **Подтверждение:** `[код]`; консерватизм (пустой номер → не сливать) реализован `[код]`.
- **Снизить:** при миграции — **никаких** автоматических слияний: план + подтверждение admin +
  soft-merge (`merged_into`) с возможностью отката; в рантайме — только предупреждение о дубле.
- **Закрывается:** W07 (миграция) + W03 (предупреждение вместо слияния).
- **Блокирует:** W07. **Статус:** `открыт`.

## R-05. Потеря исторических времён и «версий» при переносе

- **Причина:** Excel round-trip не содержит `created_at/updated_at/archived_at`
  (`core/controls_exporter.py:262–273`); при импорте из скрытого листа они = время импорта
  `[выполнено]`; в JSON они naive-локальные и разные на разных ПК `[код]`.
- **Опасность:** после переноса нельзя отличить «не менялось» от «пересоздано»; нет основы для
  аудита и для «кто изменил».
- **Снизить:** перенос в `legacy_created_at/legacy_updated_at/legacy_archived_at` как текст +
  best-effort timestamptz с флагом `tz_assumed`; `revision=1` для мигрированных; отчёт сверки.
- **Закрывается:** W07 + W03 (аудит). **Статус:** `открыт`.

## R-06. Разрушительное применение импорта Excel

- **Причина:** план считается на deepcopy и применяется «вслепую», без проверки свежести и срока
  годности; применение в цикле с `try/except` на строку → частичное применение
  (`ui/controls/controls_tab.py:4513–4611`; `core/controls_exporter.py:611–716, 529–609`) `[код]`.
- **Опасность:** перезапись правок, появившихся после предпросмотра; половина изменений
  применилась, половина нет; конфликтные строки молча пропущены.
- **Снизить:** серверная импорт-задача: план с TTL, `expected_revision` на каждую запись,
  «всё или ничего», обязательный pre-apply backup, повторная валидация конфликтов при apply.
- **Закрывается:** W05 (S10) + W08 (репетиция отката). **Статус:** `открыт`.

## R-07. Дубликаты операций: двойная отправка, повторные события, отсутствие идемпотентности

- **Причина:** в legacy лечится «подписью» события FilePicker в окне 3 с и проверкой имени файла
  (`ui/controls/controls_tab.py:285–311, 361–391`); серверной идемпотентности нет `[код]`.
- **Опасность:** двойной клик → два контроля/два вложения; «отправить ещё раз» после 500 →
  дубликаты; при повторном событии загрузки — `имя_1.pdf`.
- **Снизить:** `Idempotency-Key` на всех «небезопасных» POST; сравнение содержимого (SHA256) вместо
  имени; блокировка кнопки до ответа; тесты «двойной клик», «F5 при отправке», «ретрай после 500».
- **Закрывается:** W03 (контракт) + W04/W05 (тесты S14–S16). **Статус:** `открыт`.

## R-08. Вложения: ссылка есть — файла нет

- **Причина:** двойное хранилище (shared → локально), относительный путь `<control_id>/<имя>`,
  фолбэк «по самому rel» при несовпадении id; tmp-сборщик старше 600 с
  (`core/controls_data.py:881–1027, 1066–1133`; `ui/controls/controls_tab.py:3508–3617`) `[код]`.
- **Опасность:** «Файл вложения не найден» у живых записей; «полуфайл» при обрыве (в legacy
  закрыто атомарной записью); после миграции — расхождение реестра и диска.
- **Подтверждение:** `[документировано]` БАГ 3, 5c сценарий стресс-аудита.
- **Снизить:** сущность вложения со статусом `uploading|ready|missing`, FK на физический объект,
  проверка существования при отдаче, инвентаризация при миграции (`found/missing/renamed`),
  сборщик сирот с TTL.
- **Закрывается:** W04 + W07. **Блокирует:** перенос файлов. **Статус:** `открыт`.

## R-09. MIME и безопасность содержимого

- **Причина:** `ATTACHMENT_ALLOWED_EXT` объявлен, но не применяется (`core/controls_data.py:46–47`)
  `[код]`; единственная проверка — `endswith` в скан-гарде (`ui/controls/controls_tab.py:3726–3740`)
  и фильтр диалога выбора; лимита размера нет, только предупреждение > 20 МБ (`:3652`) `[код]`.
- **Опасность:** в браузере «открыть» = `text/html`, `image/svg+xml` (XSS), скрипты; отказ
  доступности из-за сверхбольших файлов; нет проверки на «это вообще PDF?».
- **Снизить:** серверная проверка по магическим байтам, белый список, лимит,
  `Content-Disposition: attachment`, `Content-Security-Policy` на раздаче, отдача без cookie;
  антивирус — отдельное решение (в объёме W00 отсутствует) `[решение владельца]`.
- **Закрывается:** W04 + тесты `decisions.md` §4.4. **Статус:** `открыт`.

## R-10. Доступ по прямой ссылке к чужим данным

- **Причина:** «свои» — клиентский фильтр `_mine`/`_visible_base`
  (`ui/controls/controls_tab.py:914–951`); роль и ФИО — локальные настройки
  (`core/controls_data.py:231–275`; `ui/controls/controls_settings_modal.py:23–287`); роль `user`
  с пустым ФИО = весь список `[код]`; вход без пароля (`porayonka-app/main.py:49–75`) `[код]`.
- **Опасность:** в web прямой URL (`/controls/<id>`, файл, экспорт) отдаёт чужие данные; «роль»
  правится пользователем; история/закладки/чат делают утечку постоянной.
- **Снизить:** сессия + серверная проверка на **каждом** эндпоинте и объекте; список/счётчики/
  экспорт/алармы — из одного запроса с одним предикатом; никаких «приватных» постоянных ссылок;
  тесты curl/новая вкладка/другой пользователь.
- **Закрывается:** W01 (стенд) + W02 (контракт) + W04/W05/W06 (реализация).
- **Блокирует:** начало W01. **Статус:** `открыт`.

## R-11. Desktop-механика файлов, перенесённая в браузер

- **Причина:** «Скачать» в legacy делает копию в выбранную пользователем папку и потом «Открыть
  сохранённую копию» (`ui/controls/controls_tab.py:3324–3456`); в web-режиме legacy файл
  копируется в `FLET_ASSETS_DIR/downloads` и открывается URL `/assets/downloads/<имя>`
  (`:3295–3308, 3360–3384`; `porayonka-app/main.py:518–546`) `[код]`.
- **Опасность:** (а) если web-сервер раздаёт каталог `assets` без проверки доступа, файл скана
  доступен по предсказуемому имени любому в сети — требует проверки на фактическом поведении
  Flet 0.23.2 `[не проверено]`; (б) перенос формулировок «открыть/скачать на диск» в браузер —
  обман пользователя; (в) «сохранённая копия» живёт на сервере, а не у пользователя.
- **Снизить:** скачивание только через авторизованный endpoint с `Content-Disposition`; запрет
  статики для сканов; никакой «истории сохранённых копий» на сервере; текст UI — «файл будет
  загружен браузером»; временные токены (если нужны) — одноразовые, с TTL.
- **Закрывается:** W04 + отдельная проверка «прямая ссылка на файл» (есть в W04 и W05).
- **Блокирует:** W04. **Статус:** `открыт`.

## R-12. Роли как «настройка», а не аутентификация

- **Причина:** разделение admin/user — «редакция» (`core/edition.py:251–447, 495–541`) +
  настройки вкладки; парольные ворота отключены (`main.py:49–75`) `[код]`.
- **Опасность:** «повышение» правкой файла; отсутствие входа = отсутствие личности в аудите;
  перенос этой модели в web делает сервер беззащитным.
- **Снизить:** локальные учётки + вход/выход/отзыв сессий на сервере; `user` физически не может
  ни менять, ни «видеть всё»; аудит по `account_id`.
- **Закрывается:** W02. **Блокирует:** W01. **Статус:** `открыт`.

## R-13. Часы клиентов, задержки сети, отсутствие идемпотентности

- **Причина:** «сегодня» = локальная дата (`core/controls_models.py:502–530`); `updated_at` — часы
  машины, naive; расхождение проверяется только предупреждением (`core/controls_data.py:1338–1390`)
  `[код]`. Опрос — mtime с гранулярностью ФС и задержкой SMB 0.5–2 с
  (`docs/network_audit_report.md`, «Известные ограничения» 2, 3).
- **Опасность:** «просрочено/сегодня» расходятся между клиентами; будущее `updated_at` выигрывает
  конфликты; при задержке — перезапись поверх; при медленной загрузке — двойные операции.
- **Снизить:** серверные `now()` и `revision`; `Idempotency-Key`; backoff/jitter polling;
  предупреждение о «дате из будущего» при вводе; «сервер недоступен» ≠ «нет данных».
- **Закрывается:** W03 + W06 (тесты: сдвиг часов клиента, задержка, повторный submit).
- **Статус:** `открыт`.

## R-14. «Тихие» отказы и расхождение список/счётчики/экспорт

- **Причина:** экспорт получает `_visible_base()` — без поиска, фильтров и сортировки — и снова
  фильтрует `not archived` (`ui/controls/controls_tab.py:4457–4470`;
  `core/controls_exporter.py:182`) `[код]`; счётчики — по тому же `_visible_base()`
  (`controls_tab.py:1483–1490`) `[код]`; раньше пустая «Дата поступления» давала тихий отказ
  сохранения — сейчас там автоподстановка с тостом (`:3750–3761`) `[код]`.
- **Опасность:** пользователь не понимает, «что именно экспортировалось», и правит данные вручную;
  в web это станет жалобой «потеряли данные при экспорте».
- **Снизить:** единый серверный запрос-источник для списка/счётчиков/экспорта; экспорт архива —
  отдельная операция; пустой результат с объяснением; тест «экспорт == список».
- **Закрывается:** W04 + W05. **Статус:** `открыт`.

## R-15. Ограничения Win7 и возможностей браузера

- **Причина:** legacy web-режим рассчитан на «старый браузер Win7» (`main_web.py:1–27`), а
  уведомления опираются на `winsound`/MCI/tray (`ui/sound_alert.py:1–60`,
  `ui/controls/controls_tab.py:5328–5340, 5720–5730`) `[код]`.
- **Опасность:** перенос функций, которых там нет: фоновый аларм при закрытом браузере,
  «открыть в программе», balloon, `showDirectoryPicker`, стабильный polling в фоновой вкладке
  (throttling), кириллица/длинные имена в `download`, отсутствие Web Notifications.
- **Снизить:** зафиксировать минимальный профиль браузера и фолбэки (W04/W06); polling с проверкой
  при фокусе и видимой «свежестью»; уведомления — «в окне», с явным «если вкладка закрыта — не
  придёт»; скачивание вместо «открыть»; тесты на реальной Win7-машине — задача владельца
  `[решение владельца]`.
- **Закрывается:** W01 (срез) + W04/W06. **Статус:** `открыт`.

## R-16. Неизвестные стек, сервер и размещение

- **Причина:** `migration-web/01-architecture.md` фиксирует: версии стека, сервер, браузер —
  неизвестны; `migration-web/05-status.md` — решения не приняты `[план]`.
- **Опасность:** W01/W02 могут выбрать стек, который нельзя установить (оффлайн-контур,
  лицензии, политика ИБ), и всю работу придётся переделывать.
- **Снизить:** контракт API/схема описываются независимо от фреймворка (сделано здесь); стек —
  только после ответа владельца; установка зависимостей в W00 не выполнялась.
- **Закрывается:** W01 (после решений). **Блокирует:** старт W01. **Статус:** `открыт`.

## R-17. Совместимость Excel и версии `openpyxl`

- **Причина:** экспорт жёстко привязан к эталону (10 колонок, merged A1:J1, автофильтр, формат
  дат, ширины) (`core/controls_exporter.py:26–46, 147–176, 224–256`) `[код]`; импорт ищет шапку в
  первых 10 строках, читает **только `wb.active`**, при неудачном сопоставлении — «по порядку»
  (`:436–483`) `[код]`; скрытый лист индексируется по вх. номеру → коллизия теряет строку
  (`:641–651, 718–734`) `[код]`; версия `openpyxl` закреплена (`requirements.txt`) `[код]`.
- **Опасность:** «пользовательский» файл с другим порядком колонок читается неверно; лист
  «оконченое» не импортируется никогда; смена версии openpyxl меняет форматирование/поведение
  скрытых листов.
- **Снизить:** серверный импорт с явным разбором заголовков (без «по порядку» без подтверждения),
  предпросмотр плана, golden-файлы, фиксация версии библиотеки, отдельный режим «архив».
- **Закрывается:** W05 (S07–S09). **Статус:** `открыт`.

## R-18. Гонки при записи файлов и «advisory»-блокировки

- **Причина:** атомарная публикация через tmp + `os.replace`, ретраи на Windows sharing, сборщик
  tmp старше 600 с (`core/controls_data.py:881–960`); блокировка редактирования — lock-файл,
  stale 10 мин, при недоступной сети «не мешаем» и при ошибке создания — «не мешаем»
  (`core/control_locks.py:111–186`) `[код]`.
- **Опасность:** lock не защищает данные (не проверяется при сохранении); при недоступной сети
  два админа пишут одновременно; в web число конкурентов выше.
- **Снизить:** «кто редактирует» — только UX-подсказка; защита — `revision`+409; файловое
  хранилище — immutable-объекты (write once), дедупликация по хешу.
- **Закрывается:** W03 + W04. **Статус:** `открыт`.

## R-19. Уведомления: потерянные, лишние и «недоставленные»

- **Причина:** журнал уведомлений — в настройках конкретного ПК (`notify_log`, `alarm_log`)
  (`core/controls_data.py:297–334`; `ui/controls/controls_tab.py:5553–5595, 5690–5760`) `[код]`;
  интервалы 2 ч/24 ч (`core/controls_notify.py:20–25`) `[выполнено]`; доставка — тост/звук трея
  только при живом процессе.
- **Опасность:** пользователь открыл приложение с другого ПК → все «новые» придут заново (или не
  придут никогда); аларм по контролю, которого нет в списке (S04); гарантия доставки
  недостижима при закрытом браузере.
- **Снизить:** серверный журнал уведомлений (один на человека), единое правило «участник»
  (B1 в `decisions.md`), честная формулировка «уведомления показываются при открытой вкладке»,
  счётчик непрочитанных при следующем входе.
- **Закрывается:** W06. **Статус:** `открыт`.

## R-20. Скрытые (мёртвые) компоненты legacy как источник ложного поведения

- **Причина:** альтернативная карточка `ui/controls/control_card_modal.py` и
  `ui/controls/name_picker.py` не импортируются рантаймом (только проверка компиляции в
  `tests/test_controls_smoke.py:520`) `[код]`; их поведение отличается от активного
  (`end_date`, `is_done/done_date/comment` пунктов, `sync_due_after_tasks`, тихий возврат, отсутствие
  скан-гарда и lock — см. `requirements-matrix.md` §2).
- **Опасность:** перенести «как в modal-карточке» = вернуть три регрессии, которые уже чинились.
- **Снизить:** фиксация «источник истины — `_open_detail`/`_save_detail`» (сделано в
  `requirements-matrix.md` §2); отдельная задача на удаление мёртвого кода в legacy-ветке.
- **Закрывается:** W02 (контракт зафиксирован по активной карточке). **Статус:** `закрыт` (для
  W00 — зафиксирован вывод; закрытие этапа — за рецензентом).
