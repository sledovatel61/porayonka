### Честные границы обещаний (не «дособирать» в коде)

- **Локальный доступ к скачанному файлу не гарантируется.** Веб-приложение не знает каталог
  загрузки браузера, не проверяет наличие файла на диске и не синхронизирует его.
  Корректное обещание: файл есть на сервере, ссылка действует, пока есть доступ (и TTL — для
  временных URL). В legacy «Открыть сохранённую копию» работает лишь пока открыта карточка
  **[Код]** (`detail_state["saved_copies"]`).
- **Звук и уведомления при закрытом браузере не гарантируются.** Скрытая вкладка троттлится,
  Notification требует разрешения, фонового процесса нет. Привычный legacy-механизм
  «модал-аларм + звук + balloon из трея» живёт только при открытом приложении
  **[Код]** (`_check_deadline_alarms`, `ui/tray_icon.py`). Если напоминание при закрытом
  браузере обязательно — нужен отдельный канал (почта/серверный обход), это вне текущей
  архитектуры и требует решения **[Владелец]** (N-06).
- **Нечёткое сопоставление ФИО — не авторизация и не основание для прав** (D-07); в миграции
  оно допускается только как подсказка в отчёте.
- **W00 не объявляется принятым**: независимо от полноты документов принятие невозможно без
  N-01/N-02/N-06/N-08 (см. §6).

## 4. Операции API (верхний уровень; детали — W02)

Общие правила **[Пред]**: все изменяющие запросы — с `Idempotency-Key`; изменющие ответы
содержат новый `revision`; конфликт `revision` → 409 с телом `{current, draft}`; права
проверяются на каждом роуте; ошибки — единый формат `{code, field?, message}`;
пагинация `limit/offset`, `limit ≤ 200`; сортировка `sort=<key>,dir` + tie-breaker `id`.

## 5. Чем предложенная схема закрывает конкретные legacy-проблемы

| Проблема legacy | Механизм новой системы |
|---|---|
| union-merge двух копий, «воскрешение» удалённого (`controls_data.py:1170–1199`) | одна БД; удаление действительно удаление (D-01) |
| побеждает тот, у кого часы впереди (network audit §4.3) | `revision` + 409 + серверное время (D-02/D-05) |
| пользователь читает все данные, фильтр в UI (R12) | серверная политика на запрос и объект (D-04) |
| публичная раздача скачанных копий `/assets/downloads/…` (`controls_tab.py:3295–3320`) | только авторизованный `GET /files/{id}` (S-13) |
| потерянные ссылки после «удалить файл + Отмена» (`:3487–3506`) | отвязка в той же транзакции (§4) |
| нестабильные id промежуточных точек (`:3784`) | стабильный `id` + `ordinal` (R04) |
| молчаливая потеря нераспознанного текста при импорте (`controls_models.py:301–304`) | парсер сохраняет остаток + отчёт (R18/S-16) |
| скрытый лист теряет `created_at/updated_at/archived_at` (`controls_exporter.py:240–277`) | D-14 |
| дубли под разными UUID (раунд 38 лечил последствия) | бизнес-ключ + план слияния + отчёт (R19); UNIQUE не вводится (D-17) |
| уведомления дублируются на каждой машине | серверные `notification_state` (D-18) |
| `alarm_enabled` читается, но нигде не пишется | настройка в UI либо удаление (R24) |

Короткие вопросы владельцу (по одному, простым языком; не «полотном»):

1. Есть ли компьютер, который можно назначить сервером; кто его включает и обновляет; можно
   ли на него поставить базу данных и сертификат?
2. Откройте на самом старом рабочем ПК «О браузере» и скажите название и версию; можно ли
   установить другой браузер, если потребуется?
3. Сколько сотрудников одновременно работают с контролями и сколько всего контролей и файлов
   (хотя бы порядок: сотни / тысячи / десятки тысяч)?
4. Если сеть пропала — достаточно ли показывать уже открытые данные и запрещать сохранение до
   восстановления?
5. Нужно ли напоминание о сроке, когда браузер закрыт? Если да — согласуем отдельный канал
   (например, почту), обычный браузер это не гарантирует.
6. Кто создаёт учётные записи и сбрасывает пароли? Нужен ли пароль вообще в первой версии?
7. Сотрудник, указанный в контроле, видит все пункты и всех исполнителей этого контроля или
   только свои? (Сейчас — весь контроль.)
8. Кто ведёт список людей, если зональные криминалисты остаются в старой программе?
9. Сохранять ли автоархивацию при «Контроль исполнен» и нужна ли кнопка «вернуть в работу»?
10. Нужен ли журнал действий (кто и что менял) и сколько месяцев его хранить?

Пока N-01, N-02 и N-06/N-08 не закрыты, **W01 начинать нельзя**: негде и нечем строить
платформенный стенд. Независимая часть обследования (эти семь документов, mapping, сценарии,
риски) выполнена и от ответов не зависит.

## 8. Что НЕ является решением и не должно делаться до утверждения

- выбор серверной ОС, версий Python/Node, Docker-развёртывания, конкретного браузера Win7;
- фиксация размера страницы («20» / «100») — только после замера W01;
- «улучшения» правил сроков, периода (30 ≠ месяц), архива, скан-гарда, видимости пунктов;
- локальное кэширование данных «для офлайна», service worker, push;
- двусторонняя синхронизация legacy ↔ новая система (запрещена AGENTS §6);
- перенос зональной вкладки/отделов, «Кто вы?», `edition.json`, UNC-настроек;
- реализация по `ui/controls/control_card_modal.py` (мёртвая альтернативная карточка).
