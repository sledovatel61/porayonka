## 1. Стек и платформенные ограничения

### 1.1 Стек — подтвердить базовое предложение, альтернатива не нужна

**[ПРИНЯТО]** Базовое предложение `01-architecture.md:7` — **Python/FastAPI + React/TypeScript + PostgreSQL**,
HTTPS на одном адресе, сервер отдаёт собранный интерфейс с того же origin, статика/шрифты/иконки локальные,
без CDN и телеметрии, без dev-сервера в production. Обследование не выявило блокера, требующего альтернативного
стека: доменная логика legacy (`controls_models.py`, `controls_dedup.py`, `controls_exporter.py`,
`controls_notify.py`) — чистые функции без Flet/SMB-зависимостей и переносится на Python практически дословно
(подтверждено зондами: правила сроков, статусов, дедупликации, round-trip Excel воспроизводимы вне UI).

**[П]** Дополнения, которые должен закрепить W01 (это не новый стек, а условия применимости утверждённого):

1. **Браузерный минимум зафиксировать числом, а не словами «Win7-браузер».** Проверенные факты о потолке
   браузеров на Windows 7 (внешние источники, см. `reports/W00.md` §5):
   - Chrome и Edge **109** — последние версии для Windows 7/8/8.1 (Chrome 110 требует Windows 10+);
   - Firefox **115 ESR** — последний для Windows 7, обновления безопасности продлены до марта 2027.
   Следовательно целевой минимум: **Chrome/Edge ≥ 109 и Firefox ≥ 115**, и сборка должна проверяться именно на них.
   Если фактический браузер на рабочих Win7-машинах старше — это блокер (см. §5, вопрос В-04).
2. **Сборка фронтенда — с явным `build.target`.** В текущем Vite 7 по умолчанию target `baseline-widely-available`,
   который в релизных заметках Vite 7.0 соответствует Chrome/Edge 107, Firefox 104, Safari 16.0, а в действующей
   документации Vite — уже Chrome/Edge 111, Firefox 114, Safari 16.4. **Значение зависит от версии**, поэтому W01
   обязан не полагаться на дефолт, а задать явно (например `build.target: ['chrome109', 'firefox115']`) и проверить
   фактическую сборку на Win7. Проверка дефолта «по памяти» недопустима.
3. **Tailwind CSS v4 для Win7 не пригоден.** v4 опирается на `@property`, `color-mix()`, cascade layers и
   ориентируется на Chrome 111+/Safari 16.4+/Firefox 128+ — выше потолка Win7-браузеров. Варианты:
   (а) Tailwind **v3.4** (поддерживает старые браузеры), (б) рукописный CSS без новых функций, (в) любая другая
   утилита с компиляцией в CSS, совместимый с Chrome 109. Решение — в W01, но **не v4 по умолчанию**.
4. **Прототип в `src/` не является основой новой системы [К].** `package.json`: React 19.2.3, Vite 7.2.4,
   TypeScript 5.9.3, Tailwind 4.1.17, `vite-plugin-singlefile`; `vite.config.ts` не задаёт `build.target`;
   `tsconfig.json` — `target: ES2020`. Содержимое `src/App.tsx` (733 строки) — прототип вкладки
   **«Следственные отделы»** с жёстко зашитым списком подразделений: слово «контрол» в нём не встречается ни разу
   (проверено `grep -c`). То есть для «Контролей» в прототипе нет ни макета, ни логики, а его стек (Tailwind v4 +
   Vite 7 default + single-file сборка) противоречит пунктам 2–3. Использовать можно только организационные
   решения (TypeScript, Vite), версии закрепить заново.
5. **`vite-plugin-singlefile` не нужен.** Сервер отдаёт статику с того же origin; один HTML-файл лишает кэширования
   и усложняет обновления (требование W06).
6. **Список browser-API и CSS-функций, которые нельзя использовать** (пересечение возможностей Chrome 109 и
   Firefox 115). Не использовать: `color-mix()`, CSS nesting в поставляемом CSS, `@scope`, Popover API,
   `text-wrap: balance|pretty`, `Object.groupBy`, `Promise.withResolvers`, `Array.prototype.toSorted/toReversed/with`,
   `URL.canParse`, `Intl.DurationFormat`, CSS `subgrid`. Разрешено и проверено по версиям: `fetch`,
   `AbortSignal.timeout`, `crypto.randomUUID`, `structuredClone`, `dialog.showModal()`, `:has()`, `@container`,
   `findLast/findLastIndex`, `Array.prototype.at`. Список — **[П]**, W01 подтверждает его на реальном браузере.
7. **Без внешних шрифтов.** Segoe UI / системный стек; кириллица обязательна. Никаких CDN.

### 1.4 Правила, установленные по результатам стенда W01

1. **Не-ASCII значения в HTTP-заголовках — только percent-encoded (RFC 5987).** Прямая кириллица в
   `Content-Disposition` приводит к 500 (starlette кодирует заголовки в latin-1). Найдено smoke-проверкой,
   закрыто тестом. Обязательно для W02+ (скачивание вложений, экспорт Excel, имена файлов).
2. **Тип файла определять по содержимому, а не по `Content-Type` клиента.** Стенд отклоняет файл с
   заявленным `application/pdf` без сигнатуры `%PDF` (415). Для W04 это означает снаффинг типов вложений.
3. **Идентичность вложения — пара `(control_id, rel_path)`**; тот же путь с другим содержимым → 409,
   повторная загрузка идентичного файла идемпотентна (`created: false`). Совпадает с правилом legacy.
4. **Сортировка списка обязана совпадать с индексом** (`receive_date DESC NULLS LAST, incoming_number
   DESC NULLS LAST, id DESC`), иначе серверная пагинация нестабильна.
5. **Список никогда не отдаётся целиком**: `page_size` по умолчанию 50, жёсткий максимум 200, запрос
   `page_size=10000` отклоняется (422).

## 2. Решения по поведению системы

### 2.1 Единая база и единая политика выборки

**[ПРИНЯТО]** Одна БД (PostgreSQL), один сервер, один контракт выборки для списка, счётчиков, экспорта и
уведомлений. **[К]** В legacy политика выборки продублирована в четырёх местах с расхождениями:
`_mine` (`controls_tab.py:914`) — для списка, `control_belongs_to` (`controls_notify.py:30`) — для алармов,
`_visible_base` (937) — для счётчиков, `export(..., user_name)` (`controls_exporter.py:127`) — для Excel.
Расхождение D-03 (контролёр не виден в списке, но получает аларм) — прямое следствие дублирования.

**[П]** Ввести один серверный предикат `visible_to(account)` и применять его во всех перечисленных контурах;
различия между контурами выражать параметрами, а не отдельными реализациями.

### 2.2 Идентичность и доступ

**[ПРИНЯТО]** Вход по аккаунту, серверные cookie-сессии, CSRF, права — на сервере.
**[К]** В legacy прав в серверном смысле нет: роль определяется редакцией сборки (`is_user_edition`),
а `network_role` в настройках **не ограничивает запись** (зонд тулбара: при `network_role="user"` в admin-сборке
доступны «Добавить контроль», «Импорт Excel», «Справочники»; скрыта только «Удалить все»).
Парольный шлюз отключён в раунде 34; хеш пароля — `base64(sha256(соль|пароль))` с жёстко зашитой солью
и поддержкой plaintext-поля (`core/edition.py:538-571`) — переносу не подлежит.

**[П]** Правила доступа:
| Действие | `admin` | `user` |
|---|---|---|
| Список/карточка/чтение файлов своих контролей | все записи | только свои (по `person_id`) |
| Создание, редактирование, исполнение, архив, восстановление | да | нет (403) **[Р: вопрос В-09]** |
| Окончательное удаление | да (только архивные, со снапшотом) | нет |
| Справочники людей/инициаторов | да | чтение |
| Импорт Excel, массовые операции, «очистить всё» | да | нет |
| Экспорт | все доступные записи | только свои |
| Настройки организации | да | чтение части |
| Персональные настройки | да | да |

**[Р]** Границы доступа внутри карточки для user (вопрос В-09): может ли user отмечать исполнение **своих**
пунктов и прикреплять файлы? В legacy user-редакция не может ничего (вплоть до вложений).

### 2.3 Конфликты, версии, офлайн-редактирование

**[ПРИНЯТО]** Без офлайн-редактирования: при отсутствии связи запись запрещена, ввод сохраняется в форме.
**[К]** В legacy — LWW по `updated_at` (`merge_controls`, `controls_data.py:1170-1199`; naive-время трактуется
как UTC, при равенстве побеждает локальная версия **[З: K]**), lock-файлы с гонкой «прочитал-потом-записал»
и stale 10 минут (`control_locks.py:24, 87-160`), а при обновлении данных из сети открытая карточка
**закрывается без сохранения** с потерей введённого текста (`_apply_pending_on_close`, `controls_tab.py:2401-2436`).

**[П]** Механика:
- `revision` у каждой записи; изменяющий запрос обязан передать ожидаемую версию (`If-Match`);
  несовпадение → **409** с телом «свежая версия + список изменённых полей», введённые пользователем значения
  сохраняются в форме и могут быть применены заново;
- ключи идемпотентности (`Idempotency-Key`) для создания и для подтверждения импорта; повтор запроса
  возвращает первоначальный результат, не создавая дубль;
- lock-файлы не используются;
- транзакция на операцию; каждая изменяющая операция пишет `audit_log` и увеличивает `change_cursor`.

### 2.4 Временные загрузки против опубликованного скана

**[П]** Двухфазная схема: `POST /api/uploads` создаёт временный объект (TTL, SHA256, размер, определённый MIME),
не привязанный к записи; `POST /api/controls/{id}/attachments` публикует его и связывает. Скан-гард проверяет
**опубликованные** вложения с допустимым содержимым. Прерванная загрузка сканом не считается; повторный POST
с тем же `upload_id` не создаёт копию; чужой `upload_id` не принимается.
**[К]** В legacy гард проверяет наличие файла на диске с расширением из `.pdf/.png/.jpg/.jpeg`
и только для новой карточки (`controls_tab.py:3724-3748`), импорт Excel освобождён.

### 2.5 Индивидуальные сроки

**[ПРИНЯТО]** Правила `user_effective_due_date`/`user_deadline_status` переносятся дословно,
включая неочевидный fallback: если свои пункты исполнены, а пользователь остался исполнителем/контролёром —
он видит **общий** срок и, следовательно, чужую просрочку **[З: B1–B5]**.
**[П]** Изменить только способ сопоставления: `person_id` вместо `name_matches` (фамильное совпадение даёт
ложные срабатывания, включая «Иванов» ↔ «Иванова» **[З: A4/A5]**).

### 2.6 Периодичность

**[К]** Автоматического переноса `due_date` периодического контроля в legacy **нет** ни в одном месте кода.
**[Р]** Вопрос В-05: нужен ли автоперенос в новой системе? Рекомендация — **не вводить** в рамках миграции
(изменение бизнес-правила), при необходимости — отдельная задача после переключения.

### 2.7 Уведомления

**[ПРИНЯТО]** Серверный журнал, интервалы user 2 ч / admin 24 ч, статусы `overdue`/`today` для алармов,
`overdue`/`today`/`soon` и «новый/изменённый» для ленты; атомарное подтверждение показа; одна цепочка опроса на вкладку.
**[П]** Ограничения, которые объявляются владельцу, а не обходятся: закрытый/уснувший браузер не даёт ни звука,
ни доставки; звук — только после явного жеста пользователя; пропущенное видно в ленте после возврата.
**[К]** В legacy звук — Windows MCI/winsound, вне Windows тихо; `notify_log`/`alarm_log` локальные и обрезаются
через 30 дней (дефект T-01 — из-за этого падает один кейс smoke-теста **[Т]**).

### 2.8 Обновление данных

**[П]** Лёгкий опрос `GET /api/changes?since=<cursor>` раз в 15–30 с (интервал фиксируется в W01),
права перепроверяются, устаревший курсор → безопасная полная перезагрузка доступной выборки,
таблица не пересоздаётся целиком, форма/фокус/поиск/прокрутка не затираются, при изменении открытой карточки —
индикатор новой версии, не автоперезапись. **[К]** В legacy — чтение целого файла по mtime раз в ~60 с
(`_poll_network_io`, 5482) и полная перестройка таблицы (`_rebuild_table`, 1457).

## 3. Операции новой системы (API-уровень)

Таблица — **[П]**, контракт уточняется в W02. Общее для всех: JSON, UTF-8, ошибки в едином формате
`{"error": {"code", "message_ru", "field?", "details?"}}`, `revision` в теле записи, `Idempotency-Key`
для создающих/подтверждающих операций, CSRF-токен для изменяющих запросов, cookie-сессия `HttpOnly; Secure; SameSite=Strict`.
«Транзакция» — одна транзакция БД, включающая запись `audit_log` и увеличение `change_cursor`.
