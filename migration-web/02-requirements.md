# Требования и источники поведения

Это исходная матрица, не утверждение о полном аудите всех ветвей legacy. W00 дополняет её по коду и синтетическим примерам. Каждый пункт получает тест и ссылку на реализацию в итоговой матрице приёмки.

Пути ниже заданы относительно определяемого агентом абсолютного корня репозитория. Рабочий корень автора плана: `C:\Users\User\Documents\Исходная программа\porayonka-app v2 DARK final`.

## Поля, которые нельзя потерять

Control: id, incoming_number, receive_date, initiator, content, executors, controller, control_type, period_days, due_date, end_date, done, done_date, comment, tasks, milestones, attachments, archived, archived_at, archive_reason, created_at, updated_at.

ControlTask: id, title, assignees, due_date, is_done, done_date, comment.

ControlMilestone: id, date, note, is_done.

Старые строковые ФИО преобразуются в ссылки на людей через проверенную таблицу соответствий. Нечёткий поиск legacy нельзя использовать для серверной авторизации. Однофамильцы и неоднозначные сокращения требуют решения администратора; неизвестное имя не удалять и не связывать с первым похожим аккаунтом.

## Правила с повышенным риском

- Периодичность сейчас хранится в днях. Не заменять «30 дней» календарным месяцем без отдельного согласования. Завершение/перенос периодического срока описать по фактическим операциям legacy.
- У user без своего активного срока статус может быть «В работе», а не «Без срока»: не унифицировать молча.
- Входящий номер — основание диагностики дублей, не безусловный UNIQUE до разбора существующих коллизий и правил владельца.
- Сохранять исходную идентичность записей и вложений; legacy-ID missing/duplicate исправлять только воспроизводимым mapping, не новым UUID при каждом повторе миграции.
- Различать сохранение исторических данных и допуск новых невалидных записей. Старые дефекты выводить в отчёт, не превращать молча в корректные значения.
- При новой модели доступа владельцу нужно подтвердить, видит ли участник все пункты доступного контроля или только свои. Базовое предложение: доступная карточка целиком, индивидуальный расчёт сроков; до подтверждения не раскрывать спорные данные.

## Осознанные отличия от legacy

Одна база вместо union-merge; конфликт версий вместо победы по времени; аккаунт вместо «Кто вы?»; браузер вместо установщиков; нет фонового tray; нет гарантированных уведомлений при закрытом браузере; нет офлайн-редактирования; открытие серверного файла вместо контроля скачанной локальной копии. Каждое существенное отличие подписывается решением в W00.
