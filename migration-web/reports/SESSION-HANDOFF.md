## 7. Особенности среды, которые нужно учитывать при продолжении

- **История git сбрасывается каждый ход (подтверждено трижды: два раза в W01-ходе, один раз в W00).**
  В `git reflog` остаются только `clone` и `checkout`, HEAD возвращается на `b5f24ab`, коммиты агента
  локально исчезают, файлы рабочего каталога сохраняются как неотслеживаемые.
  Процедура восстановления в начале каждого хода:
  ```bash
  git log --oneline -3; git status --short
  git fetch origin arena/01a0a90c-porayonka
  git ls-tree -r FETCH_HEAD -- migration-web controls-web   # blob-SHA удалённых версий
  git hash-object <файл>                                    # сверка каждого локального файла
  cp <свои изменённые файлы> /tmp/keep/                      # сохранить правки хода
  rm <дубликаты, идентичные удалённым>
  git merge --ff-only FETCH_HEAD
  cp /tmp/keep/* <обратно>
  git rev-parse HEAD; git status --short
  ```
  Если файл отличается от удалённой версии — не удалять его, а коммитить поверх и пушить обычным push.
- **Процессы стенда сброс git переживают**: PostgreSQL (`.pgdata`) и uvicorn продолжали работать после
  пересоздания checkout. Но каталоги `.venv`, `node_modules`, `dist` при пересоздании **песочницы**
  не сохраняются — разворачивать заново `bash scripts/provision_stand.sh` (полный прогон exit 0).
- **Сеть песочницы ограничена**: доступны PyPI (200) и npm registry (200), GitHub; **недоступны**
  deb.debian.org (http и https), repo1.maven.org, get.enterprisedb.com, ftp.postgresql.org; Docker и
  podman отсутствуют; `sudo` и `apt-get` есть, но списки пакетов пусты. Поэтому PostgreSQL берётся из
  npm-пакета `@embedded-postgres/linux-x64` (16.14.0-beta.17).
- **Подключение GitHub** может быть недействительным (в W00 было); при ошибке авторизации сообщать
  ограничение и просить переподключить GitHub в Arena, не обещая публикацию.
- **Порт стенда 8080** (0.0.0.0) виден владельцу как live preview платформы. Для показа без временных
  endpoints запускать с `CONTROLS_WEB_ENABLE_TEST_ENDPOINTS=0`.
