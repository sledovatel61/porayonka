## 7. Особенности среды, которые нужно учитывать при продолжении

- **История git сбрасывается каждый ход (подтверждено дважды).** Песочница пересоздаёт checkout: в `git reflog`
  остаются только `clone` и `checkout`, HEAD возвращается на `b5f24ab`, коммиты агента локально исчезают
  (`fatal: Not a valid commit name`), а файлы рабочего каталога сохраняются как неотслеживаемые.
  Процедура восстановления в начале каждого хода (без force и без потери данных):
  ```bash
  git log --oneline -3; git status --short                     # проверка состояния
  git fetch origin arena/01a0a90c-porayonka                    # FETCH_HEAD = опубликованный коммит
  git ls-tree -r FETCH_HEAD -- migration-web                   # blob-SHA удалённых версий
  git hash-object migration-web/<файл>                         # сверка каждого локального файла
  cp -r migration-web /tmp/backup-$(date +%s)                  # страховка
  rm <неотслеживаемые дубликаты, идентичные удалённым>          # только после совпадения hash-object
  git merge --ff-only FETCH_HEAD                               # fast-forward своей ветки
  git rev-parse HEAD; git status --short                       # HEAD = SHA из remote, дерево чистое
  ```
  Если файлы изменились относительно удалённых версий — не удалять их, а закоммитить поверх и выполнить
  обычный push (fast-forward). `--force`, merge/rebase `main` и удаление ветки запрещены.
- **Подключение GitHub.** `gh auth status` может быть как недействительным, так и восстановленным; при ошибке
  авторизации не подменять её обещанием публикации, а сообщать ограничение и просить переподключить GitHub в Arena.
- **Архивная копия документов.** На случай повторного сброса истории семь документов дополнительно переданы
  владельцу одним ZIP-архивом через интерфейс Arena (вне репозитория, в git не добавляется).
