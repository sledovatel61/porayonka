### 1.1 Инцидент среды: сброс checkout (произошёл дважды за этап)

Песочница Arena пересоздаёт git-checkout: `HEAD` возвращается на базовый `b5f24ab…`, опубликованные
коммиты локально исчезают, а файлы рабочего каталога сохраняются как неотслеживаемые. В этом ходу сброс
случился **дважды** (в начале хода и в середине, между наполнением БД и коммитом).

Процедура восстановления (выполнена, данных не потеряно, `--force` не использовался):

```bash
git fetch origin arena/01a0a90c-porayonka          # FETCH_HEAD = опубликованный коммит
git ls-tree -r FETCH_HEAD -- migration-web         # blob-SHA удалённых версий
git hash-object migration-web/<файл>               # побайтовая сверка каждого локального файла
cp <изменённые в этом ходу файлы> /tmp/w01keep/     # сохранить свои правки
rm <дубликаты, идентичные удалённым>                # только после совпадения hash-object
git merge --ff-only FETCH_HEAD                      # fast-forward своей ветки
cp /tmp/w01keep/*.md migration-web/                 # вернуть свои правки поверх
```

Результат: `HEAD = 0d2b9d9` (remote = local), правки `decisions.md` и `risk-register.md` сохранены как
изменения поверх, каталоги `controls-web/` и `.github/` не затронуты. Процессы стенда (PostgreSQL,
uvicorn) сброс пережили: `/api/health` → `ok`, `pg_ctl status` → `server is running`.

## 4. Решения W01

| № | Решение | Обоснование |
|---|---|---|
| 1 | Новый проект только в `controls-web/`, полностью независимый от `porayonka-app` и `src/` | Требование плана; прототип `src/` (Tailwind v4, Vite 7 по умолчанию) с Win7 несовместим |
| 2 | Backend: Python 3.11 + FastAPI 0.141.1 + psycopg 3.3.5; PostgreSQL ≥ 14 (проверено 16.14) | Базовое предложение `01-architecture.md`; тихая замена на SQLite запрещена |
| 3 | В песочнице PostgreSQL поднят из npm-пакета `@embedded-postgres/linux-x64` 16.14.0-beta.17 | apt-зеркала Debian (http и https) и Docker в песочнице недоступны; Maven Central и EDB заблокированы. Это настоящий сервер PostgreSQL, а не замена |
| 4 | Frontend: React 19.3 + TypeScript 5.9.3 + Vite 7.3.6, обычный CSS без UI-библиотек | Промпт: «не добавлять тяжёлую UI-библиотеку без необходимости»; TypeScript 7.x и Vite 8.x не взяты как слишком свежие для воспроизводимой сборки |
| 5 | `build.target` задан явно, список запрещённых API/CSS проверяется тестом | Совместимость доказывается проверкой сборки, а не намерением |
| 6 | Схема — идемпотентный `schema.sql`; инструмент миграций отложен на W02 | Промпт запрещает миграции рабочих данных в W01 |
| 7 | Соединение с БД на запрос, без пула; один процесс uvicorn | Пул, число работников и служба — задача W07 |
| 8 | Временные endpoints `/api/w01-test/*` под флагом `CONTROLS_WEB_ENABLE_TEST_ENDPOINTS` | Промпт требует пометить и удалить/закрыть их до W02; флаг `0` отключает их вместе с `/api/docs` |
| 9 | Каталог загрузок не раздаётся статикой; файл доступен только по id вложения | Промпт: «не оставляй публичную раздачу файлов» |
| 10 | Список: `page_size` по умолчанию 50, максимум 200; `page_size=10000` → 422 | Промпт: «не отправляй все 10 000 записей в браузер» |
| 11 | Детерминированное наполнение: `uuid5` от seed, digest в `seed_meta` | Требуется воспроизводимость 10 000 записей |
| 12 | Синтетический PDF генерируется reportlab + локальный DejaVu (кириллица), проверяется pypdf | Доказательство кириллицы внутри файла, а не только в имени |
| 13 | CI: три job'а (frontend → backend → smoke) с PostgreSQL 16 сервис-контейнером, установка из lock. Файл хранится в `controls-web/ci/controls-web-w01.yml`, а не в `.github/workflows/` | Промпт: первичный CI без секретов. Опубликовать workflow из сессии не удалось: токен GitHub-приложения не имеет права `workflows` (§6). Содержимое сохранено в git, инструкция по включению — в `controls-web/ci/README.md` |
| 14 | Win7-статус — «ожидает проверки», инструкция владельцу подготовлена | Без реальной машины объявлять совместимость запрещено |

### 7.2 Что доказано

1. Сквозной путь работает: HTTP → FastAPI → **настоящий PostgreSQL 16.14** → список → карточка.
2. 10 000 записей наполняются воспроизводимо: одинаковый digest при повторном прогоне, сверка с БД
   (`verify.ok = true`), полный проход по 200 страницам возвращает ровно 10 000 уникальных id без потерь
   и повторов (тест `test_full_sweep_200_pages_returns_all_10000_unique_ids`).
3. Страницы по 50, границы страниц и лимиты `page_size` корректны; все записи одним ответом не отдаются.
4. Поиск по кириллице работает, спецсимволы LIKE экранируются (`%`, `_` дают 0 результатов, а не все записи).
5. Production-сборка обслуживается с того же origin; внешних ресурсов, CDN, шрифтов и телеметрии нет.
6. Кириллица сохраняется: в карточке, в имени файла, в заголовке `Content-Disposition` (RFC 5987)
   и **внутри** синтетического PDF (извлечение текста pypdf).
7. Загрузка/скачивание PDF побайтово идентичны (sha256 совпадает), дубль с другим содержимым отклоняется
   (409), повтор идентичного файла идемпотентен, каталог загрузок статикой не раздаётся (404).
8. Сборка не использует API/CSS новее согласованного порога — проверяется тестом, а не визуально.

| 1 | Кириллица в `Content-Disposition` → 500 (starlette кодирует заголовки в latin-1) | smoke-проверка | percent-encoding по RFC 5987; тест `test_sample_pdf_header_is_rfc5987_encoded` |

### 7.4 Наблюдения, требующие решения в W02/W03 (занесены в реестр рисков)

- Глубокая пагинация через OFFSET дорожает линейно: страница 200 — p50 ≈ 83 мс (R-28, keyset-пагинация в W03).
- Поиск `ILIKE '%термин%'` по шести колонкам — последовательное сканирование: p50 ≈ 72–139 мс (R-29,
  `pg_trgm`/полнотекстовый поиск в W02/W03).
- Соединение с БД на каждый запрос даёт ~1–3 мс накладных (пул — W07).
- Стенд в песочнице эфемерен: `.venv`, `node_modules`, `dist`, `.pgdata` не переживают сброс среды (R-30);
  воспроизводимость обеспечена lock-файлами и `scripts/provision_stand.sh`.

## 10. Инструкция Win7

Полная инструкция: **`controls-web/docs/win7-checklist.md`** (17 шагов, что записывать, критерии
пройденной проверки, действия при сбое). Кратко:

1. На машине с Windows 7 открыть `browser://version`, записать версию движка Chromium, разрядность,
   версию ОС, RAM, разрешение; убедиться, что режим Турбо выключен.
2. Открыть адрес стенда, дождаться списка из 50 строк, засечь время.
3. Проверить счётчики в шапке и строку состояния внизу.
4. Прокрутить список, оценить плавность.
5. Найти `СТЕНД-000042` (ровно одна запись) и кириллический термин `сводку`, засечь время.
6. Перейти на 5 страниц вперёд и в конец списка.
7. Открыть карточку: проверить кириллицу, даты, ФИО, пункты.
8. Скачать синтетический PDF, проверить русское имя файла и кириллицу внутри.
9. Загрузить тот же PDF в карточку, убедиться в успехе; загрузить повторно — дубль не создаётся.
10. Отключить сеть, нажать «Обновить» → понятное русское сообщение; вернуть сеть → «Повторить».
11. Оставить страницу на 5–10 минут, отметить память вкладки.
12. Приложить скриншоты, SHA сборки (`git rev-parse HEAD`), имена файлов из `frontend/dist/assets`,
    дату/время и сообщения об ошибках дословно.

Стенд для проверки разворачивается по `controls-web/README.md`, раздел «Запуск на сервере»;
для показа владельцу временные endpoints отключаются: `CONTROLS_WEB_ENABLE_TEST_ENDPOINTS=0`.
