# Эскиз интерфейса: один рекомендуемый вариант

Этап W00, агент 1. Документ содержит **только описание** интерфейса: структуру, состав элементов, тексты,
состояния и правила поведения. HTML/React/Flet-кода нет — реализация начинается в W01 после выбора владельца.

Все пользовательские тексты — на русском. Тема — тёмная, компактная, без тяжёлых эффектов.
Настоящие ФИО и входящие номера в примерах не используются; данные синтетические.

---

## 1. Принцип: один вариант, без параллельных редизайнов

В `design/mockups/` уже существуют три серии мокапов (v1 — 5 направлений раскладки, v2 — 5 скинов, v3 — 6 скинов)
и рекомендация «основной кандидат — Graphite Pro». Предлагаемый здесь вариант — **продолжение этой линии**:
плотная таблица с фильтрами (семейство «Excel-Pro») + рабочая карточка справа, тёмная графитовая палитра.

Почему именно он, а не «master-detail» из рекомендации v1:
- **[К]** фактический legacy-интерфейс — это таблица со строкой фильтров (`controls_tab.py:1636-1950`),
  пользователи к ней привыкли, перенос раскладки важнее смены визуального языка;
- **[К]** в legacy уже есть сохранённые персональные ширины колонок (`col_widths`) — табличная раскладка
  переносит их без переучивания;
- плотная таблица лучше держит 10 000 записей с серверной пагинацией, чем список карточек;
- карточка справа сохраняет «быстрое переключение между записями», ради которого рекомендовался master-detail.

**Владелец выбирает один вариант.** Если выбран не этот — дальше реализуется только выбранный,
второй не поддерживается (требование `03-stage-prompts.md` W00.6).

## 2. Базовые параметры отображения

### 2.1 Экран-основание **[Р: вопрос В-06]**

Фактическое разрешение Win7-мониторов неизвестно. До ответа принимаем расчётное основание:

| Параметр | Значение | Статус |
|---|---|---|
| Целевое (расчётное) окно браузера | **1366 × 768**, масштаб 100 %, без панелей, полезная высота ≈ 640 px | **[П]** |
| Комфортное окно | 1600 × 900 и выше | **[П]** |
| Минимум, при котором интерфейс не ломается | 1024 × 768 | **[П]** |
| Максимальная ширина содержимого | без ограничения (таблица тянется), боковые отступы 16–24 px | **[П]** |

Правила деградации:
- при ширине < 1280 px — скрываются второстепенные колонки («Тип», «Дата поступления») в пользу
  «Вх. №», «Содержание», «Срок», «Статус»; полный набор колонок доступен через «Настроить колонки»;
- при ширине < 1100 px — карточка открывается на всю ширину (не справа), список под ней сохраняется;
- при высоте < 700 px — панель счётчиков и панель фильтров склеиваются в одну строку;
- системное масштабирование 125 % не должно ломать раскладку (проверка в W01 на реальном Win7).

### 2.2 Типографика и ритм **[П]**

| Элемент | Размер | Вес |
|---|---|---|
| Базовый текст таблицы | 13 px | 400 |
| Вторичный текст, подсказки | 11–12 px | 400 |
| Заголовки колонок | 10–11 px, прописные, межбуквенный интервал 0.08em | 600 |
| Заголовок экрана | 20–22 px | 700 |
| Заголовок карточки | 16 px | 700 |
| Секция карточки | 10–11 px прописными, акцентный цвет | 700 |

Шрифт — системный (Segoe UI / системный стек), **без внешних загрузок**; кириллица обязательна.
Межстрочный интервал таблицы 1.35; отступы ячеек 8–10 px по вертикали, 7 px по горизонтали.
Радиусы 4–12 px; тени — только у карточки и диалогов, не у строк таблицы; `backdrop-filter` и свечения не использовать.

### 2.3 Палитра (тёмная, «графит») **[П]**

Ориентир — документированная палитра мокапа `design/mockups/v3/01_graphite_pro.html`
(последняя зафиксированная рекомендация дизайна). Важное ограничение: CSS мокапа использует `color-mix()`,
которая **не поддерживается Chrome 109** — в реализации использовать готовые значения цветов, не `color-mix()`.

| Вторичный текст | `#8994a7` | подсказки, метки, «показано N из M» |
| Акцент | `#4493f8` | ссылки, активные элементы, фокус, входящий номер |
| Просрочено | `#f05b61` | левая полоса строки, пилюля статуса, дата |

### 4.2 Шапка и тулбар

- Слева: имя раздела «Контроли» и **индикатор связи** — одна строка, три состояния:
  `● Сервер: связь есть · данные на 14:32:05` (зелёный), `● Обновление…` (акцентный),
  `● Нет связи с сервером · последние данные 14:02` (красный). Индикатор виден всегда — это замена
  legacy-строки «Сеть: админ · 14:32:05» (`controls_tab.py:884-913`).
- Справа: основные действия. Состав зависит от роли (**[К]** в legacy состав кнопок зависит от редакции сборки,
  а не от роли — в новой системе зависит от роли):

| Кнопка | admin | user |
|---|---|---|
| `+ Добавить контроль` | да | нет |
| `⇧ Импорт Excel` | да | нет |
| `⇩ Экспорт Excel` | да | да (только свои записи) |
| `⚙ Настройки` | да | да (только персональные) |
| `🔔 Уведомления` + счётчик | да | да |
| `Журнал действий` | да | нет |
| `Справочники` | да | чтение |

- Кнопки, недоступные роли, **не показываются вовсе** (как в legacy user-редакции), а не рисуются неактивными:
  это уменьшает шум и исключает попытку действия, которое сервер всё равно отклонит.

### 4.3 Счётчики и фильтры

- Плитки-счётчики: `Все`, `Просрочено`, `Сегодня`, `Скоро`, `В работе`, `Исполнено`, `Без срока`
  (в legacy последней плитки нет — статус `none` смешивался с «В работе» у user; см. R08).
  Клик — фильтр по статусу, повторный клик — снять. Числа считаются **по тому же запросу, что и список**
  (в legacy счётчики игнорировали поиск и выпадающие фильтры **[К]**, `controls_tab.py:1483`).
- Переключатель `Активные | Архив` — как в legacy (архив отдельно, не смешивается).
- Строка поиска: «Поиск по номеру, содержанию, исполнителям…». Поиск серверный, с задержкой 300 мс,
  минимум 2 символа; состав полей поиска — как в legacy плюс `comment` и `receive_date` **[П]**,
  точный состав утверждает владелец.
- Строка фильтров под шапкой (по колонке): вх. № (текст), дата поступления (с/по), инициатор (список),
  содержание (текст), исполнители (список + «Прочие»), контролёр (список + «Прочие»), тип (список),
  срок (с/по), статус (список). Кнопка `Сбросить фильтры` — как в legacy (`_reset_filters`, 1732).
- Даты вводятся **и клавиатурой** (`ДД.ММ.ГГГГ`), и выбором в календаре; есть кнопка очистки.
  **[К]** В legacy ручной ввод дат отсутствует: поле даты — только текст с открытием русского календаря
  (`ui/controls/russian_calendar.py:86-120`). Это намеренное улучшение.
- Выбор людей — **без вложенных диалогов**: раскрывающийся список с поиском прямо в панели фильтров
  (требование W04.2; в legacy для этого был `_build_inline_multi`, `controls_tab.py:2002`).
- Все фильтры, сортировка, размер страницы и номер страницы **сохраняются** в URL и в персональном профиле:
  возврат из карточки восстанавливает их, как и позицию прокрутки. **[К]** В legacy сохранялись только ширины
  колонок и размеры карточки.

### 4.4 Таблица

| Колонка | Ширина (предложение) | Содержание | Правила |
|---|---|---|---|
| Индикатор срока | 3 px | цветная полоса слева | цвет статуса; продублирован пилюлей |
| № | 3 % | порядковый в текущей выборке | нумерация сквозная с учётом страницы |
| Вх. № | 11 % | номер + пилюли | акцентный цвет, жирный; **без обрезания** длинных номеров с суффиксами — перенос строки; пилюля `📎 N` (вложения) и `Без скана` (красная) |
| Дата поступления | 7 % | `ДД.ММ.ГГГГ` | пустая — прочерк |
| Инициатор | 8 % | каноническое имя | длинное — перенос, не обрезание |
| Содержание | 24 % | текст | до 3 строк с многоточием, полный текст — в подсказке и в карточке |
| Исполнители | 12 % | сокращённые ФИО через запятую | для user — **с выделением себя**; длинные списки сворачиваются «+2» |
| Контролёр | 8 % | сокращённое ФИО | — |
| Тип | 6 % | «Разовый» / «Постоянный, ежеквартально» | как `control_type_text` (`controls_exporter.py:90-103`) |
| Срок | 8 % | дата (личный срок для user) + подсказка «общий срок: …» | цвет по статусу; пустой — «Без срока» |
| Статус | 8 % | пилюля: точка + текст | 7 статусов из R06 |
| Действия | 6 % | `Открыть`, `Изменить`, `•••` | `•••`: «Исполнить», «В архив», «Восстановить», «Удалить навсегда» (admin, только архивные) |

Прочее:
- липкая шапка и липкая строка фильтров при прокрутке;
- сортировка кликом по заголовку: срок, дата поступления, вх. №, статус; индикатор направления;
  стабильный tie-breaker `(срок, id)` — иначе порядок «прыгает» при равных датах **[П]**;
- исполненные записи в режиме «Активные» опускаются вниз (как в legacy, `controls_tab.py:1043-1046`);
- режим «Архив»: дополнительная колонка «Причина и дата архивации» («Исполнено 12.05.2026» /
  «Удалено 12.05.2026») — как в legacy (1334–1345);
- плотность: переключатель «Компактно / Обычно» (высота строки 34 / 44 px) **[П]**;
- «Настроить колонки»: порядок, видимость, ширина (сохраняется в профиле).

### 4.5 Пагинация и производительность

- Серверная пагинация: по 50 (доступно 25/50/100), строка «Показано 1–50 из 134».
- **[К]** В legacy пагинации нет: `_rebuild_table` (1457) строит по виджету на каждую видимую строку.
- Прокрутка страницы — без полной перерисовки: обновляется только тело таблицы, строка фильтров,
  поиск и прокрутка не сбрасываются (требование W06.3).
- Ожидание ответа — индикатор в строке пагинации и приглушение таблицы, **без** модального блокирующего окна.

### 4.6 Состояния списка

| Состояние | Как выглядит |
|---|---|
| Загрузка | скелетон 8 строк + «Загрузка…»; никаких пустых миганий |
| Пустой список (нет данных вообще) | иконка, «Контролей пока нет», для admin — кнопка «Добавить контроль» и «Импорт Excel» |
| Пустой результат фильтра | «Ничего не найдено по этим условиям» + кнопка «Сбросить фильтры» |
| Ошибка сервера (5xx) | «Не удалось загрузить список» + «Повторить» + время последней успешной загрузки |
| Нет связи | баннер сверху «Нет связи с сервером. Данные на 14:02. Изменения сейчас сохранить нельзя» + повтор с backoff |
| Доступ отозван / сессия истекла | «Сеанс завершён. Войдите заново» — форма карточки при этом не теряется (см. §6.4) |

## 5. Карточка контроля

### 5.1 Размещение

- Ширина ≥ 1280 px: панель справа, ~46–50 % ширины, высота — вся доступная; список остаётся виден слева
  и не перерисовывается. Клавиши `↑`/`↓` — переход между записями, `Esc` — закрыть.
- Ширина < 1100 px: карточка на всю ширину поверх списка (с возвратом к прежнему фильтру и странице).
- **[К]** Legacy-карточка — модальное окно 920 × 780 с перетаскиванием размеров (`controls_tab.py:2603-4350`,
  размеры из настроек `card_width/card_height`, 571–572).

```
│ 🖼 фото-страницы.png · 340 КБ · загружен 01.03.2026 · [👁][⬇][✕]│
│ ▓▓▓▓▓▓▓▓░░ 80 % · загрузка 4,1 МБ из 5,1 МБ                    │
├───────────────────────────────────────────────────────────────┤
│ Изменён: Петров П.П., 12.05.2026 14:20 · версия 7              │
│                        [ Отмена ]  [ Сохранить ]  [••• действия]│
└───────────────────────────────────────────────────────────────┘
```

Правила полей:
- обязательные помечены `*` **и действительно проверяются** (в legacy `*` у даты поступления есть, а проверки нет);
- даты — ввод с клавиатуры и календарь, кнопка очистки; некорректная дата подсвечивается сразу,
  подсказка «Формат: ДД.ММ.ГГГГ»;
- «Конечная дата» видна для **обоих** типов контроля (в legacy для разового она скрыта, но значение сохраняется —
  расхождение D-02); подпись объясняет смысл: для постоянного — окончание цикла, для разового — срок контроля;
- выбор людей — один раскрывающийся список с поиском, **без вложенных диалогов**;
- длинное содержание и длинные ФИО не ломают раскладку: поля тянутся, текст переносится,
  горизонтальной прокрутки внутри карточки нет;
- «Периодичность» — тот же набор, что в legacy: ежедневно (1), еженедельно (7), ежемесячно (30),
  ежеквартально (91), каждое полугодие (182), ежегодно (365), свой интервал (≥ 1 день) **[К]**
  (`controls_tab.py:216-227`);
- подсказка «следующие даты» — как `_refresh_cycle_hint` (2808–2816), только отображение.

### 5.3 Пункты и точки

- Пункт — строка-карточка с полями: название, ответственные (мультивыбор), срок, комментарий,
  чекбокс «исполнено» и дата исполнения, кнопки «удалить» и «переместить» (порядок сохраняется).
  **[К]** В legacy иконка перетаскивания есть, но перетаскивание не реализовано — порядок менялся только
  добавлением/удалением.
- Отметка «исполнено» сразу показывает пересчитанный общий срок контроля (правило `sync_due_after_tasks`)
  и подписывает его: «Общий срок изменён: 01.05.2026 → 01.06.2026 (после исполнения п.1)».
- Пустое название пункта — ошибка («Укажите название пункта»), а не молчаливое удаление строки
  (в legacy пункт с пустым названием исчезает при сохранении **[К]**, 3768–3775).
- Точки: дата и/или примечание, «исполнено». Id точки стабилен между сохранениями (в legacy перевыпускается
  при каждом сохранении — D-05).

### 5.4 Вложения

- Список с именем, размером, типом, автором и датой загрузки; действия: просмотр (`👁`), скачать (`⬇`),
  удалить (`✕` — admin или загрузивший).
- Загрузка с прогрессом и возможностью отмены; ограничение размера и типа показывается **до** выбора файла
  (подпись «PDF, PNG, JPG · до 50 МБ» — лимит **[Р]**).
- Готовое вложение видно сразу, без перезагрузки карточки; повторное нажатие «Сохранить» не создаёт копию;
  прерванная загрузка сканом не считается.
- Просмотр = серверная копия (PDF/изображение в новой вкладке или во встроенном просмотрщике);
  скачивание — отдельное действие с корректным кириллическим именем файла. Интерфейс **не утверждает**,
  что знает локальную папку пользователя (в legacy была кнопка «Открыть папку» и `os.startfile`).
- Одинаковые имена разных файлов допускаются (в legacy второй файл с тем же именем отбрасывался).

### 5.5 Действия в подвале (по роли)

| Действие | admin | user | Условие |
|---|---|---|---|
| `Сохранить` | да | нет | только при изменениях; `Ctrl+S` |
| `Отмена` | да | нет | при несохранённых изменениях — предупреждение |
| `Исполнить контроль` | да | нет | диалог с датой исполнения |
| `Исполнить пункты…` | да | нет **[Р В-09]** | мультивыбор пунктов + одна дата (как legacy `_open_task_done_dlg`, 3873) |
| `В архив` | да | нет | подтверждение с причиной |
| `Восстановить` | да | нет | только для архивных |
| `Удалить навсегда` | да | нет | только для архивных, двойное подтверждение |
| `Закрыть` | да | да | — |
| `Экспорт этой записи` | да | да | опционально **[П]** |

### 5.6 Несохранённые изменения и уход со страницы

- Индикатор «изменена» в заголовке карточки + предупреждение при закрытии вкладки/переходе
  («Изменения не сохранены. Уйти?»).
- **[К]** В legacy при обновлении данных из сети открытая карточка закрывалась **без сохранения**
  с потерей введённого текста (`_apply_pending_on_close`, 2401–2436). В новой системе ввод сохраняется в форме.
- Черновик **не** кладётся в постоянное браузерное хранилище по умолчанию (требование W04.6);
  допускается только в памяти вкладки.

## 6. Импорт Excel, экспорт, конфликты и потеря связи

### 6.1 Импорт

```
1. Выбор файла        [ Перетащите файл сюда ]  или  [ Выбрать файл… ]
                      Требования: .xlsx, до 20 МБ, шапка во второй строке
2. Анализ             ▓▓▓▓▓░░ Разбор файла…        (файл: импорт-2026-09.xlsx, SHA256: 9f2c…)
3. План               Найдено строк: 210
                      Новые: 12   Обновляемые: 34   Без изменений: 158
                      Конфликты: 4   Ошибки: 2   Без скана: 41
                      ┌ конфликты ─────────────────────────────────────────┐
                      │ ВХСОП-123-456-27 — несколько записей с таким номером│
                      │ ВХ-7 — номер повторяется внутри файла               │
                      └────────────────────────────────────────────────────┘
                      [ Показать подробности ]  [ Отмена ]  [ Применить ]
4. Применение         Создаётся контрольная копия… → Применение… → Готово
                      Применено: 46 · Пропущено: 4 (конфликты) · Отчёт: ⬇
```

Правила:
- план имеет владельца, срок действия, SHA256 файла и версии затрагиваемых записей; если записи изменились —
  план помечается устаревшим и требуется пересчёт (не молчаливое перетирание);
- применение возможно только после успешного снимка БД и файлов; если снимок не создан — применение не начинается;
- ошибки строк показываются построчно **без чужих данных** (номер строки, поле, причина);
- повторное подтверждение того же плана идемпотентно;
- категории плана — те же, что в legacy (`new/updates/unchanged/conflicts/errors`, `controls_exporter.py:611-717`),
  плюс «Без скана» (как в legacy-предпросмотре, `controls_tab.py:4558-4563`).

### 6.2 Экспорт

Диалог: режим («Как в таблице» / «Полный»), состав (текущая выборка / все доступные),
для admin — «Персонализировать под исполнителя…» (список людей). Предупреждение:
«Полный режим содержит служебные поля. Экспорт доступен только вам и будет записан в журнал».

### 6.3 Конфликт версий (409)

```
┌──────────────────────────────────────────────────────────────┐
│ Запись изменилась                                            │
│ Пока вы редактировали, Петров П.П. сохранил версию 8         │
│ (12.05.2026 14:31).                                          │
│                                                              │
│ Изменились поля: Срок исполнения, Комментарий, п.2 (исполнено)│
│                                                              │
│ [ Показать свежую версию ]  [ Сравнить ]                     │
│ [ Применить мои значения поверх ]   [ Отменить мои правки ]   │
└──────────────────────────────────────────────────────────────┘
```

Введённые значения **сохраняются** в форме в любом из вариантов; «Сравнить» показывает две колонки
(моя версия / свежая) по изменённым полям.

### 6.4 Потеря связи

- Баннер сверху списка и в карточке: «Нет связи с сервером. Последние данные: 14:02.
  Сохранить изменения сейчас нельзя». Кнопки записи становятся неактивными с подсказкой причины.
- Повтор соединения — с нарастающей задержкой (1 с → 2 с → 4 с → … до 60 с), после восстановления —
  автоматическое догоняющее обновление видимой выборки; карточка при этом не закрывается,
  а показывает индикатор «есть более новая версия».
- При возврате фокуса в вкладку — немедленная проверка свежести.
- История: в legacy статус связи был строкой в шапке («Сеть: нет связи») — сохраняется как элемент,
  но дополняется временем последней успешной загрузки.

### 6.5 Уведомления

- Колокольчик со счётчиком в шапке; лента справа (не модальное окно поверх таблицы):
  «Новый контроль ВХСОП-123-456-27 — срок 01.05.2026», «Срок п.2 наступил сегодня»,
  «Контроль ВХ-2 изменён: срок перенесён на 01.06.2026».
- Алармы по просроченным/сегодняшним срокам — отдельный заметный блок в ленте + звук
  (**только после первого действия пользователя** в сессии; в настройках — отключить).
- Интервалы: user — не чаще раза в 2 часа по одной записи, admin — 24 часа (как в legacy,
  `controls_notify.py:21-22`); «новый» — один раз.
- Честное ограничение в настройках: «Если браузер закрыт или компьютер спит, напоминание придёт
  после входа — в ленте пропущенных».

## 7. Доступность, маленький экран, длинные данные

| Ситуация | Правило |
|---|---|
| Длинный номер (`ВХСОП-123-456-27/дсп`) | перенос строки, без обрезания; колонка не уже 11 % |
| Длинное содержание (500+ знаков) | 3 строки в таблице, полный текст в карточке; поле карточки растягивается |
| Много исполнителей (10+) | в таблице «Иванов И.И., Петров П.П. +8», в карточке — полный список с поиском |
| Много пунктов (20+) | скролл внутри секции, заголовок секции липкий, счётчик «Пункты (23)» |
| Много вложений (30+) | скролл внутри секции, счётчик, фильтр по типу |
| Экран 1024 × 768 | скрытие второстепенных колонок, карточка на всю ширину, пагинация упрощается до «‹ 1/3 ›» |
| Масштаб 125 % | раскладка не ломается, горизонтальной прокрутки страницы нет |
| Клавиатура | полный обход: `Tab` по полям, `Enter` — сохранить, `Esc` — закрыть, `↑`/`↓` — навигация по списку, `Ctrl+F` — фокус в поиск; видимый фокус (акцентная рамка 2 px) |
| Цветовая слепота | статус всегда текстом + точкой, не только цветом; полоса слева дублируется пилюлей |
| Скринридер | заголовки колонок связаны с ячейками, статус объявляется текстом, диалоги имеют заголовки |

## 8. Чего в интерфейсе не будет (осознанные удаления)

| Legacy-элемент | Почему не переносится |
|---|---|
| Диалог «Кто вы?» при старте (`_maybe_ask_identity`, 5762) | Идентичность — из аккаунта, а не из выбора ФИО в списке |
| Настройки «Сетевой режим», «Роль», «Путь к общей папке» | SMB-синхронизация упраздняется |
| Диалоги блокировок `<shared>\.locks` (`_show_lock_dialog`, 2503) | Конфликт решается версией записи (409) |
| Диалог «Данные на сервере изменились» с закрытием карточки без сохранения | Заменяется на индикатор версии и сравнение (§6.3) |
| Предупреждение о расхождении часов клиента и сервера (`check_time_skew`) | Время считает сервер |
| «Удалить все» без снимка и журнала | Заменяется операцией с обязательным снимком, фразой подтверждения и записью в журнал |
| Кнопки «Открыть папку» / «Открыть скачанный файл» | Сервер не знает локальную папку пользователя; есть просмотр и скачивание |
| Вложенные диалоги выбора людей | Один раскрывающийся список с поиском |
| Ручная подстановка «сегодня» в пустую дату поступления | Явная ошибка валидации |
| Альтернативная карточка `control_card_modal.py` и `name_picker.py` | Мёртвый код **[К]** |
