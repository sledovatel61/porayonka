# ui-outline.md — интерфейс браузерных «Контролей» (один рекомендуемый вариант)

База: SHA `b5f24ab`. Ниже — ОДИН рекомендуемый вариант, текстовые схемы, без HTML/React кода
(код на W00 запрещён). Идея — сохранить привычную плотность и тёмную тему legacy-вкладки,
перенеся их на серверную пагинацию, роли и серверные права.

> **Все числа размеров — предложение и ничего больше.** Разрешение, RAM и браузер на Win7 не
> определены (N-02 в `decisions.md`). После замера на реальной машине (W01) ширины, кегли и
> высота строки пересматриваются одним решением владельца. В W00 размеры нужны только чтобы
> оценить состав и объём экранов.

## 0. Принципы (проверяемые)

1. **Компактная читаемая тёмная тема.** Палитра наследуется из legacy
   `ui/controls/glass_theme.py` (`GLASS`, `:16–46`): фон `#0a1024`, панели `#171f31`,
   плашка строки `#2a3247`, секции карточки `#2a3045`, поля ввода `#161c2c`, текст
   `#f2f5ff`, вторичный `#93a3c7`, приглушённый `#5d6b8f`, акцент `#4f8cff`,
   «просрочено» `#ff5c6e`, «сегодня» `#ffd166`, «скоро» `#ff9f43`, «в работе» `#2fd08b`,
   «исполнено» `#8a94ad`, «завершён» = акцент. Отдельное исправление **[Пред]**: в legacy
   ДВЕ палитры статусов — `GLASS` (таблица) и `STATUS_COLORS`
   (`core/controls_models.py:602–611`, другие оттенки, используется в `STATUS_LABELS`
   контексте) → один источник цвета.
2. **Минимум эффектов.** Без теней, размытия, «стекла», анимаций. Допустимо: рамка 1 px,
   подсветка строки при наведении, подсветка выбранного фильтра. Основание: Python-hover в
   legacy удалён из-за лагов (`controls_tab.py:582–589`)**[Код]** — на слабом ПК в браузере
   это тем более верно.
3. **Срок и статус видны всегда.** Колонки «Срок» и «Статус» не скрываются и не уезжают за
   горизонтальный скролл (sticky справа). Просроченное отличается не только цветом: иконка +
   подпись (монохромный экран, печать, доступность).
4. **Серверная пагинация.** Экран получает не более `page_size` строк (предложение 50),
   никогда «все контроли». Основание: legacy строит DOM для всех строк
   (`_rebuild_table` `:1457–1482`)**[Код]** — единственное место, где «тысячи строк»
   становится проблемой.
5. **Состояние списка сохраняется.** Фильтры, сортировка, страница, позиция скролла и ширины
   колонок восстанавливаются после F5 и при возврате на вкладку. В legacy сохраняются только
   ширины/размеры (`_save_col_widths` `:699–707`, размеры карточки `:4316–4332`), фильтры —
   только в памяти процесса **[Код]**.
6. **Форма не теряет ввод.** Любая ошибка (409/422/обрыв сети) оставляет введённый текст;
   «Закрыть» при изменениях спрашивает подтверждение.
7. **Русские подписи.** Названия кнопок и колонок — как в legacy (см. §7), даты —
   `ДД.ММ.ГГГГ`, без английского.

## 2. Строка списка

Состав — как в legacy (`_build_row` `:1265–1455`)**[Код]**, плюс два отличия:

```
│▌4 │ВХСОП-9001-26 │15.02│ГУК │Проверить материалы              │Романов Р.Р.│ 05.03 │ ● Просрочено │
│  │              │     │    │ п. 1 Левченко — 01.03            │Левченко Л.Л│ 10.03 │   📎2  ⚠     │
│  │              │     │    │ п. 2 Романов — 05.03 (исполнен)  │            │       │              │
```

- слева — 4-px цветная полоса статуса (как legacy, `:1432–1436`);
- «Содержание» включает строки пунктов: `п. N — ответственные — дата`, исполненные помечаются
  «(исполнен ДД.ММ.ГГГГ)» **[Код]** (`:1290–1303`);
- метки: 📎 число вложений (жёлтая пилюля), ⚠ «Без скана» (admin, активные, не исполненные)
  **[Код]** (`:1305`, `:1322–1333`);
- правые колонки sticky: «Срок» (эффективная дата; в user-режиме своя; ниже — ближайшие
  неисполненные точки; tooltip — оба срока, как в legacy `:1350–1357`) и «Статус»;
- длинные тексты: 2 строки + многоточие, полный текст — в подсказке; клик по строке →
  карточка;
- высота строки фиксирована для плотного сканирования (предложение 44–56 px; в legacy высота
  = контент при минимуме 56 через padding **[Код]** `:1421–1445`, а константа
  `_ROW_HEIGHT = 56` (`:198`) объявлена и не используется).

Отличия от legacy: (1) «№» — номер в пределах страницы, а не позиции всего списка
**[Код]** (R10/F-05); (2) счётчики считаются тем же запросом, что и список (см. P-02 в
`decisions.md`); если владельцу нужна legacy-семантика (счётчики по всему разделу, вне
фильтров) — это отдельный переключатель «считать по разделу».

```
│ Инициатор [ГУК ▾] (+ новый)                 │   коммент.: [___________]      │
│ Содержание                                  │ ▸ п. 2   срок 05.03.2026 ☑ 10.02│

│ Конечная дата  [01.03.2026 📅 ⟲]  (и у разового [Пред])                      │
│ ПРОМЕЖУТОЧНЫЕ ТОЧКИ  [+ точка]                                                │
│  15.02.2026 «промежуточный доклад» ☐ готово ✕                                 │
│ СКАН ЗАДАНИЯ  [+ прикрепить]                                                  │

│  📄 скан.png · загрузка 40 % ✕                                                 │
│ КОММЕНТАРИЙ [ multiline ]                                                     │
├──────────────────────────────────────────────────────────────────────────────┤
│ [Контроль исполнен] [Исполнен пункт] [В архив] │ [Отмена] [Сохранить] rev 12  │
└──────────────────────────────────────────────────────────────────────────────┘
```

Правила:
- поля и смысл 1-в-1 с legacy-карточкой (`_open_detail` `:2603–4350`)**[Код]**; секции те же:
  «Реквизиты», «Исполнение», «Комментарий», «Сроки», «Промежуточные точки», «Скан задания»,
  справа — «Пункты задания» (`:4141–4170`);
- автодобавление ответственных пунктов в исполнители контроля — сохраняем поведение legacy
  (`_sync_exec_from_tasks` `:2731–2755`), но показываем это как пометку «из пунктов», чтобы
  ручное снятие не выглядело багом (S-05) **[Пред]**;
- `end_date` показывается у обоих типов: в legacy поле скрыто у разового, хотя значение
  участвует в колонке H Excel **[Код]** (`:2788`, `controls_exporter.py:90–104`);
- у каждой даты — «⟲ очистить» (в legacy очистка невозможна **[Код]**, R01);
- вложения: состояния `загрузка N % / готов / ошибка / файл отсутствует` (в legacy «готово»
  подразумевается существованием файла **[Код]**), действия «предпросмотр / скачать / удалить»;
  «скачать» = обычная загрузка браузера, без обещаний о локальном хранении;
- пункт без заголовка и точка без даты и примечания — ошибка валидации, а не молчаливое
  удаление **[Код]** отличия от legacy (`:3766–3769`, `:3781–3783`);
- `rev N` — видимая версия записи (в предложении — в tooltip), чтобы конфликт 409 был
  понятен пользователю и отладке;
- роль `user` видит ту же карточку read-only: без полей ввода и кнопок действий, но с
  «предпросмотр/скачать» — как в legacy (`_iter_tree_parents`-обход `:4291–4330`)**[Код]**,
  с той разницей, что запрет обеспечивает сервер.

- список предпросмотра — постраничный (в legacy «до 20 + 20 + 10», `:4533–4560`)**[Код]**.

## 5. Конфликт версий, потеря сети, устаревшие данные

```
┌ Данные изменились (конфликт версий) ─────────────────────────────────────┐
│ Пока вы редактировали, контроль обновил Романов Р.Р. (12:03, rev 12 → 13).│
│ Ваши правки не будут потеряны. Выберите, что делать.                      │
│  [Их версия] [Моя версия] [Применить мои поля ▾] [Отмена]                 │
└────────────────────────────────────────────────────────────────────────────┘

● Сеть недоступна · 12:07 — сохранение приостановлено; черновик останется в этой вкладке.
◐ Данные могут быть неактуальны (последняя синхронизация 12:04)      ⟳ Повторить
```

Правила:
- 409 не закрывает форму и не затирает ввод (в legacy «Обновить» = закрыть без сохранения
  **[Код]** `:5341–5376`);
- «применить мои поля» — выбор по полям, автоматического слияния нет
  (`01-architecture.md`);
- при обрыве сети «Сохранить» не отправляет запрос и объясняет почему; черновик живёт в
  памяти вкладки + `sessionStorage`; сохранение при закрытии вкладки НЕ обещается;
- после восстановления — явное «Повторить» и автоповтор с backoff (legacy: toast
  «Сеть восстановлена, данные синхронизированы» **[Код]** `:5412–5481`);
- «могут быть неактуальны» — метка у списка, данные остаются читаемыми;
- при 422 ошибки показываются у поля, а не общим списком.

## 6. Роли, длинные тексты, узкий экран

**Роли.**
- `admin`: полный доступ, справочники, импорт, экспорт (в т.ч. по выбранному исполнителю —
  R16), массовые операции, настройки отдела, журнал действий;
- `user`: чтение доступных контролей, свои сроки и статусы, экспорт своих, вложения
  (просмотр/скачивание), настройки просмотра (ширины, размер карточки). Изменяющие кнопки не
  рендерятся, и сервер отклоняет такие запросы (двойная защита — R12).

**Длинные тексты** (содержание 1000+ символов, 15 пунктов, 8 вложений):
- содержание — авторастущее поле в карточке; в списке — 2 строки + полный текст в подсказке;
- пункты — внутренний скролл блока (в legacy правая колонка скроллится отдельно **[Код]**
  `:4155–4168`); в новой версии — обычный поток страницы + «показать все N пунктов», чтобы
  не терять ориентацию на маленьком экране;
- вложения — список с прокруткой; имена с кириллицей обрезаются с полным именем в подсказке;
- горизонтального скролла таблицы избегать: при нехватке места скрываются «Инициатор» и
  «Дата поступления», затем «Исполнители» — «Срок» и «Статус» не скрываются никогда.

**Узкий экран / небольшой монитор (перечисленное — предложение, не согласованные значения).**
- ≤1200 px: две колонки карточки складываются в одну (пункты под реквизитами);
- ≤1024 px: из списка остаются №, вх. №, Содержание, Срок, Статус;
- фильтры сворачиваются в «Фильтры (2)» с кнопками «Применить»/«Сбросить»;
- счётчики и индикатор связи — всегда видны;
- ни одного диалога шире 90 % окна; модалки — на всю высоту с внутренним скроллом;
- никаких «липких» нижних горизонтальных скроллов — только нативная прокрутка.

**Доступность и печать.** Контраст текста ≥4.5:1 на фоне палитры **[Не проверено]** —
инструментально меряется в W01; видимая фокус-обводка; Enter = сохранить, Esc = закрыть;
статус = цвет + иконка + текст; таблица печатается через Excel-экспорт, а не печать браузера.

## 7. Мелочи, которые сохраняем сознательно (проверено кодом)

| Мелочь | Где в legacy | Зачем |
|---|---|---|
| Сокращённая форма ФИО в списке и экспорте (`Фамилия И.О.`) | `short_name` (`core/controls_models.py:42–63`) | экономия места; полное имя — в подсказке |
| «Прочие» в фильтрах людей | `FILTER_OTHER` (`:54`), логика `:982–998` | ловит строки вне справочника, ничего не теряется |
| Чипы ролей «И»/«К» в справочнике людей | `_people_badges` (`:4818–4822`) | список выбора в карточке ≠ список фильтра (R11) |
| Жёлтая подсветка даты только «просрочено/сегодня» | `controls_exporter.py:213–218` | «скоро» не тревожит (просьба пользователя) |
| Подсказка «Следующие: …» у периодического | `_refresh_cycle_hint` (`:2808–2815`) | показывает следующие даты, не меняя данные (R05) |
| Toast «Сохранено» | `_save_detail` (`:3845`) | подтверждение, что сервер принял |
| Метка «Без скана» | `:1322–1333` | дозаполнение архивных записей видно сразу |
| «Исполнено» и «Завершён» — разные статусы | `STATUS_LABELS` (`core/controls_models.py:592–601`) | разные смыслы: закрывали мы или период истёк |

## 8. Что в UI не делаем (границы)

- не переносим «Справочники» пользователям (admin-only);
- не делаем drag&drop для всего — только для порядка пунктов, и лишь если W01 подтвердит
  дешёвую реализацию;
- не добавляем переключатель светлой темы (только тёмная);
- не делаем inline-редактирование в таблице: карточка остаётся единицей редактирования,
  как в legacy;
- не обещаем офлайн-редактирование, уведомления при закрытом браузере и «локальную копию
  файла» (`decisions.md` §2 «Честные границы»);
- не проектируем «десятки альтернатив» — этот вариант единственный; правки — списком
  замечаний от владельца, без параллельных редизайнов.
