# UI-контур вкладки «Контроли» в браузере (W00, один вариант)

Основа — фактическая структура legacy-вкладки (`porayonka-app/ui/controls/controls_tab.py`,
базовый SHA `b5f24ab…`), а не «идеальный редизайн». Пометки: `[код]` — как в legacy;
`[предложение]` — предлагается; `[решение владельца]` — нужно решение.

Принципы: один экран; диалоги поверх страницы, без «модального окна в модальном окне»
(в legacy три слоя оверлеев были источником регрессий — `AGENTS.md` §15.8); никакого `alert/confirm`;
данные подгружаются по требованию (список — страницами, карточка — по клику, файл — по клику).

**Колонки** — те же 10 + «Статус»: `TABLE_HEADERS` (`core/controls_exporter.py:26–40`), заголовок
таблицы берётся из них же (`controls_tab.py:1223 _rebuild_header`) `[код]`. «Содержание» включает
строки пунктов «п. N — ответственные — дата (исполнен дд.мм.гггг)» (`:1281–1300`) `[код]`.
«Разовый/постоянный» = `control_type_text` (`core/controls_exporter.py:90–103`) `[код]`. «Срок» =
персональный срок в user-режиме + до 2 ближайших неисполненных точек + tooltip с общим сроком
(`:1346–1376`) `[код]`.

**Отличия от десктопа (осознанные):**

| Что | Legacy `[код]` | Браузер |
|---|---|---|
| Левая полоса цвета статуса 4 px | Stack-слой (`:1417–1429`) | `border-left: 4px solid var(--status)` |
| Разделители колонок, resize мышью | 9 `_vsep` + `GestureDetector` + аккумулятор дельт (`:1101–1195`), ширины в `settings["col_widths"]` (`:699–706`) | CSS `col-resize`; сохранение ширины — личный `view_prefs` `[предложение]` |
| Hover строки | нативный InkWell (`:1437–1449`) | CSS `:hover` |
| Высота строки | по контенту, ≥56 px, **все** пункты (`:1299–1312`) | то же; при >4 пунктах — «ещё N» + раскрытие `[предложение]` |
| Счётчики | по `_visible_base()`, фильтры/поиск игнорируются (`:1483–1497`) | по текущему фильтру (R10) |
| Пагинация | нет — `_rebuild_table` строит все строки (`:1457–1481`) | серверная, по 50 (25/50/100/200) `[предложение]` |
| Пустой список | «Контролей не найдено» / «В архиве пусто» (`:1461–1468`) | то же + «сбросить фильтры» |
| Режим «Архив» | колонка «Тип» → «Причина» + дата архивации (`:1330–1338`) | то же |
| Пилюли вложений | «📎N» (жёлтая) и «⚠ Без скана» (`:1305–1331`) | те же; «без скана» — только активные/неисполненные |
| Сортировка | клик по любому заголовку; для «Содержания»/«Исполнителей»/«За кем контроль» фактически = по сроку (`:1018–1046`) | только реально поддерживаемые столбцы; у остальных — обычный курсор и tooltip «недоступно» |
| Состояние фильтров | в памяти вкладки, теряется при перезапуске; «мусорное» значение сбрасывается на «Все» (`:1519–1572`) | URL-параметры + личный `view_prefs`; возврат/F5/«назад» сохраняют фильтры, страницу и позицию |

**Роли.** `user`: в toolbar только «Экспорт» и «⚙ Просмотр» (тема/плотность); «Добавить», «Импорт»,
«Справочники», «Удалить все» не отображаются **и** запрещены сервером (в legacy кнопки физически не
добавляются: `:5163–5169` — в новой системе переносим это на сервер, R12). `admin`: полный toolbar.
Счётчики, список и экспорт считаются по «мои/все» в зависимости от роли `[решение владельца]`
(см. S04: в legacy алармы шире списка).

**Позиция скролла.** При фоновом обновлении списка строки меняются точечно (incremental), скролл и
фокус сохраняются; при открытии карточки позиция запоминается и восстанавливается при закрытии
`[предложение]` (в legacy позиция терялась — пересборка всего `rows_column`).

```
┌──────────────────────────────────────────────────────────────────────────────────┐
│ Карточка контроля      ИСС-12-34-26-26                                     [✕]  │
│ rev 7 · изм. Иванова А.А. 12:41 · ⚠ «редактирует Петров П.П. с 12:33» [обновить] │
├──────────────────────────────────┬───────────────────────────────────────────────┤

│ «Следующие: 09.06 · 09.07 · 08.08»│ …                                            │

```

Переносится 1:1 по поведению `[код]`:
- обязательность — только «вх. №» (`:3709–3716`); пустая «Дата поступления» автоподставляется с
  тостом (`:3750–3761`);
- «Периодичность» и «Конечная дата» видны только при типе «Постоянный» (`:2758–2790`), но
  `end_date` сохраняется и у разового (`:3813`);
- подсказка «Следующие: …» = `base + period_days·i`, i=1..3 (`:2808–2818`);
- пункты: `title`, ответственные (роль «Исполнители»), срок, «готово», дата, комментарий; черновик
  не затирается при пересборке (`:2847–2975 _harvest_task_drafts`) — в вебе это естественное
  состояние формы, но тест обязателен;
- исполнители контроля пополняются ответственными пунктов автоматически, снятые вручную галки не
  возвращаются (`:2728–2757 _sync_exec_from_tasks`);
- «Исполнен пункт» — мультивыбор чекбоксами + одна дата, пишет сразу (`:3873–4005`, пересчёт срока
  `:3936`);
- «Контроль исполнен» — только через диалог с датой (`:4360 _open_done_dialog`), архивация с
  причиной `done` (`:4350 _do_complete`);
- «В архив» (`:3847 _delete_detail`) с подтверждением; в архиве — «Восстановить»/«Удалить
  навсегда» (`:4207`, `:4210`);
- вложения: миниатюра 76 px, «🔍 предпросмотр» (картинка в overlay; PDF без встроенного рендера —
  кнопка «Открыть», `:3089–3160`), «↗ открыть», «⬇ скачать» (`:3324 _download_attach`,
  `:3409 _on_dl_saved`, `:3446 _dl_button_for`), «🗑 удалить» с подтверждением (`:3487`);
- скан-гард при создании — ошибка + подсветка секции (`:3720–3747`), при редактировании истории —
  нет.

Новое `[предложение]`: «rev + changedBy + changedAt» в заголовке, панель «Журнал изменений»,
advisory-плашка «редактирует другой админ» (вместо lock-файлов `core/control_locks.py:111`),
автосохранение черновика при ошибке/закрытии, счётчик знаков в длинных полях.

**Длинный текст.** В legacy: `min_lines=3, max_lines=5` для содержания (`:2745`) и `1…3` для
комментария (`:2829`), в списке — рост по числу строк + tooltip с полным текстом (`:1299–1300`).
В новой системе: авто-рост до 10 строк → внутренний скролл → «Развернуть»; в списке — `max-lines`
+ tooltip; перенос длинных ФИО и дат в пунктах не должен обрезать значение.

**Две колонки → одна** при ширине < 1100 px (`[код]`: `is_narrow = (page.width or 1280) < 1100`,
`:4132`); секции складываются в одну колонку с общим скроллом.

```
Шаг 1  [Выбрать .xlsx] → загрузка на сервер (прогресс, отмена)
Шаг 2  Сводка:  Найдено 42 · Новые 5 · Обновляемые 3 · Без изменений 33 · Конфликты 1 ·
                Ошибок 0 · Без скана 4 · Формат: полный | таблица
         вкладки: [Новые 5] [Обновляемые 3] [Без изменений 33] [Конфликты 1] [Ошибки 0]
         план:    «ИСС-12-34-26-26 · изменится: Содержание, Срок (10.05.26 → 05.09.26)»
         конфиг:  «номер встречен 2 раза в файле — не применяется» /
                  «в базе несколько записей с таким номером — выбрать вручную»
         ошибки:  «строка 34: нет вх. № — пропущено»
Шаг 3  [Отмена] [Применить] → pre-apply backup → применение → отчёт
         «создано 5 · обновлено 3 · пропущено 34»; при 409 — «данные изменились, пересобрать план»
```

Совпадение с legacy: те же категории плана и правила «richer-поля» (R17/R18) `[код]`. Отличия: план
постраничный (в legacy — лимиты 20/20/10 без навигации, `:4530–4556`), перед применением —
проверка `expected_revision`, отчёт хранится и доступен из «Журнала импортов» `[предложение]`.

## 4. Экран «Экспорт Excel»

`[Экспорт ▾]`: «Как в списке (текущий фильтр, N строк)» · «Полный round-trip (admin)» · «Архив
(admin)» · «Мои контроли» (user) `[предложение]`. Формирование — серверная задача, автозагрузка по
готовности, при пустом результате — явная причина («в архиве пусто», «фильтр ничего не нашёл»);
в legacy экспорт в режиме «Архив» молча давал пустой файл (S08) — исправляется осознанно.

## 5. Состояния: конфликты, сеть, ошибки

| Ситуация | Legacy `[код]` | Целевое поведение в браузере |
|---|---|---|
| Данные изменились, карточка закрыта | `_apply_shared_update`: молча заменяет список + тост «Данные обновлены из сети» (`:5377–5410`) | плашка «Данные обновились · Показать», без пересборки скролла; список обновляется постранично |
| Данные изменились, карточка открыта | `pending_shared` + диалог «Обновить/Позже»; «Обновить» = закрыть без сохранения (`:5341–5376`, `:2401–2436`) | черновик не теряется: автосохранение + сравнение «ваш вариант / серверный»; «Применить мои» (→ PATCH с `expected_revision`) / «Взять серверные» |
| Конфликт сохранения | LWW по `updated_at` (`core/controls_data.py:1149–1199`) | `409`: форма остаётся открытой со значениями, показывается дельта; «перезаписать» — отдельное явное действие |
| Сервер недоступен | индикатор «Сеть: нет связи» (`:884–913`), работа на локальных, merge при возврате (`:5412–5480`) | баннер «Нет связи с сервером · изменения не сохранены»; повторные попытки с backoff; локальных «теневых» копий нет |
| Ошибка/обрыв загрузки файла | tmp удаляется, вложение не прикрепляется, тост «Не удалось прикрепить файл» (`core/controls_data.py:923–1027`, `controls_tab.py:3508–3617`) | то же + состояние «не опубликовано (ждёт)» у строки; повторный клик не создаёт копию |
| Файл потерян | тост «Файл вложения не найден» + диалог с путём (`:3458–3485`) | плашка «файл утерян»; путь на диск не показываем |
| Битая дата | `parse_date → None` («без срока») молча | поле подсвечено: «значение „31.04.2026“ не распознано», сохранить можно только исправив |
| Идёт фоновое копирование большого файла | счётчик задач `wait_attach_jobs` (`:324–360`) | прогресс на строке вложения; «Сохранить» не блокируется, но предупреждает |
| 429 / 5xx | — (недоступно) | понятный текст + «повторить через N с» |

## 6. Тёмная тема

Палитра — порт `porayonka-app/ui/controls/glass_theme.py` (`GLASS`) в CSS-переменные: `bg #0a1024`,
`card #2a3247`, `surface/surface_alt/surface_solid`, `border #0dffffff`, акцент, `overdue`, `today`,
`soon`, `in_progress`, `done`, `completed`, `text/text_secondary/text_muted` `[код]`. Подписи статусов —
`STATUS_LABELS` (`core/controls_models.py:592–601`), цвета — `STATUS_COLORS` (`:602–610`),
иконы — `STATUS_ICONS` (`ui/controls/controls_tab.py:89–99`), коды статусов — `:15–21`,
подсветка Excel и списка — только `OVERDUE`/`TODAY` (`core/controls_exporter.py:235–237`) `[код]`.
Приёмка W04: `contrast ratio ≥ 4.5:1`, видимый `:focus-visible`, `prefers-reduced-motion`, отсутствие
светлой вспышки при загрузке (`<html data-theme="dark">` до первого кадра) `[предложение]`. Светлая
тема вне объёма (в legacy её нет).

## 7. Плотность и узкие экраны

- `≥1366px`: полная таблица (10+1 колонок), две колонки в карточке;
- `1100–1365px`: компоновка legacy-минимума (ширина таблицы 1240 при окне 1280,
  `:652–697 _fit_widths`), горизонтальный скролл таблицы не нужен;
- `≤1100px`: карточка в одну колонку (`:4132`); таблица — закреплённые «№/Вх. №» + горизонтальный
  скролл `[предложение]` (в legacy фиксации колонок нет);
- `≤760px`: список карточками (Вх. №, содержание, срок, статус), фильтры — выезжающая панель,
  действия — нижняя шторка `[предложение]`;
- плотность «Обычная/Компактная», размер страницы — личные настройки `view_prefs`.

## 8. Размерности (предложение, не обязательство)

Таблица: высота строки 56+ (по контенту), ширины — как `_FIXED` (`bar 4, num 32, incoming 160,
receive 88, initiator 116, controller 112, type 82, due 100, status 116`; `:187–197`) + гибкие
«Содержание»/«Исполнители» (мин. 60) `[код]`. Карточка: 920×780 по умолчанию (`:571–573`
`settings["card_width"]/["card_height"]`), изменение за правый нижний угол (`:2280–2340`); в вебе
предлагается `max-width: 1240px`, высота по контенту с внутренними скроллами, запоминание размера
как личная настройка. Справочники: 680×560 по умолчанию (`:574–575`) `[предложение]`. Точная
геометрия фиксируется скриншот-тестами на 1280×860 / 1024×768 / 1366×768.

## 9. Чек-лист соответствия legacy (для ревью W00 и приёмки W04)

- [ ] тот же набор полей карточки и та же обязательность (только «вх. №»)
- [ ] «Дата поступления» автоподставляется с тостом, а не молча
- [ ] статусы/цвета/подписи 1:1 с `STATUS_LABELS`/`STATUS_COLORS`; подсветка только OVERDUE/TODAY
- [ ] «Срок» в списке = персональный (для user), общий срок — в tooltip
- [ ] периодичность: «Ежедневно/Еженедельно/Ежемесячно/Ежеквартально/Каждое полугодие/Ежегодно/Свой интервал», подпись месяцами
- [ ] пункт: ответственные, срок, «готово», дата исполнения, комментарий; `id`/`done_date` не теряются
- [ ] точки: дата, описание, «готово»; влияют на общий срок
