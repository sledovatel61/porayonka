# Архитектура новой версии

## Решено и предложено

**Решено владельцем:** браузер, отдельная переработка «Контролей», исполнители Arena, без переписывания зональных и отделов сейчас.

**Базовое техническое предложение для утверждения W00:** Python/FastAPI, React/TypeScript, PostgreSQL. Python, FastAPI и React уже встречаются в репозитории, но старые закреплённые версии не являются ограничением нового сервера. PostgreSQL добавляется осознанно. W01 закрепляет поддерживаемые на дату реализации версии, драйвер, миграционный инструмент, тестовые средства и сборщик с доказательством совместимости браузера. Не ставить библиотеки просто «на всякий случай».

Не поддерживать две базы или два фронтенда. Если серверная инфраструктура не позволяет PostgreSQL, остановиться и согласовать альтернативу, а не незаметно заменить его SQLite.

## Схема

Браузеры Win7/современных ОС → HTTPS на одном адресе → сервер приложения → PostgreSQL и закрытое файловое хранилище на сервере.

Сервер — поддерживаемая ОС (конкретную выбирают в W00). База и приложение не запускаются на Win7. Не размещать файлы базы на SMB-папке. Резервные копии можно дополнительно переносить на отдельный сетевой носитель.

Один модульный сервис, не микросервисы. Основные слои: доменная логика без UI; сервисы операций; БД и файловое хранилище; HTTP API; браузерный интерфейс. Не создавать новый файл на шесть тысяч строк, объединяющий таблицу, сеть, импорт и карточку.

Сервер обслуживает собранный интерфейс с того же origin. Статика, шрифты, иконки локальные, без CDN и внешней телеметрии. В production не использовать dev-сервер фронтенда. Развёртывание должно иметь один документированный поддерживаемый путь под выбранную ОС; Docker допустим только если подтверждён инфраструктурой, не обязателен.

## Браузер и Win7

Нельзя обещать «любой браузер». В W00 снять точную версию доступного браузера, разрядность, RAM, разрешение, ограничения установки и сеть. В W01 зафиксировать браузерный минимум и проверить фактическую сборку на нём. Internet Explorer в базовый план не входит.

Обычные HTML-элементы, CSS без обязательных новейших возможностей, ограниченный JavaScript. Не Flutter Web, не Canvas-приложение, не Electron. Страницы списка выдавать порциями с сервера; не отправлять все записи пользователю и не строить тысячи строк DOM.

Не считать режим эмуляции браузера доказательством поддержки Win7. Если допустимый браузер слишком стар для выбранных зависимостей, W01 возвращается к решению W00. Приоритет — лёгкий интерфейс и фактическая работоспособность, а не сохранение конкретной UI-библиотеки.

## Идентификация и права

Единая серверная учётная запись, связанная со стабильным person_id. Роли admin и user, по умолчанию user только читает доступные ему контроли. Самостоятельный выбор ФИО не является входом. Запреты проверяются сервером для списка, карточек, счётчиков, поиска, файлов, экспорта и событий обновления.

Предлагается серверная cookie-сессия: HttpOnly, Secure, SameSite, CSRF-защита изменяющих запросов; ограничение попыток входа и штатное хеширование паролей. Не хранить пароли/токены в localStorage. Способ выдачи учётных записей и восстановления доступа определить в W00/W02. Серверные секреты вне Git, debug выключен. Предусмотреть отключение аккаунта и завершение его сессий.

HTTPS с доверенным на рабочих машинах сертификатом — часть ввода, не декоративная настройка. Не требовать отключить проверку сертификатов или ослабить TLS ради старого браузера. Нет доступа из интернета; ограничение LAN не заменяет авторизацию.

## Хранение и изменения

Контроль сохраняет существующий UUID. Отдельные сущности для пунктов, промежуточных сроков, людей, назначений, вложений, журнала действий и настроек. Полный mapping старых полей фиксируется W00/W02. Исходные legacy-значения и непонятные поля при миграции сохранять для сверки, не выбрасывать.

Серверное время: моменты в UTC; календарные сроки — даты без преобразования в UTC. «Сегодня» определяется согласованным часовым поясом организации, предложено Europe/Moscow. Клиентские часы не выбирают победителя конфликта.

Операции выполняются транзакционно. У контроля revision/version. Обновление с устаревшей версией получает конфликт (например HTTP 409), а не перетирает чужое сохранение. То же для изменения пунктов, архива, вложений и импорта. В интерфейсе сохраняется введённый пользователем текст и показывается предложение сравнить с новой версией. Автоматического слияния полей нет.

Для создания и повторяемых операций предусмотреть ключ идемпотентности, привязанный к пользователю и содержимому запроса. Повтор после потери ответа не создаёт второй контроль. Аудит фиксирует актёра, время и изменение; не логировать пароли и содержимое сканов.

Удаление — сначала архив с причиной. Окончательное удаление отдельно подтверждается администратором и отражается в журнале. Старое union-merge с «воскрешением» удалённого не переносим.

## Обновление и пропажа сети

Начальный вариант — лёгкий авторизованный опрос версии/изменений раз в 15–30 секунд, точный интервал фиксируется после W01. Опрос не скачивает всю базу, не пересоздаёт всю страницу, не сбрасывает поиск, прокрутку и редактируемую форму. Возврат фокуса вкладке вызывает проверку свежести. Ошибка — backoff, видимый статус связи и время последнего успешного обновления.

При потере сети сохранение запрещено или завершается понятной ошибкой, но уже введённая форма не очищается. Не обещать сохранение при закрытии/перезагрузке вкладки; предупредить о несохранённых правках. Автоматического офлайн-редактирования и очереди скрытых отправок нет. Уже показанные данные могут оставаться на экране с пометкой «неактуальны». Это изменение относительно legacy требует одобрения W00.

Пользовательские уведомления формирует сервер; браузер показывает доступные уведомления без дублей. Скрытая вкладка может тормозить таймеры, закрытый браузер не гарантирует ни звук, ни уведомления. Push/service worker не обязательны. Если фоновые напоминания при закрытом браузере обязательны, согласовать отдельный канал до начала работ; не обещать решать это обычным JavaScript.

## Файлы и Excel

Файлы лежат вне публичной статики. Чтение только через авторизованный endpoint. Непредсказуемый URL не является защитой. Сервер генерирует имя хранения, проверяет разрешённый тип, размер и пути, не исполняет загрузку. Скачивание с безопасными заголовками; активный HTML/SVG не выдавать inline.

Загрузка — временный объект, проверка, публикация, затем привязка к модели. Сбой БД или файла имеет компенсацию и сборку сирот. Не утверждать, что транзакция БД автоматически атомарна с файловой системой. Повтор загрузки/сохранения не создаёт копии.

«Открыть» в браузере означает открыть серверную копию/просмотр или скачать. Веб-приложение не знает, куда браузер сохранил файл, и не проверяет его наличие на локальном диске. Desktop-механику FilePicker не воспроизводить.

Excel выполняется сервером с проверкой доступа, ограничениями размера/времени/распаковки. Предпросмотр привязан к пользователю, сроку действия и версиям записей; устаревший план нельзя применять молча. В экспорт не попадают чужие записи даже в скрытых листах.

## Что не входит в первую версию

Зональная вкладка и её PDF, отделы, мобильное приложение, автозапуск/tray, работа на Win7 в качестве сервера, синхронизация двух систем, полное офлайн-редактирование, публичный облачный сервис, внешние LLM, SSO без отдельного решения. Справочники людей и инициаторов для контролей входят.
