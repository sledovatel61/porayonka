## Задачи раунда 18

### 1. Строка фильтров — доводка

В `ui/controls/controls_tab.py`, секция `filter_row`:

- **Добавить слева заголовок «Фильтры»** с иконкой (например, `ft.icons.FILTER_LIST` / `ft.icons.TUNE`), таким же шрифтом/размером/жирностью, как надпись «Контроли» в `title_row`.
- **Заменить маленькую `IconButton` сброса фильтров** на полноценную кнопку `ElevatedButton` / `TextButton` с текстом **«Сбросить фильтры»**.
- **Растянуть панель `filter_row` на всю ширину** таблицы/окна. Сейчас она короче правого края (см. `Основной экран.png`). Задать явную ширину, равную ширине таблицы (`table_container.width`), и обновлять её в `_apply_table_geometry()` / `page.on_resize`.
- Сохранить поведение `Row(scroll=ScrollMode.AUTO)`: если фильтры не влезают по ширине, строка прокручивается горизонтально, а не уезжает за экран.

### 2. Excel — сохранить конечную дату исполнения (`end_date`) и соответствие исходной таблице

Исходная таблица (`Таблица контроей эксель.png`) имеет колонки:

| Колонка | Заголовок в исходнике |
|---|---|
| A | № |
| B | вх. № ВХСОП-____-__ |
| C | Дата поступления |
| D | Инициатор |
| E | Содержание (если один из нескольких пунктов - указать пункт) |
| F | Исполнитель (ФИО) |
| G | За кем контроль (Потёмкин С.А. / Чащин Э.А.) |
| H | Разовый / постоянный |
| I | Следующая дата исполнения |
| J | Исполнено + дата |

Колонка H используется комбинированно:
- **Разовый контроль** → там записана конечная дата исполнения (`01.09.2026`).
- **Периодический контроль** → либо текст периодичности (`Еженедельный ПН`), либо «`<конечная дата>` далее `<периодичность>`» (`10.05.2026 далее каждые 3 месяца`).

Колонка I — следующая/текущая дата исполнения (`due_date`).

Что сделать:

1. **Привести заголовки в `core/controls_exporter.py` (`TABLE_HEADERS`) и в таблице приложения (`_header_cell` в `ui/controls/controls_tab.py`) к точным названиям из таблицы выше.** Длинные заголовки переносятся на 2 строки (механизм раунда 17).
2. **Импорт (`core/controls_exporter.py`, `import_from_excel`, `_row_to_control`):**
   - Если значение колонки H парсится как дата → `control_type = ONE_TIME`, `end_date` = эта дата, `due_date` = дата из колонки I (если есть) или эта же дата.
   - Если в H текст периодичности → `control_type = PERIODIC`:
     - Парсить `period_days` существующей эвристикой.
     - Извлекать ведущую дату из текста, если она есть (например, `10.05.2026 далее каждые 3 месяца` → `end_date=10.05.2026`, `period_days=90`).
     - `due_date` = дата из колонки I.
   - Если присутствует скрытый лист `_controls_full` — он по-прежнему имеет приоритет для round-trip.
3. **Экспорт (`ControlsExcelExporter.export`):**
   - Колонка H «Разовый / постоянный»:
     - `ONE_TIME` → выводить конечную дату (`end_date` или `due_date`) в формате `dd.mm.yyyy`, а не слово «разовый».
     - `PERIODIC` → если задан `end_date`, выводить «`<end_date>` далее `<периодичность>`» (например, `10.05.2026 далее каждые 3 месяца`); если `end_date` нет — только периодичность.
   - Колонка I → `due_date` («Следующая дата исполнения»).
   - Скрытый лист `_controls_full` продолжает содержать полные данные.
   - В таблице приложения колонка «Разовый / постоянный» для разового контроля должна показывать конечную дату, для периодического — периодичность (как в Excel).
4. **Round-trip:** экспорт → импорт не должен терять `end_date`.

### 3. Заголовки колонок в приложении

В `ui/controls/controls_tab.py` заголовки таблицы (`_header_cell`) должны точно совпадать с `TABLE_HEADERS` из `core/controls_exporter.py` (см. таблицу выше). Дополнительные колонки приложения («Статус», «Действия») остаются без изменений.

### 4. Справочник людей — категории «исполнитель / контролёр»

В модальном окне «Справочники» (`_open_references`) добавить возможность назначить каждому ФИО категорию:

- **Не добавлять отдельную таблицу.** В строке каждого человека добавить переключатели/чипы/чекбоксы: **«Исполнитель»**, **«Контролёр»**, **«Обе»** (или две отдельные кнопки «Исп.» / «Контр.» с подсветкой активности).
- Хранить назначения в `controls_settings.json`:
  ```json
  "person_roles": {
    "Иванов И.И.": ["executor"],
    "Потемкин С.А.": ["controller"],
    "Сидоров С.С.": ["executor", "controller"]
  }
  ```
- Дефолтные роли:
  - Базовые криминалисты (из `core/zonal_data.load_criminalists()`) → `executor`.
  - Дефолтные контролёры (`Потемкин С.А.`, `Чашин Э.А.` из `DEFAULT_CONTROLLERS`) → `controller`.
  - Дополнительные люди (`extra_people`) → `executor` + `controller` (можно менять).
- Разделить канонические списки:
  - `get_executor_names(settings)` — все ФИО с ролью `executor`.
  - `get_controller_names(settings)` — все ФИО с ролью `controller`.
- Обновить:
  - Фильтры «Все исполнители» / «Все контролёры» (`executor_filter_dd`, `controller_filter_dd`).
  - Канонический матчинг `name_matches` — фильтр исполнителей искать по `executor_canonical`, фильтр контролёров — по `controller_canonical`.
  - Переименование/удаление человека должны корректно обновлять `person_roles`.

## Технические ограничения

- **Flet строго 0.23.2.** Не повышать.
- Цвета 8-hex — только `#AARRGGBB`.
- `print()` — только ASCII; UI-текст — русский; `ft.icons.*`.
- Внутри `Column(scroll=AUTO/ALWAYS)` — никаких `expand=True` (кроме горизонтальных спейсеров в `Row`), `wrap=True`, `animate*`, `gradient`, `shadow` на мелких контейнерах.
- Все `.update()` — через `_safe_update()`.
- Не ломать: hover таблицы, растягивание таблицы, ресайз колонок, карточку контроля, экспорт/импорт, сеть, архив, вложения, другие вкладки.
