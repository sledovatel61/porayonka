## 2. Пользовательская задача

Во вкладке **«Зональные криминалисты»** уже можно менять ФИО, примечание, активность и закреплённые отделы. Состав зональных и зоны временно меняются из-за отпусков, болезни и кадровых изменений.

Нужно реализовать две связанные возможности:

1. Пользователь может указывать, **кто с кем взаимозаменяем**.
2. Рядом с существующей кнопкой **«Экспорт в Excel»** появляется кнопка **«Выгрузить зональных»**, которая формирует PDF со свежим составом, зонами и взаимозаменяемостью в формате приложенного образца.

Это не экспорт результатов текущего сбора и не замена существующего Excel. Это отдельная печатная выгрузка актуального распределения зональных.

## 4. Модель взаимозаменяемости

### 4.1. Хранение

Добавить в `Criminalist` отдельное поле для связей по стабильным числовым ID, например:

```python
replacement_ids: List[int] = field(default_factory=list)
```

Допустимо иное ясное имя, но нельзя хранить взаимозаменяемость строками ФИО: ФИО может измениться.

Обновить сериализацию `zonal_criminalists.json`:

- старый JSON без нового поля загружается без ошибок и даёт пустой список;
- новый JSON переживает save/load round-trip без потери порядка и связей;
- преобразовывать значения к `int`, отбрасывать невалидные значения;
- не допускать собственного ID, дублей и ссылок на отсутствующих криминалистов;
- порядок ID должен быть детерминированным.

### 4.2. Семантика

Взаимозаменяемость — **неориентированная попарная связь**:

- если Иванов взаимозаменяем с Петровым, Петров автоматически взаимозаменяем с Ивановым;
- удаление пары с любой стороны удаляет обе половины связи;
- это не транзитивное отношение: пары `A ↔ B` и `B ↔ C` сами по себе не создают `A ↔ C`;
- человек не может быть взаимозаменяем сам с собой;
- удаление криминалиста очищает его ID у всех остальных;
- добавление нового криминалиста не создаёт связей автоматически;
- смена ФИО, порядка, зон или активности связь не ломает.

Вынести нормализацию/изменение связей в небольшие тестируемые core-функции, а не размазывать логику только по Flet callbacks. Нормализовать данные и после загрузки старых/ручных JSON, и перед сохранением.

`is_active` сейчас означает участие в текущем сборе. Не переопределять его молча как «в отпуске» и не удалять по нему людей или связи из печатного списка.

## 5. UI взаимозаменяемости

Добавить понятное редактирование взаимозаменяемости в существующий поток добавления/редактирования зонального.

Минимальные требования:

- в режиме редактирования видно поле/секцию **«Взаимозаменяемость»**;
- можно выбрать ноль, одного или нескольких других криминалистов;
- текущий человек отсутствует среди вариантов;
- варианты показывают ФИО и, желательно, номер/ID, который используется в PDF;
- уже выбранные люди отмечены при повторном открытии;
- сохранение одним действием сохраняет ФИО, примечание, зоны и связи;
- cancel не меняет модель;
- после сохранения UI актуализируется без перезапуска приложения;
- если связи показываются на плитке, не увеличивать фиксированную высоту и не ломать layout: использовать компактную строку/tooltip либо не выводить их на плитку вовсе;
- длинный список обязан быть bounded/scrollable согласно правилам Flet 0.23.2.

Не создавать цепочку вложенных `AlertDialog`. Можно аккуратно расширить существующий диалог либо реализовать один самостоятельный редактор, но итоговый UX должен быть однозначным и не перегружать текущий список 29 отделов.

Сохранить обратную совместимость публичных callbacks настолько, насколько это разумно; все внутренние вызовы и тесты обновить согласованно.

## 6. Новая кнопка и пользовательский сценарий

В `ui/zonal/zonal_tab.py` рядом с существующей кнопкой **«Экспорт в Excel»** добавить отдельную кнопку:

- текст: **«Выгрузить зональных»**;
- иконка только из `ft.icons.*`;
- tooltip явно говорит, что создаётся PDF распределения зон и взаимозаменяемости;
- визуально кнопка должна соответствовать текущему toolbar и не ломать его на типичном окне Windows.

Сценарий desktop:

1. Нажатие открывает `FilePicker.save_file` с именем наподобие `zonal_distribution_YYYYMMDD_HHMMSS.pdf`.
2. FilePicker сначала добавляется в `page.overlay`, затем выполняется `page.update()`, и только потом `save_file()`.
3. Cancel ничего не сохраняет, не показывает успех и не меняет состояние кнопок.
4. После успешной записи показать русский toast.
5. Дать возможность открыть последний PDF. Нельзя испортить существующую кнопку открытия Excel: хранить состояния/пути раздельно либо сделать ясный общий механизм.
6. Если файл удалён извне, обработать это без падения и показать понятную ошибку.

Сценарий web:

- `FilePicker.save_file` в браузере нельзя считать обычным локальным путём;
- PDF должен генерироваться сервером в безопасной папке внутри `FLET_ASSETS_DIR/downloads` и отдаваться через `page.launch_url(...)` или уже принятый в проекте эквивалент;
- использовать уникальное безопасное имя, исключить path traversal и гонки;
- desktop не должен начать складывать пользовательские выгрузки в assets;
- проверить как обычный web-run, так и frozen Win7 web-профиль на уровне импортов/spec/manifest.

Не переиспользовать один FilePicker с накоплением обработчиков. В Flet 0.23.2 присваивание `on_result` может накапливать handlers; использовать отдельный picker для PDF либо корректно отписывать прежний handler.

## 7. Точный формат PDF

Создать отдельный exporter, например `core/zonal_distribution_exporter.py`. Он принимает данные явно и тестируется без Flet/Page. Не помещать рисование PDF внутрь `zonal_tab.py`.

### 7.1. Внешний вид

Ориентир — `docs/reference/zonal_export_reference.pdf`:

- белый фон, чёрный текст, без цветных декоративных элементов;
- A4, правильная ориентация и поля, пригодные для обычной печати;
- заголовок сверху: **«Зональный принцип распределения отдела криминалистики»**;
- карточки идут в текущем сохранённом порядке;
- сетка — **три карточки в ряд**, как в образце;
- у карточки тонкая чёрная рамка и горизонтальное разделение шапки/зоны;
- в шапке: номер в круглых скобках и ФИО (жирно, по центру, переносится без обрезания);
- ниже: каждый закреплённый отдел отдельной строкой с маркером `-`;
- примечание не должно бесконтрольно смешиваться с названием отдела; если оно выводится, использовать отдельную компактную строку с ясным оформлением;
- после сетки отдельный заголовок **«Взаимозаменяемость:»**;
- каждая уникальная пара выводится ровно один раз в форме наподобие `Иванов И.И. (1) ↔ Петров П.П. (2)`;
- пары сортируются детерминированно по порядку карточек/ID;
- если пар нет, вывести `Не указана`;
- русские буквы и символ `↔` должны отображаться реальными glyph, без квадратов и mojibake.

Скан содержит исторические цифры в скобках после названий отделов, похожие на количество дел. **В текущей модели такого показателя нет. Не подставлять вместо него ID отдела и не выдумывать числа.** В текущей задаче выводить актуальные названия закреплённых отделов без фиктивного количества. Если будет добавлено опциональное реальное поле нагрузки, оно должно иметь отдельное редактирование, обратную совместимость и тесты, но это не является обязательной частью фазы 40.

### 7.2. Полнота и переполнение

- Не зашивать 15 конкретных фамилий или исторические зоны из скана.
- Источник истины — текущий `collection.criminalists` и `INITIAL_DEPARTMENTS` только для расшифровки ID отделов.
- Не отбрасывать людей из-за `is_active=False` или пустой зоны: экспорт отражает сохранённый справочник. Для пустой зоны написать `Отделы не закреплены` и при наличии отдельно показать примечание.
- Стандартный текущий список может отличаться от 15 карточек образца. Нельзя молча обрезать 16-го и последующих людей.
- При переполнении делать корректную многостраничную выгрузку: на каждой странице сохранять поля, читаемость, три колонки и при необходимости повторять короткий заголовок. Блок взаимозаменяемости размещать после последней карточки, перенося на следующую страницу целиком или аккуратными строками.
- Длинные ФИО, названия отделов и большое число отделов переносятся внутри карточки; текст не пересекает рамки и соседние карточки.
- Не уменьшать шрифт до нечитаемого ради одной страницы. Лучше добавить страницу.
- PDF должен быть валидным, непустым и открываться стандартным просмотрщиком Windows/браузером.

### 7.3. PDF-библиотека и шрифты

В проекте сейчас нет PDF runtime-зависимости. Разрешается добавить зрелую библиотеку (предпочтительно ReportLab), но тогда обязательно:

- выбрать и **зафиксировать** версию, совместимую с Python 3.10+, Windows и build-профилями проекта;
- обновить обычный `requirements.txt` и `requirements-win7-web.txt` согласованно;
- проверить PyInstaller desktop и оба web spec/hidden imports/data;
- не повышать Flet и не менять существующие pins без необходимости;
- обеспечить гарантированный кириллический шрифт в frozen-сборке: добавить в assets свободно распространяемый TTF/OTF и файл лицензии либо иной воспроизводимый bundled-вариант;
- включить шрифт/лицензию во все сборки и зарегистрировать шрифт по пути, работающему и в dev, и в `_MEIPASS`;
- иметь безопасный fallback с понятной ошибкой, а не формировать PDF с квадратами;
- не полагаться только на наличие `C:\Windows\Fonts` на машине разработчика.

Если выбирается реализация без новой зависимости, она всё равно обязана корректно встраивать Unicode-шрифт, давать валидный PDF и проходить все критерии. Самодельная хрупкая запись PDF без Unicode/пагинации неприемлема.

## 8. Архитектура и качество

- Бизнес-логика связей и форматирование данных — в `core`, UI wiring — в `ui/zonal`.
- Экспортер не должен мутировать коллекцию или сохранять JSON.
- Отдельные pure helpers для сокращения ФИО, уникальных пар и раскладки приветствуются.
- Ошибки записи (занятый файл, нет прав, отсутствует шрифт) не должны падать наружу из event handler: ASCII diagnostic + русский error toast.
- `print()` и диагностика — только ASCII/CP1251-safe; UI-тексты — русские.
- Не использовать emoji и `ft.Icons.*`; только `ft.icons.*`.
- Не добавлять `wrap=True` в Row внутри прокручиваемой вкладки.
- Не добавлять вертикальный `expand=True` внутрь `Column(scroll=AUTO)`.
- Не использовать `on_scroll`, тяжёлые hover, анимации, gradient/shadow на мелких элементах.
- Для скруглённых контейнеров использовать равномерную рамку.
- Обновлять немонтированные controls безопасно; соблюдать общий update lock в фоновых сценариях.
- Не делать генерацию тяжёлого PDF на Flet update thread, если она заметно блокирует UI; при фоне все изменения UI выполнять через принятую безопасную схему проекта.

15. Requirements/spec/assets включают выбранную PDF-библиотеку и кириллический шрифт во все нужные сборки.
