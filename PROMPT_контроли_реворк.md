## 2. Подтверждённые баги (логи и скрины пользователя, main @ c8257b2)

### БАГ A — «Импорт Excel» и «Экспорт Excel» не работают (из лога)

```
File "...\ui\controls\controls_tab.py", line 1021, in _export
    page._controls_file_picker.save_file(
File "...\flet_core\file_picker.py", line 208, in save_file
    self.update()
File "...\flet_core\control.py", line 314, in update
    assert self.__page, "Control must be added to the page first."
AssertionError: Control must be added to the page first.
```
То же для `_import` (строка 1037, `pick_files`). **Причина:** FilePicker
добавляется в `page.overlay.append(picker)`, но после append НЕ вызывается
`page.update()` — контрол не примонтирован к странице. Рабочий образец в
проекте: `ui/zonal/zonal_tab.py` → `on_export_excel()` — там после append
есть `page.update()` с комментарием «ВАЖНО». Проверить ВСЕ пикеры вкладки
(экспорт, импорт, вложения в карточке) и DatePicker'ы.

### БАГ B — вложенные диалоги вылетают на главный экран

Сценарий: «Добавить контроль» → клик «выбрать исполнителя» → открывается
вторая модалка (пикер) → выбор → «Готово» или «Отмена» → **закрываются ОБЕ
модалки**, пользователь на главном экране, данные карточки потеряны. То же
в «Ответственные» пункта задания. Фаза 2 пыталась лечить через
`page.open()/page.close()` — не помогло. Попытка открыть вторую модалку из
первой в Flet 0.23.2 ненадёжна.

**Требование:** устранить проблему РАДИКАЛЬНО — **убрать вложенные модалки**.
Выбор исполнителей/ответственных сделать ВНУТРИ карточки контроля: раскрываемая
секция/панель с чекбоксами + поиском (без второго AlertDialog). Никаких
вторых диалогов поверх карточки. Если найдёшь способ надёжно держать две
модалки в 0.23.2 — допустимо, но инлайн предпочтительнее и проще. Обязательна
проверка в реальном GUI: карточка → выбор исполнителей → продолжение заполнения
→ сохранение, без вылетов и потерь введённых данных.

### БАГ C — нет шапки (подзаголовков) таблицы

Пользователь: «не вижу подзаголовков в таблице, непонятно где и что».
**Причина (найдена):** `_rebuild_header()` в `controls_tab.py` пишет
`header_row_ref["control"].controls = [hdr]`, но `header_row_ref["control"]` —
это `ft.Container`, у которого есть только `.content`. Атрибут `.controls`
молча теряется, шапка никогда не рендерится. Исправить (шапка через
`.content`/`Row`), заголовки должны совпадать по ширине с колонками строк.

### БАГ D — не виден срок контроля

Пользователь: «не вижу срок контроля, только дату добавления». В строке —
дата поступления есть, «следующая дата исполнения» пустая/не там. Проверить
всю цепочку: выбор даты в карточке → сохранение в `due_date`/`milestones` →
`effective_due_date` → отображение в колонке (совпадение с шапкой БАГа C).
Заодно: в карточке дата «Следующая дата исполнения» должна реально выбираться
DatePicker'ом (см. БАГ A про монтирование контролов).

### БАГ E — значения dropdown-фильтров всё ещё обрезаны

После хотфикса (ширины увеличены) значения всё равно отображаются как «п -».
Значит дело не только в ширине: у `ft.Dropdown` внутри `label` + выбранное
значение конкурируют за место. Решения на выбор: убрать `label`, оставить
`hint_text`/подпись снаружи; `dense`/`content_padding`; больший `text_size` не
нужен — нужна видимость значения. Проверить все 5 фильтров + dropdown режима
экспорта на окне 1280 и развёрнутом 1920.

### БАГ F — мусор и deprecated

- В логе 7 × `[CONTROL_MODAL] Sozdayu kartochku kontrolya` подряд — карточка
  пересоздаётся на каждое действие; overlay засоряется DatePicker'ами.
  Карточку создавать один раз на открытие; пикеры монтировать один раз.
- `DeprecationWarning: on_window_event is deprecated in version 0.23.0` в
  `main.py:353` — не критично, по возможности заменить на актуальный API
  (осторожно, не сломать сохранение при закрытии).
