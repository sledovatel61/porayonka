## Цель

Исправить пять проблем Round 39 без потери функционала Admin/User, Desktop/Web:

1. очистка конечной даты периодического контроля;
2. ленивое создание тяжёлых вкладок;
3. двойное открытие браузера в Win7 Web;
4. два значка приложения в Windows-трее и отсутствие single-instance защиты;
5. Excel-импорт в Admin Win7 Web через Flet FilePicker upload.

Не урезать Admin Win7 Web: должны остаться «Контроли», «Зональные
криминалисты», «Следственные отделы», Excel, архив, вложения, сеть,
уведомления, справочники, редактирование, добавление, удаление, шаблоны,
сборы, сводки, статистика и экспорт. Flet строго `0.23.2`.

## 1. Конечная дата

Проверить `ui/controls/control_card_modal.py`, `ui/controls/controls_tab.py`,
`ui/controls/russian_calendar.py`, модели и Excel-код.

- В поле конечной даты должна быть явная команда очистки с понятным tooltip.
- Единый календарь должен использовать существующий контракт
  `on_change(Optional[str])`; второй независимый календарь не создавать.
- После очистки UI показывает пустое/«не указана» состояние, сохранение пишет
  `end_date=None`, повторное открытие не возвращает старую дату.
- Очистка не меняет `due_date`, `period_days`, `tasks`, `milestones`.
- Переход periodic -> one-time обнуляет скрытое значение `end_date`.
- После очистки можно выбрать новую дату и сохранить её.
- Добавить тест полного round-trip и Excel round-trip для пустой и заданной даты.

## 2. Ленивые вкладки без потери Admin-функций

Проверить `main.py`, `main_web.py`, `ui/zonal/*`, вкладку отделов и
`ui/update_lock.py`.

- На старте строится только активная вкладка «Контроли».
- «Зональные криминалисты» и «Следственные отделы» строятся при первом
  переходе.
- После первого построения экземпляр кэшируется и при возврате не
  пересоздаётся.
- Порядок вкладок и активная вкладка по умолчанию сохраняются.
- Использовать те же существующие builder-функции, чтобы не потерять ни одну
  возможность Admin. Все Flet-обновления и фоновые циклы соблюдать через
  общий lock. Не добавлять `on_scroll`, запрещённые layout-конструкции,
  анимации или тяжёлый hover.
- Допустима отключаемая ASCII-safe диагностика build/reuse.
- Тестом доказать: старт без двух тяжёлых builder-вызовов, первый переход
  строит каждый ровно один раз, повторный переход использует cache.

## 3. Один владелец открытия браузера

Проверить `main.py`, `main_web.py`, `start_web_win7.bat` и web-spec.

- Не допускать одновременного открытия браузера через Flet

- Не ломать повторный запуск, выбор порта, Admin Web и User Web.

  открытия. Не путать `webbrowser.open` в явной команде «Открыть» трея с
  автоматическим стартом приложения.

## 4. Tray и single-instance

Проверить `ui/tray_icon.py`, все вызовы из `main.py`, автозапуск и installers.

- В одном процессе создаётся ровно один `pystray.Icon`.
- Повторный и конкурентный вызов `start_tray()` возвращает существующий icon;
  проверка `_ACTIVE_ICON` выполняется и до, и после lock.
- Для Windows реализовать надёжный named mutex (`Local\\...`) или эквивалент.
  При уже занятом mutex второй desktop-процесс не создаёт tray и корректно
  завершается/передаёт управление первому. Ошибка API должна быть явно
  диагностирована; fail-open допустим только при невозможности вызвать API,
  не при `ERROR_ALREADY_EXISTS`.
- Web не должен случайно запускать desktop tray lifecycle, если это не
  предусмотрено текущей архитектурой.
- «Выход» освобождает mutex/guard и останавливает icon; закрытие окна крестиком
  сохраняет существующую семантику сворачивания в трей.
- Добавить mock-тесты повторного, конкурентного захвата и освобождения.

## 5. Excel import в Admin Win7 Web

Проверить `ui/controls/controls_tab.py`, `core/controls_exporter.py`,
`main_web.py`, оба web-spec и Flet 0.23.2 FilePicker API.

- В Web обработать реальные формы результата FilePicker: `path`,
  `files[*].path`, имя/загруженный путь и upload-событие.
- При необходимости вызвать upload и ждать завершения до `progress=1.0` и
  `error=None`; импортировать только после проверки существующего физического
  `.xlsx`. Фиктивные пути запрещены.
- Отмена, незавершённый upload, неверный файл и недоступный путь дают понятный
  русский toast и ASCII-safe запись в `error.log`/startup log. Исключения не
  должны теряться при `console=False`.
- Сохранить preview/upsert/backup, категории новые/обновляемые/без изменений/
  конфликты/ошибки, уникальные id, rich-поля и вложения.
- После подтверждения обновить модель, counters и таблицу. User-режим не
  получает импорт, Desktop-импорт не ломать.
- FilePicker добавить в `page.overlay`, затем `page.update()`. Обработчик
  подписывать ровно один раз; перед новой подпиской отписывать старую.
- Добавить mock-тест Admin Web: пустая модель -> выбор xlsx -> upload ->
  preview -> confirm -> запись в модели/таблице; отдельно отмена, ошибка и
  повторный импорт.
