## Цель

Устранить замечания пользователя после живой проверки установщиков Inno Setup и portable exe раунда 27. Сохранить весь текущий функционал, smoke-тесты ALL OK.

## Задачи

### 1. Установщики Inno Setup — обязательный автозапуск, убрать дубли

**1.1 Админский установщик (`installer/Admin.iss`)**
- На странице «Выберите дополнительные задачи» убрать чекбокс `Добавить в автозапуск Windows`. Автозапуск должен прописываться **всегда**, без возможности отказа.
- Убрать чекбокс `Запустить Порайонка — Администратор` с этой страницы. Запуск приложения оставить **только на финальном экране** мастера (как сейчас есть «Запустить Порайонка — Администратор» на последней странице).
- Убрать страницу ввода пароля (`PasswordPage`) из установщика. Пароль администратора задаётся внутри приложения (см. задачу 6). `edition.json` для admin пишется как `{"role": "admin"}`.

**1.2 Пользовательский установщик (`installer/User.iss`)**
- То же: автозапуск всегда, без чекбокса; убрать чекбокс «Запустить Порайонка — Пользователь» со страницы задач, оставить только на финальном экране.
- Страница ввода ФИО остаётся. При вводе ФИО в `edition.json` пишется `{"role": "user", "user_name": "ФИО"}`. Если ФИО не введено — `{"role": "user"}` (приложение спросит при первом запуске).

**1.3 Web-установщик (`installer/UserWeb.iss`)**
- То же: автозапуск всегда; убрать дублирующий чекбокс запуска со страницы задач; оставить только финальный запуск.
- Страница ФИО остаётся; `edition.json` с `user_name`.

### 2. Пользовательская portable-версия показывает функционал администратора

**Проблема:** пользователь установил user-версию, ввёл ФИО, но в приложении видны кнопки admin: «Добавить контроль», «Импорт Excel», «Удалить все», «Справочники», карточка редактируется.

**Диагностика и исправление:**
- Убедиться, что установщик кладёт в `{app}\edition.json` именно `{"role": "user", "user_name": "..."}` (а не пустой или admin).
- В `core/edition.py`/`ui/controls/controls_tab.py` убедиться, что explicit user-редакция **всегда** принудительно ставит `network_role = "user"` и сбрасывает `network_user`, даже если `%APPDATA%/porayonka/controls_settings.json` остался от предыдущей admin-установки.
- Добавить в `controls_tab.py` на старте **защитный гард**: если `edition["role"] == "user"` и `settings.get("network_role") != "user"`, принудительно перезаписать и сохранить. Если `edition_user` и `network_user` не совпадает с `edition["user_name"]` или `edition["user_name"]` пуст, сбросить `network_user`.
- Убедиться, что `edition.json` рядом с exe читается корректно при установленном приложении (путь к exe = папка установки, не временная папка PyInstaller).
- Если в `%APPDATA%/porayonka/edition.json` осталась admin-запись от предыдущей установки, но рядом с exe лежит user-`edition.json`, приоритет за **exe-папкой**. Либо при user-установке очищать `%APPDATA%/porayonka/edition.json`, чтобы не было конфликта.

**Smoke-проверка:**
- эмуляция установки user с ФИО + предустановленный `controls_settings.json` с `network_role=admin` → после старта роль user, функционал read-only.
- admin-установка после user → роль admin, полный функционал.

### 3. Web-версия — не спрашивать ФИО повторно

**Проблема:** web-установщик просит ФИО при установке, а после установки снова показывает диалог «Кто вы?».

**Исправление:**
- Убедиться, что web-установщик записывает `user_name` в `{app}\edition.json` и приложение его подхватывает.
- Если `edition["user_name"]` непустой, диалог «Кто вы?» не показывать, сразу строить таблицу с фильтром по этому ФИО.
- Если ФИО при установке не введено — показать диалог «Кто вы?» при первом запуске.

### 4. Вложения в карточке — мгновенная видимость

**Проблема:** после нажатия «Прикрепить файл» и выбора файла toast «Файл прикреплён» появляется, но строка с миниатюрой в карточке не видна до «Сохранить» и повторного открытия.

**Исправление:**
- В `ui/controls/controls_tab.py` в обработчике прикрепления после добавления файла в `detail_state["control"]` и `attachments` принудительно перестроить панель вложений внутри карточки и, если нужно, строку таблицы (жёлтый бейдж).
- Обеспечить `_safe_update` для панели вложений + родительской секции. Проверить, что контрол добавлен в дерево и `update()` не падает.
- Важно: не добавлять дубликатов файла (анти-дубль раунда 21 сохранить).

### 5. «О программе» — текст не помещается

**Проблема:** в окне «О программе» текст обрезается.

**Исправление:**
- Увеличить размер диалога/Container «О программе».
- Или обернуть текст в `Column(scroll=ft.ScrollMode.AUTO)` внутри ограниченной высоты.
- Или уменьшить кегль/сократить текст, чтобы помещалось на экран 1280×720.
- Минимум: текст должен быть полностью виден без обрезания на стандартном окне.

### 6. Настройки (шестерёнка) — убрать управление справочниками

**Проблема:** в модалке настроек сейчас есть секция управления справочниками людей/инициаторов, дублирующая отдельную кнопку «Справочники» в тулбаре.

**Исправление:**
- Убрать из модалки настроек (`ui/controls/controls_settings_modal.py` или соответствующий файл) весь UI управления справочниками людей и инициаторов.
- В настройках оставить только: сетевой режим (путь/роль/пользователь), порог «скоро», звук уведомлений, и другие runtime-настройки, не относящиеся к справочникам.
- Кнопка «Справочники» в тулбаре (`ui/controls/controls_tab.py`) остаётся и продолжает работать как сейчас.

### 7. Пароль администратора — в настройки приложения

**Задача:** перенести управление паролем admin из установщика в само приложение.

**7.1 Установщик**
- Полностью убрать страницу пароля из `Admin.iss` (см. задачу 1.1).

**7.2 Приложение — настройки admin**
- В модалку настроек (доступна в admin-редакции) добавить секцию «Пароль администратора»:
  - Текущий статус: «Пароль не установлен» или «Пароль установлен».
  - Кнопка/поля: «Установить пароль» (поле ввода + повтор + сохранить), «Сменить пароль» (старый + новый + повтор), «Удалить пароль» (с подтверждением).
  - При сохранении записывать `password_hash` в `%APPDATA%/porayonka/edition.json` (или `controls_settings.json`, но лучше edition.json рядом с exe? Обсудить: пароль должен переживать переустановку; разумно `%APPDATA%/porayonka/edition.json`, потому что при переустановке exe папка затирается; но пользователь просил, чтобы при удалении и переустановке ФИО менялось — для пароля это тоже логично: при удалении теряется). Предлагаю хранить hash в `%APPDATA%/porayonka/edition.json` — переживёт обновление portable, но исчезнет при полном удалении.
- При следующем запуске admin-редакции `admin_password_required()` должен видеть hash из appdata edition.json и показать ворота.
- Важно: при установке новой admin-версии поверх старой hash из appdata должен сохраняться (т.е. установщик Admin.iss НЕ перезаписывает `%APPDATA%/porayonka/edition.json` — он пишет только `{app}\edition.json`).
