## 0. Контекст и проблема

Во вкладке «Контроли» фильтры «Все исполнители» и «Все контролёры» строятся из
**фактических значений в данных** (distinct по `executors` / `controller` /
`assignees`). После импорта из Excel в данных мусор: опечатки, «Миронович
Д.В.-5.1», «Гайнутдинов С.И.Т.С.А.С.И.Ю.», «Исполнитель (...)», дубли с разными
пробелами, несколько имён в одной строке. В результате dropdown огромный и
бесполезный (скрин от пользователя: «Авакян А.А.» дважды, «Гайнутдинов С.И.»
трижды и т.д.).

Нужно: опции фильтра = **только канонический список** (криминалисты + дефолтные
контролёры), а фильтрация при этом находит контроли с ЛЮБЫМ написанием фамилии.

**Что уже есть в коде (не писать с нуля):**

- `core/zonal_data.py` / `core/controls_data.py::get_criminalist_names()` —
  канонический список ФИО криминалистов (16 чел., полные ФИО).
- `core/controls_models.py::short_name()` — «Семисенко Иван Юрьевич» → «Семисенко И.Ю.».
- `ui/controls/controls_tab.py::_mine()` (~стр. 341) — УЖЕ сделано фамильное
  сопоставление: точное совпадение ИЛИ фамилия как подстрока (case-insensitive).
  Это свежая правка из мержа сети — используй тот же подход.
- Дефолтные контролёры: Потемкин С.А., Чашин Э.А. (см. где формируется список
  контролёров для карточки, AGENTS §28.7).
- Фильтры строятся в `_refresh_filter_options()` (`controls_tab.py`), применяются
  в `_filtered()` / `_visible_base()` — найди точные места сам.

## Задача 1. Общий хелпер сопоставления имён

В `core/controls_models.py` добавить чистую функцию (тестируема headless):

```python
def name_matches(canonical_name: str, raw: str) -> bool:
    """True, если `raw` (строка из данных, возможно кривая) относится к человеку
    `canonical_name` (полное ФИО). Правила:
    - точное совпадение строк (после strip) — True;
    - фамилия (первое слово canonical) встречается в raw как подстрока
      (case-insensitive) — True;
    - иначе False. Фамилия короче 3 символов не матчится (защита от мусора)."""
```

В `ui/controls/controls_tab.py::_mine()` заменить своё локальное фамильное
сравнение на вызов `name_matches()` — поведение не должно измениться.

## Задача 2. Фильтр «Все исполнители» — канонический список

- Опции: «Все исполнители» + по одному пункту на каждого криминалиста
  (значение — полное ФИО, подпись — `short_name`). Без дублей, отсортировано по
  фамилии. Значения из данных больше НЕ попадают в опции вообще.
- Фильтрация: контроль проходит, если ХОТЯ БЫ один из его `executors` или
  `assignees` задач матчится с выбранным каноническим ФИО через `name_matches()`.
- Поведение по умолчанию («Все исполнители») не меняется.

## Задача 3. Фильтр «Все контролёры» — то же самое

- Опции: «Все контролёры» + канонический список: криминалисты + дефолтные
  контролёры (Потемкин С.А., Чашин Э.А.), без дублей, по фамилии.
- Фильтрация по `controller` через `name_matches()`.

## Задача 4. Пункт «Прочие»

В оба фильтра добавить в конец пункт **«Прочие»** (значение `__other__`):
- для исполнителей: контроль проходит, если НИ ОДИН из его `executors`/`assignees`
  не матчится ни с одним каноническим криминалистом (т.е. люди вне списка);
- для контролёров: аналогично по `controller`.
Это не даёт «потерять» контроли с людьми вне канонического списка.

## Задача 5. Не ломать остальное

- Фильтр «Все инициаторы» НЕ трогать (инициаторы — своя история: дефолтные +
  `custom_initiators`).
- Поиск по тексту, фильтры статуса/типа, даты, счётчики — не меняются.
- Роль `user` (`_mine`, `_visible_base`) продолжает работать как сейчас.
- Сохранение выбранного значения фильтра при `_refresh_filter_options()`:
  если ранее выбранное значение — каноническое ФИО или `__other__` — сохранить;
  если это мусорная строка из старых данных — сбросить на «Все ...» молча.

**Новые headless-тесты (добавить в `tests/test_controls_smoke.py`):**

1. `name_matches`: полное ФИО vs «Фамилия И.О.», vs «Фамилия И.О.-5.1», vs
   «Другой И.О. Фамилия И.О.» (не первое слово), vs опечатка в имени но верная
   фамилия, vs чужая фамилия (False), vs пустая/None строка (False), фамилия
   <3 символов (False).
2. Опции фильтра исполнителей: скорми контроли с мусорными исполнителями
   (дубли с пробелами, суффиксы, несколько имён в строке) → опции = только
   криминалисты + «Прочие», без мусора, без дублей.
3. Фильтрация: выбран «Семисенко И.Ю.» (полное ФИО) → найдены контроли, где
   исполнитель записан «Семисенко И.Ю.», «Семисенко Иван Юрьевич»,
   «Чашин Э.А., Семисенко И.Ю.» и т.п.; чужие контроли не найдены.
4. «Прочие»: контроль с исполнителем «Посторонний А.А.» находится через
   «Прочие» и НЕ находится через любого криминалиста.
5. Контролёры: фильтр по «Потемкин С.А.» находит контроль с
   `controller="Потемкин Сергей"` (если такой вариант есть в тестовых данных) —
   фамильное совпадение.

**В финальном сообщении:** имя ветки + краткий чек-лист ручной приёмки:
открыть фильтр «Все исполнители» → список ~17 пунктов (16 криминалистов +
Прочие), выбрать криминалиста → видны его контроли включая криво записанные.

## Ограничения (нарушение = баги в GUI, проверено болью)

- Цвета с прозрачностью — только `#AARRGGBB`. Динамика — `with_alpha()`.
- Внутри `Column(scroll=AUTO)`: никаких `expand=True` (кроме горизонтальных
  спейсеров в Row), `wrap=True`, `animate*`, `shadow`, `gradient` на мелких.
- Все `.update()` контролов — `_safe_update()`. В горячих обработчиках — никаких
  `traceback.print_exc()`; в остальных — `traceback.print_exc()`, не глушить.
- Вложенные `AlertDialog` запрещены. FilePicker — `overlay.append` + `page.update()`.
- `ft.icons.*`, `print()` — только ASCII, UI-текст — русский.
- Flet строго 0.23.2, без новых pip-зависимостей.
- Не ломать: вкладки 1–2, Excel-импорт/экспорт, архив, роли, сетевую
  синхронизацию (§37.5), контракты функций.
- `print()` в тестах и коде — только ASCII/кириллица cp1251 (никаких `→`,
  эмодзи и прочих символов вне cp1251 — на Windows-консоли падает с
  UnicodeEncodeError; уже было).
