## Задача 1 — Hover без тормозов

**Проблема:** рамка при наведении появляется с задержкой.

**Решение:**
- Если `on_hover` + `update()` тормозит в Flet 0.23.2 — **убрать hover-эффект полностью**.
- Оставить только `mouse_cursor=CLICK` (курсор-рука).
- Это гарантированно убирает лаг.
- Если сможешь сделать hover мгновенным без `update()` (например, через `Tooltip` или статичный стиль) — можно, но главное — отсутствие тормозов.

## Задача 2 — Таблица помещается на экране

**Проблема:** даже при ширине окна ~1900 px таблица не помещается, «Действия» уезжают за край (см. `Ховер с тормозами.png`).

**Решение:**
- Подобрать ширины так, чтобы при **1280 px** таблица помещалась с запасом.
- Дополнительно ограничить максимальную ширину гибких колонок («Содержание», «Исполнители»), чтобы они не раздувались на больших экранах.
- Если не помещается — уменьшить кегль строки до 11 px.
- Проверить расчёт с учётом **всех padding/spacing/разделителей/scrollbar**.

**Ориентир:** сумма всех ширин + отступы ≤ 1240 px при page.width=1280.

## Задача 3 — Справочники: скролл + сохранение редактирования

**Проблемы:**
- Скролл пролистывает слишком много (хоть и меньше, чем раньше).
- Редактирование записи не сохраняется: добавил «!!!», нажал галочку — строка осталась без изменений (см. `Справочники редактируем.png` / `...2.png`).

**Решение:**
- **Сохранение редактирования:** проверить обработчик галочки/кнопки «Применить». При редактировании:
  - новое значение должно записаться во временный список редактора;
  - при нажатии «Применить» — сохраниться в `extra_people`/`custom_initiators` и `controls_settings.json`;
  - перестроить фильтры.
  - Сейчас видимо обновляется только UI, но не state/settings.
- **Скролл:**
  - уменьшить `item_extent` в `ListView` (например, до 32 px) — тогда одно движение колеса прокручивает меньше пикселей;
  - или заменить `ListView` на `Column(scroll=AUTO)` с фиксированной высотой строки и маленькими отступами;
  - или перехватить `on_scroll` и прокручивать вручную на небольшое значение.

## Задача 5 — Прикрепление файла без ошибок

**Проблема:** падает с ошибкой:
```
TypeError: unsupported operand type(s) for /: 'WindowsPath' and 'NoneType'
File "core/controls_data.py", line 473, in copy_attachment_to_shared
    target_dir = shared_dir / "controls_attachments" / control_id
```

**Причина:** `detail_state["control_id"]` = `None` при прикреплении к **новой** карточке.

**Решение:**
- Для новой карточки сразу сгенерировать `control_id` при открытии (uuid), чтобы вложения копировались в правильную папку.
- Если сеть отключена (shared_dir = None) — использовать локальное копирование (`copy_attachment_to_local`), а не `copy_attachment_to_shared`.
- После копирования обновить `detail_state["attachments"]`, вызвать `_rebuild_attach()`, `_persist()`, `page.update()`.
- Toast «Файл прикреплён» показывать только после успешного копирования.

## Технические ограничения

- Flet 0.23.2 — не повышать.
- Внутри `Column(scroll=ft.ScrollMode.AUTO)` — никаких `expand=True` (кроме горизонтальных спейсеров в `Row`), `wrap=True`, `animate*`, `shadow`, `gradient` на мелких контейнерах.
- Цвета с прозрачностью — только `#AARRGGBB`.
- `print()` — только ASCII; UI-текст — русский.
- Не ломать логику данных, сеть, Excel, архив, другие вкладки.
