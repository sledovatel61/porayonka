## 2. Новые требования (фаза 2)

### 2.1 Excel: двусторонняя совместимость (импорт + экспорт)

Пользователь сейчас ведёт контроли в Excel-таблице такого формата (одна строка —
один контроль, первая строка — заголовок):

| № | вх. № ВХСОП | Дата поступления | Инициатор | Содержание | Исполнитель (ФИО) | За кем контроль | Разовый/постоянный | Следующая дата исполнения | Исполнено + дата |

Особенности реального файла:
- Даты в формате `dd.mm.yyyy` (могут быть и текстом, и excel-date).
- «Исполнитель (ФИО)» — несколько ФИО через запятую/`+`/перевод строки.
- «За кем контроль» — `Потемкин С.А.` или `Чашин Э.А.`
- «Разовый/постоянный» — свободный текст: `ежемесячно к 05 числу`,
  `ежеквартально к 01`, `еженедельный в ПН`, `1 раз в 2 мес`, конкретная дата,
  `07.05 + каждые 3 месяца` и т.п.
- «Следующая дата исполнения» — дата; жёлтая заливка ячейки означает, что срок
  наступил/близок (заливку игнорировать, читать значение).
- «Исполнено + дата» — либо дата, либо произвольный текст (`Семисенко`,
  `приостановлено`, `нужно повторно ?`), либо пусто.
- «Содержание» может включать пункты с разными исполнителями и датами в свободном
  тексте (`п. 2 - Миронович 01.05.2026, п. 3 - Авакян 01.05.2026`) — при импорте
  сохранять как есть в `content`, без попыток идеально распарсить пункты
  (опционально — попробовать выделить пункты эвристикой и показать в
  предпросмотре, что получилось).

**Импорт:**
1. Кнопка «Импорт из Excel» в тулбаре вкладки.
2. FilePicker выбирает `.xlsx` → парсинг через openpyxl.
3. **Диалог предпросмотра**: таблица распознанных строк (сколько найдено,
   сколько с ошибками, как распознались даты/тип/исполнители). Пользователь
   подтверждает импорт.
4. Дедупликация: если контроль с таким `incoming_number` уже есть — пропускать
   (показать счётчик «пропущено дубликатов: N») либо спрашивать «обновить?».
5. Маппинг:
   - «Исполнено + дата» с датой → `done=True`, `done_date=дата`;
     с текстом без даты → `done=True`, текст → `comment` (пометить
     «исполнено (по импорту): …»);
     пусто → активный контроль.
   - «Разовый/постоянный»: эвристика — содержит «ежемес» → periodic 30,
     «ежекварт» → 91, «еженед» → 7, «ежедн» → 1, «раз в N мес» → 30*N,
     только дата/пусто → once. Нераспознанное → once + текст в `comment`.
   - Исполнители: разбивка по `,` `+` `\n`, trim.
6. После импорта — autosave + обновление таблицы + тост со статистикой
   («импортировано N, пропущено M, ошибок K»).

**Экспорт (два режима):**
1. **«Экспорт (как в таблице)»** — тот же набор колонок и порядок, что выше:
   - даты `dd.mm.yyyy`;
   - **жёлтая заливка** ячейки «Следующая дата исполнения» при статусах
     OVERDUE/TODAY/SOON;
   - **зелёная заливка** строки (или ячейки «Исполнено») при `done`;
   - в «Исполнено + дата» — дата исполнения.
   - Файл должен нормально открываться в Excel и **импортироваться обратно
     без потерь** (round-trip: экспорт → правка в Excel → импорт).
2. **«Экспорт полный (для обратной загрузки)»** — служебный формат для
   безупречного round-trip: те же колонки + скрытый лист (или доп. колонки)
   с `id`, `control_type`, `period_days`, пунктами задания (JSON по строке
   или отдельный лист `tasks`). Импортёр должен уметь читать оба формата:
   «как в таблице» (эвристики) и «полный» (точное восстановление, включая
   пункты задания и id).
3. Импортёр по наличию служебных признаков сам определяет формат файла.

### 2.2 Архив исполненных и удалённых

- В модель `Control` добавить: `archived: bool = False`,
  `archived_at: Optional[str]`, `archive_reason: str = ""` (`"done"` | `"deleted"`).
  Миграция схемы: `SCHEMA_VERSION = 2` (старые файлы читаются, поля с дефолтами).
- **Исполненные**: при отметке «Исполнено» (разовый контроль) — контроль
  **автоматически уходит в архив** (с тостом «Контроль исполнен и перемещён
  в архив»). В основном списке больше не висит. Периодические — как раньше
  (перенос срока, не архивируются).
- **Удалённые**: вместо физического удаления — перемещение в архив с
  `archive_reason="deleted"`.
- **Экран архива**: отдельный режим/переключатель «Активные | Архив»
  (например, сегмент в counters_row или отдельная кнопка). В архиве:
  - тот же список/поиск/фильтры;
  - колонка «Причина» (Исполнен / Удалён) и дата архивации;
  - действия: **Восстановить** (вернуть в активные), **Удалить навсегда**
    (с подтверждением).
- Архив хранится там же в `controls.json` (флаг `archived`), чтобы синхронизироваться
  по сети тем же механизмом. Счётчики/уведомления/экспорт «как в таблице»
  учитывают только активные; в полный экспорт можно добавить лист «Архив».

### 2.3 Сканы заданий (вложения PDF/PNG/JPG)

- В карточке контроля блок **«Скан задания»**:
  - Кнопка «Прикрепить файл» (FilePicker, расширения: `pdf, png, jpg, jpeg`;
    множественный выбор желателен).
  - Список вложений: иконка по типу, имя файла, размер; кнопки **«Открыть»**
    (через `os.startfile` на Windows, кросс-платформенно как в
    `_open_last_export` в `zonal_tab.py`) и **«Удалить»** (с подтверждением).
- Хранение: при добавлении файл **копируется** в
  `%APPDATA%\porayonka\controls_attachments\<control_id>\<filename>`
  (при коллизии имён — суффикс `_1`, `_2`…).
- В модели `Control`: `attachments: List[str]` — относительные пути
  (`<control_id>/<filename>`).
- **Сетевой режим**: вложения кладутся в общую папку рядом с `controls.json`
  (`<shared_dir>/controls_attachments/<control_id>/...`), чтобы все участники
  сети могли открыть скан. При sync: новые файлы из общей папки подтягивать
  локально (копирование) либо открывать напрямую из сетевой папки — выбрать
  проще и надёжнее, обосновать.
- При архивации вложения сохраняются; при «удалить навсегда» — спрашивать,
  удалять ли файлы.
- Предупреждение при файле > 20 МБ (не запрещать, предупреждать).
- Отображать наличие сканов в строке списка (иконка скрепки + счётчик).

### 2.4 Фиксы багов фазы 1 (обязательно)

1. **`STATUS_ICONS` — битые иконки**: в `core/controls_models.py` иконки зашиты
   uppercase-строками (`"EVENT_BUSY"`), а константы Flet — lowercase
   (`ft.icons.EVENT_BUSY == 'event_busy'`). Клиент не найдёт иконку → пустое
   место в пилюле статуса. Заменить на реальные `ft.icons.*` константы
   (слой модели при этом не должен импортировать flet — вынести маппинг
   иконок в UI-слой, а в модели оставить ключи).
2. **Периодические уведомления без сети**: сейчас фоновый поток стартует
   только при `network_enabled`. Уведомления о сроках должны проверяться
   периодически (раз в ~60 сек) **независимо от сетевого режима**.
3. **Потокобезопасность UI**: фоновый поток дёргает `_rebuild_table()` и
   тосты напрямую. В Flet 0.23.2 нет `ft.Timer`/`page.run_thread`.
   Выбрать безопасный вариант и обосновать, например:
   - поток только читает файл и выставляет флаг `dirty`, а применение —
     при ближайшем UI-событии/по кнопке «Обновить»;
   - или аккуратный вызов `control.update()` из потока через try/except
     (работает на практике, но задокументировать риск);
   - или `page.pubsub` если применим.
   Главное — убрать гарантированную гонку при активной синхронизации.
4. **Экспорт — дата**: в `controls_exporter.py` колонка «Следующая дата»
   берёт `ctl.due_date`, а в UI показывается `effective_due_date(ctl)`.
   Экспорт должен совпадать с UI.
5. **Роль «пользователь»**: при `network_role="user"` фильтровать список —
   показывать контроли, где `network_user` входит в `executors` или
   ответственные пунктов (сопоставление по точному ФИО; `network_user`
   выбирать из списка криминалистов в настройках, не свободный текст).
   Уведомления — только по «моим» контролям. Администратор видит всё.
6. **DatePicker'ы в overlay**: при каждом открытии карточки в `page.overlay`
   добавляется новый `DatePicker` — переиспользовать один (или удалять
   при закрытии), чтобы overlay не разрастался.

## 4. Проверка перед сдачей

1. `python -c "import sys; sys.path.insert(0, 'porayonka-app'); import main"` — OK.
2. Smoke-тесты (скриптом, без GUI):
   - Сгенерировать тестовый `.xlsx` в формате пользователя (10–15 строк с
     особыми случаями: дата-текст, «ежемесячно», «Исполнено + текст», несколько
     ФИО) → импорт → проверить маппинг в `Control`.
   - Round-trip: экспорт «полный» → импорт → сравнить объекты (id, задачи,
     даты, вложения).
   - Архив: исполнение разового → в архиве; восстановление; удаление навсегда.
   - Вложения: добавить файл-заглушку → копия лежит в
     `controls_attachments/<control_id>/`; запись в `attachments`.
   - Миграция: `controls.json` без новых полей → загружается, v2.
3. Ручная приёмка в GUI Windows: `python porayonka-app/main.py`.
