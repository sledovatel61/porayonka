## 2. Задачи

### Задача 1. Пароль админа — диалог не закрывается, таблица дублируется

**Файлы:** `porayonka-app/ui/admin_gate.py`, `porayonka-app/main.py`.

**Симптом:** пользователь вводит пароль «1», жмёт «Войти». Диалог остаётся на экране, за ним тускло отрисовывается таблица. Повторный ввод — таблица отрисовывается ещё раз. Пароль не принимается (или принимается, но UI не переходит в рабочее состояние).

**Что нужно сделать:**
1. Убедиться, что после верного пароля диалог закрывается **ровно один раз** и вызывается `_main_impl()` тоже ровно один раз.
2. Исправить `show_admin_password_gate` так, чтобы `page.close(dlg)` гарантированно отработал перед `on_ok()` (возможно, нужен `page.update()` после close и/или небольшая задержка/колбэк, но без `sleep` в UI-потоке).
3. Защитить от повторного вызова `_try` (например, флаг `_submitted`).
4. Проверить, что при неверном/отказе приложение закрывается (сохранить старое поведение).
5. В `main.py` убедиться, что `show_admin_password_gate` не вызывает `_main_impl` синхронно, если пароль требуется.

**Критерий:** запуск `set PORAYONKA_EDITION=admin` + `python main.py` с паролем «1» → диалог исчезает, таблица одна, приложение работает.

### Задача 2. Вложения в новой карточке не видны сразу

**Файл:** `porayonka-app/ui/controls/controls_tab.py` (секция «Скан задания», `_on_attach_picked`, `_rebuild_attach`, `_apply_attach_result`, `_make_scan_section`).

**Симптом:** в новой карточке (вх. № 12345 на скрине) после «Прикрепить файл» в секции «Скан задания» не появляется строка с файлом. После сохранения, закрытия и переоткрытия — файл есть.

**Что нужно сделать:**
1. Сохранить всю существующую логику: антидубль событий FilePicker, offline/shared копирование, большие файлы в фоновом потоке, toast, фильтрация уже прикреплённых имён.
2. Сделать так, чтобы после выбора файла строка вложения появлялась в UI **сразу** (до нажатия «Сохранить»), как в уже сохранённых карточках.
3. Возможная причина: раунд 28 заменяет `scan_panel.content = _make_scan_section()` на новый инстанс, но `attach_col` (или его содержимое) остаётся привязан к старому поддереву / diff-движок 0.23.2 не переносит его. Нужно либо обновлять существующий `attach_col` без полной замены content, либо корректно пересоздавать ссылку и перестраивать список.
4. Добавить headless-тест на эту ситуацию: открытие новой карточки → прикрепление → проверка, что `attach_col` содержит ровно одну строку с именем файла.

**Критерий:** в новой карточке выбрать PDF → сразу видно строку вложения с миниатюрой/иконкой, именем, кнопками.

### Задача 3. «За кем контроль» должен показывать только контролёров

**Файлы:** `porayonka-app/ui/controls/controls_tab.py` (dropdown `controller_dd`), `porayonka-app/core/controls_data.py` (`get_controller_names`, `get_person_roles`, `DEFAULT_CONTROLLERS`).

**Симптом:** в dropdown «За кем контроль» в новой карточке отображаются исполнители (Аваян, Агеев, Белашов, Гайнутдинов и т.д.), а должны быть только контролёры (по умолчанию `Потемкин С.А.`, `Чашин Э.А.` + люди с явной ролью `controller` из справочника).

**Что нужно сделать:**
1. Убедиться, что `controller_canonical` в карточке строится только из `get_controller_names(settings)` (или fallback `DEFAULT_CONTROLLERS`), а не из `get_all_people_names` / `executor_canonical`.
2. Возможная причина: `extra_people` (добавленные при импорте Excel) по умолчанию получают обе роли (`executor` + `controller`) в `get_person_roles`. Это приводит к тому, что импортированные исполнители попадают в контролёров. Нужно изменить умолчание: `extra_people` — только `executor` (или без роли до явного назначения), а `controller` — только при явном назначении в справочнике / `DEFAULT_CONTROLLERS`.
3. Сохранить backward compatibility: если у кого-то из `extra_people` в `person_roles` явно стоит `controller`, он должен остаться в списке.
4. В dropdown текущего контроля (`ctl.controller`) всегда добавлять как опцию, даже если ФИО не в списке контролёров (как сейчас), чтобы не потерять данные.

**Критерий:** в новой карточке dropdown «За кем контроль» содержит только `Потемкин С.А.`, `Чашин Э.А.` и тех, кому вручную назначена роль контролёра в справочниках.

### Задача 4. ФИО пользователя в настройках — видимый текст

**Файл:** `porayonka-app/ui/controls/controls_settings_modal.py` (dropdown `user_dd`, строка ~82).

**Симптом:** в user-редакции с зафиксированным ФИО поле «Пользователь (ФИО)» отображается чёрным текстом на тёмном фоне и не читается (скрин `Не видно кто пользователь, текст черный.png`).

**Что нужно сделать:**
1. Сделать выбранное ФИО белым/светлым (`GLASS["text"]` или `COLORS["text"]`) и читаемым в `disabled` состоянии.
2. В Flet 0.23.2 `Dropdown` в disabled-режиме может игнорировать `color`. Варианты:
   - попробовать `text_style=ft.TextStyle(color=...)` и `disabled_color=...` (если есть в API);
   - если не работает — заменить disabled Dropdown на `Container` с `Text` + иконка замка (read-only вид), сохраняя подсказку.
3. Сохранить поведение: зафиксированное ФИО нельзя сменить из настроек; незафиксированное — выбирается из списка.

**Критерий:** в настройках user-редакции выбранное ФИО видно белым/светлым цветом.

### Задача 5. Ложное предупреждение о расхождении времени

**Файл:** `porayonka-app/core/controls_data.py` (`check_time_skew`), вызов в `porayonka-app/ui/controls/controls_tab.py` (`_first_table_init`).

**Симптом:** при старте в сетевом режиме появляется диалог «Проверьте системное время — расхождение ~125 мин», хотя время на ПК корректное.

**Что нужно сделать:**
1. Проанализировать причину: `check_time_skew` сравнивает `datetime.now()` с `mtime` общего файла. Возможные причины: shared-файл записан на машине с другим системным временем, SMB показывает время в другом часовом поясе, или логика сравнения не учитывает часовые пояса / DST.
2. Сделать так, чтобы при корректном времени на ПК предупреждение не появлялось в обычных условиях. Варианты:
   - сравнивать не с `mtime` shared, а с `last_saved` внутри `controls.json` (ISO-строка, записанная приложением);
   - нормализовать обе даты в UTC;
   - увеличить порог до разумного (например, 30 мин), но лучше убрать ложные срабатывания корнево;
   - если невозможно отличить ложное срабатывание от реального — сделать предупреждение не модальным (тихий print/toast), а не блокирующим диалог.
3. Сохранить защиту от реального сбоя часов (если она нужна), но без false positives.

**Критерий:** при старте с корректным временем и рабочей сетью нет модального предупреждения о времени.

## 3. Технические ограничения (не нарушать)

- **Flet строго 0.23.2** (`pip install flet==0.23.2`). Не повышать.
- **Без новых зависимостей** (кроме тех, что уже в `requirements.txt` / build-скриптах).
- **Layout-правила:** внутри `Column(scroll=ft.ScrollMode.AUTO)` нет `expand=True` (кроме горизонтальных спейсеров в `Row`), нет `wrap=True`, нет `animate*`, нет `gradient`/`shadow` на мелких контейнерах. Рамки с `border_radius` — равномерной толщины.
- **Цвета 8-digit — только `#AARRGGBB`**, не `#RRGGBBAA`. Динамические полупрозрачные через `with_alpha(color, "22")` → `#22RRGGBB`.
- **Иконки:** `ft.icons.*` (не emoji).
- **`print()` — только ASCII** (без русских букв, emoji, спецсимволов). UI-текст (`text=...`) — на русском.
- **Все `.update()` контролов** — через `_safe_update()` (или `_quiet_update()` для hover). В горячих обработчиках — без `traceback.print_exc()`.
- **Не ломать раунды 1–29:** smoke-тесты `tests/test_controls_smoke.py` должны остаться `ALL OK`.
- **Сохранить контракты публичных функций**, если только специально не указано.
