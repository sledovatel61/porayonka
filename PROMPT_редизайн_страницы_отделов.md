# МЕГАПРОМПТ: Редизайн вкладки «Следственные отделы»

## Репозиторий и ветка

- **Проверка импорта:** `python -c "import sys; sys.path.insert(0, 'porayonka-app'); import main"`

## Контекст

Приложение «Порайонка» — десктопный трекер статусов следственных отделов СК РФ по Ростовской области на Flet 0.23.2 (Python).

Сейчас вкладка «Следственные отделы» выглядит как длинная таблица:

- Слева — номер и название отдела.
- Справа, далеко от названия — статус («Не получено» / «Получено» / «В работе»).
- Вверху — статистика, тулбар, легенда.

Пользователь хочет, чтобы страница выглядела **современно, удобно и «приложенно»**. Главная проблема — большое визуальное расстояние между названием отдела и его статусом. Нужно предложить и реализовать крутое решение: карточки, компактные строки, статус-переключатели рядом с названием, группировки, адаптивную сетку или любой другой удачный UI.

## Что сейчас работает (нельзя ломать)

1. **Список отделов** загружается из `%APPDATA%\porayonka\departments.json`.
2. **3 статуса** с циклическим переключением по клику:
   - `empty` — «Не получено» (серый)
   - `received` — «Получено» (зелёный)
   - `in_progress` — «В работе» (жёлтый)
3. **Статистика** в реальном времени: получено, в работе, не получено, общий прогресс (%). Считается только по активным отделам.
4. **Поиск** по названию отдела.
5. **Сохранение / экспорт / сброс статусов** через кнопки в тулбаре.
6. **Управление отделами** через кнопку «Редактировать отделы»:
   - добавление, переименование, удаление;
   - включение/выключение активности;
   - перемещение отделов вверх/вниз стрелками.
   Порядок отделов сохраняется в JSON.
7. **ОВД-1 / ОВД-2** отображаются без номера (вместо номера «—»), курсивом, с разделителем.
8. **Неактивные отделы** приглушены (opacity ~0.45) и не реагируют на клик.
9. **Автосохранение** при изменении статуса.

## Технические ограничения (строго)

- **Flet 0.23.2.** Не повышать, не добавлять новые зависимости.
- **Не ломать рабочий layout плашек** во вкладке «Зональные» (см. AGENTS.md 15.12, 22, 23, 24, 27).
- **Не добавлять `expand=True` внутрь `Column`/`Container` с `scroll=ft.ScrollMode.AUTO`** — это источник схлопывания и пустых вкладок.
- Использовать `ft.icons.*` вместо emoji/символов.
- `print()` в консоль — только ASCII (без русских букв, emoji, спецсимволов), чтобы избежать `UnicodeEncodeError` на Windows cp1251.
- UI-текст (`text=...`) — на русском.
- Сохранить существующие контракты функций: `create_department_table`, `rebuild_department_table`, `filter_table`, `create_stats_bar`, `update_stats_bar`, `create_toolbar`, `create_status_cell`, `create_edit_departments_modal`.
- Не изменять логику данных, модели, сохранение/загрузку, экспорт.

## Задача

### Этап 1 — Предложить концепцию (до кода)

Проанализировать текущую вкладку и предложить **2–3 варианта** редизайна. Для каждого варианта описать:

1. **Layout**: где будет название отдела, где статус, как располагаются кнопки.
2. **Взаимодействие**: как пользователь переключает статус (клик по строке? отдельная кнопка-чип? свайп?).
3. **Преимущества**: что именно становится удобнее.
4. **Риски для Flet 0.23.2**: может ли этот layout сломаться (expand, scroll, wrap, GridView, анимации).

### Этап 2 — Реализовать выбранный вариант

После согласования с пользователем (или если пользователь не отвечает — взять лучший по соотношению удобство/безопасность) реализовать редизайн.

**Обязательно сохранить:**

- циклическое переключение 3 статусов;
- обновление статистики в реальном времени;
- поиск;
- активность/неактивность отделов;
- OVD-разделитель и курсив;
- все кнопки тулбара;
- модальное окно редактора отделов (можно стилизовать, но функционал должен остаться);
- автосохранение и ручное сохранение.

**Что можно и нужно улучшить:**

- визуальная близость названия отдела и статуса;
- hover-эффекты строк/карточек (только через смену `bgcolor`/`border`/`opacity` + `update()`, без `animate` внутри прокручиваемых колонок);
- современные скругления, тени, цвета из текущей палитры `core/constants.py`;
- компактность статистики и тулбара;
- читаемость длинных названий отделов;
- empty-state при отсутствии отделов по поиску;
- возможно, группировку по типам (городские СО / МСО / ОВД) или визуальное разделение;
- адаптивность к ширине окна.
